# ADR-005 项目存储、历史与原子提交（验证计划）

- 状态：**计划，未定**
- 日期：2026-11-04

## 1. 现状

- FableCut `project.json` 是工程文档；适配器是唯一 writer。
- 适配器账本：`business-jobs.json` / `.adapter-ledger.json` 本地 JSON；无 fsync/原子多文件提交。
- 工具层 `commandId` 账本是进程内 Map；插件重启后丢失（适配器账本仍在）。
- 无项目切换/历史/删除的产品化实现。

## 2. 计划

1. M1-T1 定义 `ProjectStore` 契约：projectId、revision、snapshot、command、history、attachment/media 引用。
2. 原子提交：单文件 tmp+rename 已有；多文件（工程+账本+历史）需要 journal 或单目录快照；崩溃恢复测试。
3. 历史：每次提交前后可回读；恢复生成新 revision，不覆盖旧版本；与 FableCut `history.restore` 的语义对齐。
4. 迁移：M0 夹具工程可读；旧样例不可静默删除；失败证据保留。
5. 并发：适配器单进程队列 + 文件锁；多进程/多实例拒绝；真实崩溃/掉电另测。

## 3. 未验证

- 断电/进程被杀时 JSON 账本一致性；
- 多文件提交的原子性；
- FableCut 原生 history/projects 写入口的收敛；
- 工程迁移/回滚。

## 4. 复审

M1-T1 完成存储契约与崩溃测试后复审；未通过前不把“可重开/不丢修改”写成已保证。
