## 1 交接与开工

1. 先读 PRD、本文和源码仓库现有指令。记录 Git 分支、HEAD、工作树状态和实际发布路径。编写本文时，源码在 `m1-m3-first` 的 `5dffbe7` 上，M4 运行时、模型桥、图形化模型设置和 Windows 启动包包含未提交修改与未跟踪文件。以**含 M4 工作树的源码**为基线。若换工作目录，先把这些变化一并带入；确认清单和内容后再实施。保留用户改动，不用清理命令回到旧 HEAD。
2. 用独立数据根、端口和 DSH 测试 profile 开发。使用合成夹具和已授权真实样片。先跑现有回归，记录任何基线失败。日常 Desktop、原工程目录和桌面快捷方式在发布切换前持续使用已验证版本。
3. 按 §9 的任务卡逐项交付。每项给出实现范围、实际运行的验证命令、结果、已知限制、可回退位置。后续阶段依赖前一阶段的完成证据。真实 ASR、真实模型、真实渲染和人工审片分别记录。
4. 用户最新要求优先，PRD 决定产品行为，本文决定 V2 执行契约。遇到可通过测试确定的实现细节就做并记录。阶段验收失败时修复或保持能力为「未就绪」，避免将占位能力暴露给新手。

已知基线包括两种入口共用 `src/web`、CUTDIRECTOR Loop 在 `src/agent`、DSH 模型桥在 `src/host`、权威写入在 `ProjectStore`、FFmpeg 后台任务在 `Jobs`。旧桌面发布包位于源码仓库的 `.m3-data/release-m4-model-ui-final`，执行前复核。本机既有 FFmpeg 已核实支持 `silencedetect` 和 `scdet`；现用 ASR 接口返回 `provider-not-ready`。 [M4 运行说明](E:/Deepseek-product/Agent/Video-agent/docs/M4-running.md)

## 3 会话、引导与上下文契约

### 3.1 持久化对象与接口

所有 V2 新记录带 `schemaVersion`，放在当前数据根的 `_agent` 下。工程路径和所有外部 ID 经过既有校验，服务端从项目记录解析归属。浏览器的本地存储只用于界面偏好，项目内的对话与草稿定位由服务端提供。

| 对象 | 最小信息 |
| --- | --- |
| Conversation | `id, projectId, title, createdAt, updatedAt, intent`。项目索引记录最近打开的会话。新会话意图初始为空。 |
| Message | `id, conversationId, role, content, createdAt`，可带运行 ID、草稿 ID、引用的素材时间或经服务端验证的界面动作。支持按游标读取。 |
| Intent | `goal, targetDurationUs, mustKeep, selectedAssetIds`，仅合并本轮明确更新的字段。 |
| Director run | `id, conversationId, projectId, baseRevision, modelRoute, phase, checkpoint, taskMode, sequence`，并记录输入证据、草稿、渲染请求和已消耗的资源预算。 |

- 新增 `GET/POST /agent/conversations` 按项目列出和新建对话，`GET /agent/conversation` 按项目、会话和游标读取消息。通过 `POST /agent/conversation/open` 更新最近打开记录。切换对话和刷新不创建新任务。
- 既有 `/agent/run` 接收可选 `conversationId`。新页面始终提供该 ID；历史调用按 M4 兼容。SSE 继续沿用现有任务入口，增加阶段与草稿引用，并使用递增序号去重；重连先读取持久化状态。
- 旧 M4 `latest` 指针及运行文件按项目归入「旧记录」。历史请求的 `previousId` 并不保证写入运行文件，因此仅在存在可靠关联时合并；其余作为独立历史记录，按落盘时间排序并标为旧记录。迁移索引可重复建立，保留原文件；读不到的记录单独报错。现有运行 ID、模型设置和偏好记录继续可读。
- 对同一会话限制一个活动剪辑任务。新对话可以独立打开。切换界面不改变已有运行绑定的工程或素材。采用草稿始终要求当前工程匹配并通过版本检查。

### 3.2 模型输出与用户文案

模型输出由服务端区分 `explain`、`clarify`、`plan_edit`、`tool_request` 和 `report`。先判断用户想了解、改目标还是执行，再决定是否调用素材工具。解释类问题可以用内置释义直接回答，例如「转写」「草稿」「撤销」。聊天正文使用短句和用户词汇，默认展示结果与一个下一步。结构化命令、堆栈、帧号和 revision 走可展开诊断。动作按钮由代码根据当前状态生成，例如识别、导入字幕、停止、播放、采用、导出。

会话上下文按优先级组装：当前请求与明确约束、当前工程与草稿、已确认会话目标、近期相关消息、已确认偏好、按需素材证据。保留人类可回看的历史；长会话采用摘要和证据指针。更改目标时只合并明确字段。生成预览后，用户说「加回开头那句」应定位当前草稿和原素材证据，再生成一个新的草稿版本。

每个新任务固定模型来源和模型 ID。DSH 选择继续走现有模型桥，仅在嵌套入口列出 DSH 模型。跨入口能读取任务与草稿，后续模型调用只有在同一来源可用时才能继续，来源不可用就提供重新连接或开新一轮时选其他模型的入口。可选 DSH 原生只读分析单独授权。既有模型设置、GUI 测试保存和密钥保护沿用。

## 4 P0 口播任务与证据

### 4.1 本地分析与缓存

- 优先接 `whisper.cpp` Windows CPU 路径，使用多语言 small 系列模型作为首个验收候选。开发时固定实际二进制版本和模型校验值，分别核实再分发条款。工作台通过「安装本地语音识别」显示来源、下载大小和进度，支持校验、重试和取消。正式包包含所需运行文件或引导下载经固定校验的组件。普通用户从工作台完成安装。
- 复用 FFmpeg 从原素材提取本地音频。按约 5 分钟分块，边界带短重叠；输出转换为原素材微秒坐标，重叠区域去重。以素材哈希、处理参数、工具和模型版本为缓存键。中断时复用已成功的块。对 25 分钟附近的实际媒体验证进度、性能和内存峰值。
- 证据记录至少有 `assetId, mediaHash, sourceInUs, sourceOutUs, kind, precision, provenance`，文本证据另有文字与可用置信度。ASR 的词、句、块精度按实际返回标记。句段精度只允许句段级语义切点。显式导入的 SRT 可提供时间段和内容依据。FFmpeg 停顿与场景变化是独立证据。
- 无人声、缺识别、音轨读取失败和识别质量不足各有状态。默认以普通话显示可选动作。无人声时可提供基于实际画面分析或手动首尾的处理路径，P0 可用动作依据当前工具能力显示。云端默认仅发送本次所需文字，原视频、音频与画面上传由单独授权检查控制。

### 4.2 导演计划和后台推进

剪辑任务主线为 `received → analyzing → selecting → building → rendering → reviewing → draft_ready`。分支有 `needs_input`、`cancelled`、`interrupted`、`failed`。普通问题直接完成，可用能力不足时进入引导。阶段更新以真正完成的分析块、渲染与审片结果为准。

| 步骤 | 实施要求 |
| --- | --- |
| 先理解，再选段 | 将文字分成完整句子和主题块。先选主旨、关键事实和必要条件，再计算时长。P0 保持源片叙事顺序，显式保护数字、专名、否定、条件和人工纠正字幕。 |
| 生成可验证方案 | 模型返回保留区间、证据引用和简要理由。服务端用证据确定合法切点，按现有帧率契约对齐。优先去寒暄、重复和过长停顿。无词级证据时按完整句段处理。 |
| 目标冲突 | 正常 30 秒样例允许 28–32 秒；必须保留内容压不进目标时，显示实际最短保留时长与原因。超过 25:00 的方案进入取舍或拆分引导。 |
| 生成草稿 | 使用固定工程快照和验证后的区间清单，完成预览与审片。用户可以开新对话、取消当前任务、查看草稿历史。 |
| 改稿 | 每次改稿创建同一草稿线的新版本。保留原草稿、用户反馈和引用时间点。点「加回这句」或在对话提出修改时用同一入口。 |

既有每轮 8 步与渲染预算保留给 M4 路径。V2 自动导演由有界阶段推进：一个任务允许一次默认预览和一次仅由可修复检查触发的重渲染；分段分析单独受并发、超时和取消约束。按顺序保存任务检查点。重启后明确恢复，已发布的步骤按原请求键回读。失败时保留成功的分析块、可读错误和可继续动作。

## 5 多区间、草稿、预览和采用

### 5.1 多区间编译与草稿数据

- 首版保持现有单视频轨和速度 1。计划允许从同一原片保留多个不重叠区间，保持源顺序。内部清单含 `assetId, mediaHash, sourceInFrame, sourceOutFrame, evidenceIds`。对齐现有半开区间，验证正长度、有效源范围、工程归属和最大成片时长。
- 用同一纯编译函数生成草稿快照与采用后的工程变更。新片段 ID 由规范化输入稳定生成，顺序和输出起点确定。字幕从源时间映射到新片段和成片时间。已纠正字幕若被移除或破坏，构建失败并给出能保留它的选择。按输出帧率的精确有理时间计算总时长。超过 25:00 时，在预览提交前拦截。
- 草稿记录至少包含 `draftId, version, conversationId, projectId, baseRevision, parentDraftRef, timelineHash, plan, status, previewJobId, qa`。每个版本不可变，已发布版本和当前选择分别存放。草稿引用已有本地素材；服务端保存编译快照和引用哈希。状态更新使用原子旁置记录。
- `GET /agent/drafts` 与 `GET /agent/draft` 读取按项目归属的摘要与详情。`POST /agent/draft/preview`、`/agent/draft/export`、`/agent/draft/adopt` 均接收精确草稿引用及操作 ID。自动生成草稿通过内部服务触发预览，用户能看到同一任务的进度。普通工程渲染 API 保持兼容。

### 5.2 发布与工程写入

- 给 Jobs 增加内部草稿快照入口。它只接受服务端从已验证草稿读取的快照。manifest 和缓存键包含项目、基线 revision、草稿 ID/版本、快照哈希、素材哈希、渲染设置和渲染器版本。同一请求重试回读同一产物；失败、取消和未完成文件不得发布。
- 预览或草稿导出只产生任务和产物。采用时读取指定草稿，按 `baseRevision` 做 CAS，并通过稳定 `commandId` 提交一个 `timeline.applyDraft` 工程命令。调用者仅提供草稿引用与操作 ID，服务端根据草稿生成验证过的命令数据。提交结果含 `draftRef, previousRevision, newRevision`。崩溃恢复后可从工程账本核对采用结果。相同操作重放只返回一次提交结果。
- 当前工程与草稿基线不匹配时返回版本冲突，原草稿继续可播放和导出，用户可用当前工程重新生成。采用后的撤回复用现有版本恢复入口。P0 扩展命令与旁置记录即可，现有工程字段和 M0–M4 入口继续读写。发布前保留完整数据备份。
- 审片至少记录文件解码、实际时长、字幕时序、受保护证据覆盖及音画问题。切点优先按完整句段和合理停顿落点。需要时检查邻近画面、音频峰值和字幕密集处。视觉模型仅在支持且本次已授权时读取画面。人工听感与视觉判断单列，按实际状态显示。

## 6 P1 卡点与参考片，P2 混剪与联网

### P1 卡点和参考片

1. **音乐与节拍。** 实现可取消的本地 `librosa.beat.beat_track` worker，固定依赖和 Windows 安装包版本。输入用户选定的音乐，输出节拍和可信度。优先选高可信节拍与自然镜头边界，检查画面来源、时长与播放连续性。低可信或素材不足时，提示换音乐或放宽节奏。第一版交付一首背景音乐、一条顺序画面轨，保留原声或明确调低音量。
2. **参考片。** 上传登记为只分析素材。使用 FFmpeg `scdet` 标出镜头边界，统计长短与切换密度。可结合节拍与已授权图像理解，生成可编辑的风格卡，包含开头节奏、平均镜头长短、字幕和声音规律。引用时间段说明依据。成片素材由用户自己的已选媒体提供。
3. **从预览改稿。** 预览暂停时记录草稿引用、成片时间与对应源时间。用已有可执行能力完成定点修改；暂时无相应工具时显示可做的调整。P1 引入可选背景音乐时，为用到该能力的项目启用版本化契约和渲染配置。旧项目按兼容路径读取。先用单条音乐与原声做混合，控制音量和淡入淡出。

### P2 轻混剪、Vlog 和搜索

1. **多素材编排。** 支持选择多段用户素材，按主题或时间顺序排在同一画面轨。保留字幕来源和现场声控制。首个 Vlog 方法为有代表性的开场、顺序清楚的主体、结尾回顾，允许逐段改顺序和恢复原声。
2. **联网找风格。** 实现可配置的 SearXNG JSON 只读搜索适配器，首版用公开结果摘要及引用链接生成风格卡。用户明确请求搜索时才发出查询，查询使用风格词而非原片内容、路径、用户字幕和凭据。搜索结果和参考视频文字都作为资料处理，里面的指令不得驱动工具。断网时继续使用本地素材和已保存风格。
3. **风格复用。** 存档用户确认的风格卡和来源，可在下一条片子选择、调整或撤销。项目偏好默认留在项目内，用户明确选择后才跨项目使用。联网学习和参考分析发生在项目策略和任务上下文层。

## 7 开源项目使用清单

帖子用于发现项目。X 原帖访问受限，本手册以能核对的上游资料做决策。每次引入代码、模型或素材都记录实际仓库、固定提交/版本、模块路径、适用许可证、依赖体积、Windows 支持和测试结果。随包文件按各自适用条款保留声明。上游能力介绍只作为待验证输入。

| 项目 | 决策 | 具体使用方法与关口 |
| --- | --- | --- |
| [whisper.cpp](https://github.com/ggml-org/whisper.cpp) | P0 直接接入 | Windows 本地 ASR，通过有界 CLI 适配；固定版本、模型哈希，验证中文、时间坐标、长录音重叠去重和打包。 |
| [FFmpeg](https://ffmpeg.org/ffmpeg-filters.html) | 沿用并扩展 | 已有包支持停顿与镜头变化检测。保留现有导出路径，先用其完成取音频、帧抽取、拼接、音量与解码校验。 |

## 8 反馈、评测与发布验收

| 层次 | 必测 | 放行证据 |
| --- | --- | --- |
| 对话和新手体验 | 「转写是什么」、无素材、缺 ASR、澄清、纠正目标、会话切换、键盘与窄屏 | 双入口操作记录；普通视图可读，下一步能点；至少 8/10 新手完成口播任务并找到草稿 |
| 素材与语义 | 真实中文、SRT、噪声、静音、数字、否定、条件、必须保留项超过目标、长素材跨块 | 样片与人工标注对照，注明转写与模型来源；标准 60→30 秒草稿为 28–32 秒；语义完整和接缝由人确认 |
| 工程与恢复 | 同源多区间、分数帧率、字幕映射、取消、崩溃恢复、并发冲突、采用重放、撤销 | 草稿和导出前后工程 revision 相同；采用只写一次；输出绑定精确草稿；旧工程可打开 |
| 交付 | 25:00 与 25:01、完整解码、音画与字幕同步、从两个入口打开草稿 | 接近上限和上限夹具的实际发布报告；软件门禁阻止超长输出；内容与人工 QA 单列 |
| P1/P2 附加 | 节拍准确性、参考片分离、搜索来源、断网、多素材与音量混合 | 独立样片、真实界面、可编辑草稿及人工评审结果 |

复用现有偏好系统。案例记录用户改了什么、为什么改，以及对应草稿版本。采用草稿是接受本次结果，只有用户明确选择「以后也这样」才写入长期偏好。为导演策略建立固定评测，保存版本、任务结果和人工判定。用同样的素材与任务比较 M4、V2 和可接通的 DSH/Codex 基线。关键指标包括任务完成率、非必要追问次数、误删必保项、首次草稿可用率与返工时间。
