## 1 产品定位与第一版范围

面向中文个人创作者，让用户通过对话与可视编辑，共同完成口播、教程和产品视频。Agent负责理解、内容取舍与反馈闭环，工作台让用户预览、选中对象、直接修改并继续交给Agent。

### 1.1 第一版建设原则

工作台、Agent和共享项目从早期同步验证。可以先做轻量片段列表、播放器与字幕编辑，复杂拖拽和高级效果随后完善；“人工改后Agent接着改”的证明必须提前。

主编辑底座先比较再决定。可选现成编辑器与适配，也可选自研薄层；依据共同编辑、工程重开、字幕、预览导出和运行成本决定，而不预设先自研数周再评估复用。

### 1.2 支持范围和默认值

| 项目 | 首版范围 |
| --- | --- |
| 使用方式 | Windows本地、单用户DSH工作区；精确版本与依赖由M0记录 |
| 任务 | 中文口播粗剪；简单带讲解的教程/产品素材；保留指定句子或操作，支持局部修改 |
| 输入 | 本地视频/音频；先用选定路径可正确解码的素材，不能只凭扩展名判断支持 |
| 基础编辑 | 选择、删除、排序、裁剪片段；字幕纠正；基础音量与淡化；输出规格设置 |
| 教程边界 | 先支持明确标注或可回看核对的关键操作；复杂步骤自动识别、OCR和多机位后续扩展 |
| 输出 | MP4、UTF-8 SRT、可重开的工程、版本差异与验收报告；烧录字幕路线在M0验证 |
| 规格 | 创建项目时明确分辨率、画幅、有理数帧率及音频配置；默认值必须展示并写入工程 |
| 资源范围 | M0记录验证过的文件数量、总时长、分辨率及硬件；范围外提示未验证，不伪称已支持 |

首批验收素材可采用1至3段、累计约10分钟、1080p作为测试规模建议，不据此宣称产品极限。多轨高级合成、变速、复杂转场、自动全网对标与独立应用分发不作为首版退出前提。

### 1.3 用户控制与需求冲突

用户表达目标、必须保留项和输出要求；Agent整理为可检查的任务简报。需求范围内可撤销的编辑可以推进，涉及改变核心表达或放弃保留项时给出取舍。不能为满足时长暗中删除限制说明或改变否定语义。

任务简报至少含受众/用途、目标与允许偏差、保留项、输出规格、作用范围和已知缺口；缺省项使用显式默认值。来源不清或素材不足时说明依据，不将低把握判断写成完成事实。

## 2 Agent与Skill的责任

产品Agent承担：理解目标、评估素材、组织结构与选段、选择能力、执行提案、接续人工修改、检查实际预览、局部修正并记录反馈。

| Skill类别 | 内容 | 功能 |
| --- | --- | --- |
| 主Skill | video-editing | 理解任务、选择与组合方法、协调范围和冲突、组织交付 |
| 通用流程 | footage-intake、revise-edit、render-qa | 素材接收、局部修改、实际产物验收 |
| 首个专项 | talking-head-roughcut | 按讲话内容选段、去重复停顿、组织顺序并保护语义 |
| 后续专项 | 卡点、教程产品、访谈、Vlog等 | 针对具体任务和片段范围提供方法 |

主Skill不堆积全部专项规则。Skill由同一Agent按需读取，不等于另一个Agent。第一版先完成主Skill、三个通用流程与口播专项；新增方法还需对应可用工具和共同提案接口。

新Skill声明名称、功能、适用场景、依赖能力、作用范围和产出类型。涉及编辑时统一返回提案：项目与baseRevision、目标片段、候选操作、来源依据、保留约束、待确认事项。专项不直接覆盖工程。

选择、组合、切换和能力缺失均要验证。例如卡点只处理指定B-roll，不能截断受保护讲解。首版可以用受控测试夹具验证第二专项路由与冲突处理；夹具通过只证明接口，不宣称已交付真实卡点剪辑。

## 3 总体架构与依赖边界

```text
工作台页面 ───┐
              ├─ 项目服务 / 编辑命令 / 版本 / 变更通知
产品Agent ────┘                 │
                         能力与执行适配器
                       编辑器 / 媒体 / ASR / 渲染
                                │
                        工程、任务与产物存储

DSH提供：插件组合、模型与工具、会话、运行任务、界面扩展与通信。
```

### 3.1 工程所有权

一份项目只有一个权威编辑服务。若采用现成编辑器，由其工程和编辑服务承载时间线，项目服务作为共同入口及业务映射；若自研，则由本项目命令层拥有。不得同时维护两个可独立修改且不一致的时间线。

工作台与Agent都经该入口写入。原生编辑器已有写入口时，必须接入其事务、变化通知与版本机制，不能靠定时复制另一份project.json补同步。

### 3.2 模块依赖

领域逻辑不依赖DSH或React，通过接口接收存储、执行器和显式配置。Host、工具适配、任务桥接和Client可以使用相应DSH API。领域代码可以与插件同包分目录，禁止的是反向依赖，不是目录共存。

工作台只保存选择、播放位置、缩放等交互状态；工程内容、任务和版本以服务为准。允许根据交互验证补充Host接口，但必须维护契约兼容和回归；不以“Host完全零修改”判断早期工作是否有效。

### 3.3 可复用的DSH机制

插件装载、作用域、工具注册、运行jobs、存储、凭据与界面扩展优先复用DSH。视频项目定义自己的内容语义、工程映射、业务任务与验收，不重复建设通用插件市场或另一套Agent运行框架。

接口依照M0固定版本核对，参考[官方架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)、[Web Client](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/web-client.md)、[Jobs](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/jobs.md)、[Storage](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/storage.md)与[MCP](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/mcp.md)。

## 4 工程 时间与编辑契约

以下是逻辑契约，在M0映射到所选编辑器。字段落在原生工程、关联清单或数据库由ADR明确，不能因此再建平行权威工程。逻辑约束验证后才固化具体schema与接口。

### 4.1 工程与对象

| 对象 | 至少需要表达 |
| --- | --- |
| 项目头 | schemaVersion、projectId、当前revision、outputSpec、requirements及工程引用 |
| 素材 | 稳定assetId、内容hash、原始路径/URI、原始规格与stream信息、工作媒体引用 |
| 工作媒体 | 独立标识/hash/路径、转换参数、fps与时间原点、旋转/像素比例及音画偏移处理、回到原素材的映射 |
| 时间线 | tracks持有segmentIds等引用；片段实体只保存一份，含segmentId、trackId、assetId、来源区间与输出位置 |
| 转写 | sourceTranscript、来源词/区间与时间、识别配置、缺失时间和不确定项 |
| 字幕 | 文本纠正记录与字幕实例；实例关联具体segmentId和来源词/区间，再派生输出时间 |
| 历史 | revision索引、父revision、命令、操作者、不可变快照或原生等价历史 |
| 任务与产物 | 持久化业务记录及产物引用，不把所有日志和历史塞进当前工程正文 |

片段标识不复用，同一素材多次出现在工程中形成不同片段实例。字幕纠正与原始转写分开保存，重排或裁剪后重新映射对应实例并保留纠正；自建标题明确采用输出时间锚定。

### 4.2 时间与媒体归一化

项目采用整数帧与有理数fps，例如`{num:30000, den:1001}`，区间统一为`[in, out)`。源时间保留素材时间基准、时间戳与原点；微秒可以作为归一化接口表示，但不能替代全部原始信息。

点位转换默认取最近帧，半帧按统一规则处理；需覆盖完整内容的来源区间按起点向下、终点向上量化，并记录策略。输出帧区间及预期总帧数由代码计算。外部适配器采用不同取整方式时显式转换并报告差异。

验收分别检查：帧网格值往返保持帧号；非网格时间的误差在相应量化界限内；29.97等分数帧率按实际有理数测试。不要求任意微秒与整数帧往返无损。

VFR或不兼容输入可以生成CFR工作媒体。必须保留原素材、归一化媒体和转换记录，核对时间原点、旋转及音画偏移；转写、抽帧、渲染明确引用哪份媒体及映射。容器扩展名不等于编码或时间戳支持情况。

首版编辑speed固定为1，变速、转场、多机位同步等通过后续契约版本扩展。

### 4.3 编辑提交与幂等

建议入口为`apply(command)`，包含commandId、projectId、baseRevision、op、target与params。校验对象、时间、约束、能力及版本后，在同一原子提交内完成版本比较、状态写入、历史与幂等结果记录。

单用户本地实现可采用每项目写队列与原子持久化，或存储事务。两个调用不能都检查旧revision成功后分别覆盖新状态。成功返回newRevision、diff和affectedIds；失败返回稳定错误码、说明及适合重试的条件。

同一commandId与相同内容重试返回原提交结果，不再次修改；同一ID携带不同内容报错。重试结果不代表它仍是当前最新版本，调用者继续处理前需读取项目头。

### 4.4 撤销 回滚与历史

revision单调递增且不复用。回滚通过新命令恢复目标内容并生成新revision，例如r3恢复r1内容后成为r4。历史保持可追溯，旧baseRevision不会重新匹配新的内容。

工程重开必须恢复当前内容和当前revision。若原生编辑器历史与业务revision不同，适配器记录两者对应关系，保证人工操作与Agent操作都进入同一可追踪历史。

## 5 渲染 业务任务与能力适配

### 5.1 冻结输入与验收

提交渲染时生成不可变renderManifest，至少记录projectId、revision、工程快照及hash、媒体/字幕/字体等依赖hash、输出规格、所用工具/适配器版本和参数。

渲染、产物和验收都引用同一清单。逻辑接口为`render(renderManifest)`与`verify(artifact, renderManifest)`，不能拿当前最新工程去验收旧版本成片。任务运行中用户继续编辑时，旧结果标明所属版本，不覆盖新项目或伪装为最新结果。

缓存键使用完整的渲染相关内容和实现配置，不只用revision，也不包含无关时间戳。只有产物存在、完整且验证有效才复用；回滚后的相同画面可复用有效缓存，缓存失效时允许重渲染。复用也要建立当前任务与清单的验收引用。

可使用工作目录或`.partial`中间文件；完成校验后原子发布到稳定产物路径。文件存在不等于任务成功，未完成文件不能进入作品库。

### 5.2 业务job与DSH运行job

| 层次 | 负责内容 |
| --- | --- |
| businessJob | 持久化jobId、项目revision、输入/清单、provider版本、尝试、状态、产物和检查结果 |
| executionAttempt | 每次运行关联执行器、runtimeJobId、Session owner或CLI运行标识、进度、退出信息和日志 |
| DSH运行任务 | 在DSH模式下管理执行进度、输出、等待与取消；CLI模式采用对应执行适配器 |

建议业务状态包括queued、running、verifying、succeeded、failed、canceled；取消请求另标cancelRequested，恢复核对期间标needsReconcile，确认执行中断则标interrupted。

DSH运行中映射为running；停止请求只表示取消处理中；执行completed后进入verifying，检查通过才succeeded；failed或killed须结合真实执行结果结算。DSH运行记录不替代持久化业务事实。

任务提交携带稳定requestId与输入摘要；同ID同内容通过原子去重返回既有businessJobId，同ID不同内容拒绝。调用端重试沿用requestId，不能每次网络尝试都重新生成。每个业务job最多有一条未结算attempt，启动、恢复与重试原子取得执行权；结果未明时先核对，不重复启动。显式失败重试创建新attempt，重试请求本身同样幂等。

重启后核对清单、已发布产物及外部执行状态。无法确定是否仍在执行时保留待核对，不直接判成功或重复启动。恢复可以从有效输入重新执行，不承诺所有后端支持断点续跑。

### 5.3 能力适配器

| 描述 | 约定 |
| --- | --- |
| 发现 | providerId、capabilityId、apiVersion、实现版本、输入输出schema |
| 就绪状态 | available、notConfigured、missingDependency、incompatible等，并给出原因 |
| 限制 | 格式、语言、时间精度、支持操作、资源条件及执行位置 |
| 执行 | `run(input, {signal, onProgress})`；长任务关联统一业务job |
| 进度 | stage必有；percent可未知，不编造百分比 |
| 取消 | 声明任务级、进程级、尽力取消或不支持；请求不等于已停止 |
| 错误 | code、message、retryable及详情引用；权限/配置/输入不支持不做盲目重试 |
| 缓存 | 输入内容、参数、模型/工具/适配器版本共同决定有效性 |

本地进程取消需确认对应进程树已停止；HTTP/MCP任务按服务实际能力映射，不要求所有provider“杀进程组”。不允许中断不属于本任务的共享执行。原始日志落盘，模型与页面按需读取摘要和片段。

同一能力可有多个实现，工作台与Agent消费同一目录。当前不可用的方法明确反馈缺失，可选择已验证替代实现；不把安装成功当作已就绪，也不让每个后端各建项目状态。

## 6 里程碑与任务依赖

M0至M3组成首版建设。工作台和Agent从M0/M1一起验证；内核完善、页面完善与方法完善沿同一条真实任务迭代。排期在M0记录实际耗时和限制后估算，更新成本由范围、集成和素材质量共同决定。

| 阶段 | 目标与主要交付 | 退出依据 |
| --- | --- | --- |
| M0 选型与可行性 | 少量候选比较、真实DSH工具调用、最小页面、预览/导出小样、ADR | 候选可读写工程；界面和Agent可观察同一项目；关键兼容性明确 |
| M1 最小共同编辑 | 项目服务、命令、revision、页面播放器/字幕或片段列表、Agent操作工具、任务桥接 | AC-01至AC-05：共同读取、人工后Agent接续、冲突、幂等和重开 |
| M2 真实剪辑闭环 | 真实中文转写、按需画面、选段提案、字幕、异步渲染、实际验收 | AC-06至AC-09：内容有依据、快照一致、取消恢复及媒体边界 |
| M3 首版验收与扩展证明 | 五个首版Skill、专项路由/组合、反馈、作品入口、固定任务集 | AC-01至AC-10联合回归、人工审片及已知限制清单 |
| 后续扩展 | 教程视觉、访谈、卡点/Vlog、对标搜索、偏好复用、外部工程 | 为新增能力建立专项验收后逐项发布 |

### 6.1 M0任务

| 卡号 | 任务与产出 | 验证重点 |
| --- | --- | --- |
| M0-T1 | 建立真实素材及输出基准，明确测试输入与必须保留内容 | 中文、字幕、手机/录屏、音画及路径条件 |
| M0-T2 | 比较最多两条进入验证的编辑路线，记录比较表 | 现成底座/适配与薄层方案的工程、共同编辑、预览导出及依赖成本 |
| M0-T3 | DSH联合小样：插件加载、Agent调用探测、页面读项目、提交修改 | 精确版本、Host/Client通信、工具结果、变化通知 |
| M0-T4 | 异步小样：渲染或受控长任务、查看进度、取消与回读 | 业务job到运行job的映射，不只验证脚本能跑 |
| M0-T5 | 形成ADR并给出M1任务卡 | 选型理由、运行环境、限制、待验证项与复审条件 |

硬编码选段或假转写只用于验证接口与媒体执行，不计作Agent内容判断或转写质量证据。联合小样使用真实Agent工具调用，Skill正文和完整编辑界面不需要一次做全。

### 6.2 M1任务

| 卡号 | 依赖 | 任务与产出 |
| --- | --- | --- |
| M1-T1 | M0-T5 | 工程所有权和逻辑字段映射；正反样例与兼容策略 |
| M1-T2 | M1-T1 | 时间转换、工作媒体与字幕来源映射 |
| M1-T3 | M1-T1 | 原子编辑、baseRevision、commandId及统一错误 |
| M1-T4 | M1-T3 | 不复用revision、撤销/回滚、工程重开 |
| M1-T5 | M1-T3 | 页面选中/字幕修改与Agent工具共用命令入口 |
| M1-T6 | M0-T4、M1-T4 | 冻结清单、业务job、运行适配、初步预览/导出与回读 |
| M1-T7 | M1-T2至M1-T6 | AC-01至AC-05集成演示，并保存证据 |

### 6.3 M2与M3任务

M2完善一个真实中文ASR路径、转写质量表、可回查摘要和按需画面读取，再接选段提案、字幕映射、完整渲染与验收。时间戳缺失要报告和补对齐，不能以“十分钟每个词必须都有时间”掩盖模型局限。只有粗粒度时间时限制精细切点能力。

M3完善主Skill及通用/专项方法，验证路由、组合、缺能力反馈，覆盖成功、局部修改和真实失败。作品库与“做同款”是连续使用入口，不能代替共同编辑验收。

## 7 开发AI任务卡与协作规则

开发AI负责已授权任务的实现、适当测试、修复、运行验证和记录证据。负责人决定产品取舍与重要架构变更，验收真实素材的内容和体验；产品Agent仍需承担剪辑任务中的判断。

### 7.1 任务卡模板

```md
### M?-T? 名称
- 目标：一个可独立验收的行为
- 依赖：前置任务及实际状态
- 依据：ADR、契约及相关文件
- 输入与输出：接口、样例和预期改动位置
- 验收：项目中实际存在的命令、期望行为及对应AC编号
- 异常与集成：与本次行为有关的失败、兼容和接线检查
- 人工检查：内容、观感或交互事项
- 边界：已授权范围与需要提出的语义变化
- 交接：完成项、证据、未解问题和下一步
```

本文的接口名、目录和任务产出是设计，不代表命令已存在。执行卡在开工前确认真实运行方式；尚无脚本时先在该卡建立所需验证入口，再报告实际运行结果。

### 7.2 改动规模与决策

每卡围绕一个行为，可以修改完成它所需的实现、schema、适配、配置和测试文件；说明清单和依赖，不以三个文件为硬上限。无关功能与大规模重构另行组织。允许在同一会话继续相关卡，跨会话保存事实状态。

已授权范围内的实现、文档与测试修复自主完成。影响产品范围、已发布接口语义、历史兼容、工程迁移或引入显著运行/许可/服务条件的新依赖，先提出可审阅方案与影响。兼容新增错误码和常规内部调整记录理由，不要求每个条目都中断工作。

不为通过测试偷偷改变目标或缩小样例范围。遇到反复失败，保留最小复现，说明观察、已排除原因和下一次验证假设；只有外部阻塞才请求缺失信息，不靠无变化重试消耗时间。

### 7.3 完成证据

提交实际运行的验证命令、结果摘要与日志位置，修改文件清单、工程/产物路径、适用环境和未验证项。长期保存必要日志，不将密钥和完整媒体塞进聊天。验证层级分为契约/行为、集成、媒体结果、人工审片，不用底层单测替代整体任务。

## 8 首版验收与度量

以下AC为本文件的固定验收标识，阶段引用这些编号，不再引用外部文档条目数量。通过情况逐项记录，未实现不能写通过。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 共同读取 | 页面与真实Agent读取同一工程 | 项目、revision、素材与所选对象引用一致 |
| AC-02 接续人工修改 | 用户改字幕，Agent再缩短开头 | 人工纠正保留，目标修改生效，差异可见 |
| AC-03 并发与旧基准 | 人与Agent基于同一旧revision提交 | 不发生静默覆盖；冲突返回当前版本并可重新核对 |
| AC-04 幂等与回滚 | 重试命令、恢复旧内容后继续编辑 | 相同命令不重复应用，回滚生成新revision，旧ID不同内容报错 |
| AC-05 工程重开 | 重启或重新打开工程 | 恢复正确当前revision、内容与历史引用，媒体缺失明确报出 |
| AC-06 内容与来源 | 真实素材按目标生成剪辑提案 | 选段可回查，必须保留项有证据，冲突或缺口明确 |
| AC-07 渲染版本 | r1渲染时继续编辑到r2 | 产物和报告只验收r1清单，不覆盖或误标为r2；有效缓存可复用 |
| AC-08 任务可靠性 | 重复提交、失败、取消、中断与重新启动 | 同请求不重复启动，同job最多一条未结算attempt；状态有依据，未完成文件不发布，资源停止可核对 |
| AC-09 媒体边界 | CFR/VFR、分数帧率、非零原点、旋转、缺音轨、中文路径 | 支持项按基准正确；不支持项明确拒绝，字幕与音画映射可验证 |
| AC-10 Skill扩展 | 分别验证方法选择、限定范围组合、方法切换与能力缺失 | 四种情形都有样例；第二专项可用受控夹具，组合冲突和保护范围实际检查，提案格式一致 |

### 8.1 文件 内容与人工验收

文件验收检查实际解码、预期视频帧数、画幅、音轨与字幕产物。音频时长、编码延迟与音画起点按所用采样率和编码策略单独定义容差；不能只看容器总时长或统一以“误差小于一帧”代替全部检查。

内容验收核对指定语义、句子与画面。字幕出现产品名不独立证明原声保留；来源片段正确也不独立证明渲染无误。必要时回看、回听或重转写辅助核对。人工验收评估节奏、自然度、字幕观感和是否还需修改。

### 8.2 样例与指标

先用少量真实素材做选型，逐步形成约12至20个有明确要求的任务。开发样例与未参与调优的保留任务分开维护，保留任务须覆盖首版主要场景，而非仅随机留三条。

ASR分别记录关键实体/数字/否定词错误、一般转写错误、时间对齐和缺失覆盖。每个比率写清分母、人工标注和统计规则，不用单一“错误率5%”自动决定换模型。关键保留内容逐项核对。

记录任务完成情况、关键内容保留、人工修改次数、阶段耗时、模型/转写/渲染成本、失败类型与使用环境。摘要策略兼顾上下文开销、信息保留和回查能力；token预算依据实际模型与任务设定。

每次能力替换或相关功能变动，运行受影响行为与集成/媒体样例；阶段结束做联合回归。结果仅说明本轮样例与条件，不填入未测到的效果数字。

## 9 目录与数据布局

以下为责任边界示意，M0选型后统一语言、构建和具体路径；不是已经存在的实现文件。

```text
video-agent/
├─ package.json / cordis.patch.yml
├─ src/
│  ├─ core/       项目、命令、版本、时间、业务任务与接口
│  ├─ adapters/   编辑器、媒体、ASR、渲染、存储等实现
│  ├─ dsh/        Host、工具、运行任务桥接与路由
│  └─ client/     DSH界面入口、播放器、字幕、片段与版本交互
├─ skills/        主Skill、通用流程与专项方法
├─ schema/        M0确定的逻辑数据与能力契约
├─ test/          行为、集成与媒体基准
├─ docs/adr/      选型、证据与复审记录
└─ outputs/       方案及调研资料
```

项目数据放在配置的工作区：工程/原生工程引用、历史快照、原素材或引用、工作媒体、分析、任务、日志与发布产物分工保存。$DSH_HOME可保存索引与设置，项目本体应可定位并重开。相对项目路径、外部媒体引用和迁移方式由存储ADR明确。

## 10 风险与扩展边界

| 风险 | 对策与验证 |
| --- | --- |
| 编辑底座不适合共同编辑 | M0比较，M1真实页面和Agent往返，及时复审模型映射 |
| 中文识别与对齐不足 | 真实术语样例、热词/纠正与备选路径，明确缺失精度 |
| 人工修改被覆盖 | 原子版本检查、统一命令、差异和撤销 |
| 预览与导出不一致 | 尽量共用渲染语义，固定媒体/字体/参数；实际结果比较 |
| 外部任务状态不明 | 业务事实与执行记录分层，取消和重启核对，不虚报完成 |
| Skill或provider不断增加 | 按需目录、统一提案/结果、就绪状态和专项回归 |
| 外部工程效果损失 | 逐格式适配并报告保留、简化和未支持项 |

对标搜索、素材获取、参考分析与应用分别接入。偏好先保存用户明确确认的规则，跨项目复用与自动方法优化分开验收。新的流程复用共同工程、命令和任务，不再各建一套状态。

在现有DSH Desktop运行插件、对外部署Web、分发自己的桌面应用是不同交付。首版以DSH内可体验插件为目标；独立分发、对外服务和脱离DSH的应用需要另立范围、选型与排期，不设置强制M6。
