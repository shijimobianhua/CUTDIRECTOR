## 0. Codex 接手规则

1. 先读两份 V3.2 文档。PRD 定义用户体验和发布范围，本手册定义实现和验收。M0–M4、V2 文档只用于理解遗留行为。本文的 M0–M3 均指 **V3 的实施批次**。
2. 检查实际仓库、当前工作树、`AGENTS.md`、已有测试和 DSH 安装版本，记录基线提交与脏文件。保留现有未提交工作。先在开发目录、独立 DSH 测试 profile 和隔离数据目录验证。
3. 以真实 DSH 侧栏打开页面做验收。浏览器组件测试、模拟模型、模拟视频和 fixture 各自标注。Windows 剪映实机、Codex 实际图片和 Seedance 实际视频单列证据。功能标为可用的条件是验收通过。
4. 从两条工作流沿用户路径逐步接通。每批交付运行命令、版本、场景、证据路径、失败项和下一批依赖。用本文末尾覆盖表逐条勾对；任何未过项保留为待验收。
5. V3 发版包仅交付 DSH 插件及其运行依赖。保留本机媒体处理进程和磁盘数据；退役可独立访问的工作台、浏览器启动、双击启动器、快捷方式和旧独立服务入口。正式替换在隔离 profile 通过后执行，迁移和回退见 §11。
6. 首发工程以非商业和公开源码为发布范围。固定上游版本、记录移植位置和许可，写第三方声明。付费实测使用已获批准的额度和素材。未知剪映版本、未通过的图像能力和无法核对的远端任务有独立状态。

## 1. 宿主、服务与源码落点

### 1.1 入口及信任边界

```text
DSH Desktop 当前 profile
  ├─ 侧栏 CUTDIRECTOR → 嵌入页面 /video-agent/
  ├─ CUTDIRECTOR Host → 同源 /video-agent/v3/*、页面资源和受控媒体流
  │   ├─ DSH ctx.llm 单次模型推理、DSH Skill 发现、受控工具和子 Agent
  │   └─ 私有进程通道 → V3 工程服务、任务队列、文件处理和适配器
  └─ 旧项目兼容页 → Host 限定的旧 writer 接口和旧数据目录
```

- 延用当前插件 ID `@local/video-agent`、侧栏注册键 `video-agent` 和插件 URL 前缀。保留现有 `src/client/client.js` 槽位与 iframe 嵌入模式。将标题改为「CUTDIRECTOR 视频制作」。设置和工具中心均在该插件内；宿主原生对话无需创建。用 DSH 当前版本实际支持的 API 完成设置跳转或窗口回焦。M0 无对应 API 时显示「打开 DSH → 设置 → 模型」，带「重新检查」和现有可选能力。
- Host 作为唯一网络入口。页面、样式和脚本由插件服务；工程、媒体和上传仅走同源 Host 路由。将 V3 私有服务以非 detached 子进程启动，绑定 `127.0.0.1:0`，用继承的 IPC 报告端口和健康握手。Host 生成每次启动的随机凭据，经 IPC 传递，内部每个请求验证凭据及 Host；禁止把凭据放入 URL、网页、启动参数和日志。用户页面的 bootstrap 绑定 DSH 插件嵌入会话，普通浏览器顶层打开不给予写权限或完整工作台；M0 验证当前版本可用的嵌入校验机制。可选用经 M0 验证的纯 IPC 传输替代私有 HTTP，须保持同等的流式上传与媒体 Range 契约。
- Host 出口按操作白名单转发，核对当前 profile 与项目归属、请求方法、内容类型、体积和同源信息。写入要求同源 + 实例绑定的短期页面会话和防跨站令牌，Host 重新签内部请求。CSP 至少限制脚本和连接到本源、媒体到受控源，设置 `frame-ancestors 'self'` 和禁用对象嵌入。允许的外链由 Host 打开并限经验证的 HTTP(S) 地址。媒体服务支持 Range、206/416、MIME、校验过的相对引用，省去绝对路径暴露。
- Host 生命周期按 profile 防重复启动。握手校验协议版本、实例与数据根标识。旧版固定端口 `7793` 只用于识别遗留实例。V3 发布配置移除 `adapterUrl` 固定端口和全局 `projectId: P`；每个请求携带作用域。旧 writer 在 DSH 内按需启动，通过认证的私有路径访问。现有旧工作台资源可在兼容路由内复用，兼容页无法直接访问旧独立端口。旧写入、回退、预览和渲染须回归。
- 关闭插件页时仅关闭浏览器订阅，Host 仍调度；切换项目仅改视图。退出 DSH 或卸载插件时停止接新任务，限时保存状态并终止自有子进程。子进程监视父进程连接，异常退出时释放资源；工具子进程使用受控进程树，退出时只清理自己启动的进程。远端任务用外部 ID 在重启时续查，尚未拿到外部 ID 按 §7 核对。停用后不存在可以打开的独立前端。
- DSH 文本模型通过 Host 在当前 profile 的 `ctx.llm` 目录与单次推理接入。现有 `src/host/model-bridge.js` 可借鉴目录、流式读取与取消；V3 使用当前实例的私有通道调用 Host 模型。写入权限留在 CUTDIRECTOR。对现有 `video_project_apply` 等 DSH 通用工具做能力盘点，V3 默认代理清单不暴露旧时间线写工具；旧项目兼容页的写入走原明确的用户操作与确认。子 Agent 隔离未验证时禁用委派按钮并提供同阶段手工路径。

## 2. 本地数据、版本与一致性

### 2.1 存储和对象模型

- 每个 DSH profile 有自己的数据目录、媒体库、SQLite 数据库、临时目录和日志。采用宿主可证实的 profile 标识及数据位置。若宿主不提供目录 API，通过管理员安装配置传递固定路径，禁止从请求或模型选择数据根。Windows 同用户权限保护数据库和凭据。媒体按内容哈希去重，归属仍逐项目或灵感显式登记。
- SQLite 开启外键和 WAL，单进程写入。项目快照、命令回执、任务状态和事件在同一事务落盘。媒体先写临时文件，校验后原子改名并登记；启动时核对残留 staging 和无引用文件，仅回收自有临时目录。备份用一致性数据库快照加媒体清单和校验值。
- 稳定标识用 UUID。项目、灵感和镜头为逻辑 ID，可编辑内容各有独立版本 ID。存储整数微秒；区间为左闭右开，边界按源媒体 time base 对齐，字幕进出统一做显式转换。UI 默认显示秒或分秒。禁止用数组位置充当镜头身份或直接比较不同媒体的原始帧数。

| 实体 | 必须字段及约束 |
| --- | --- |
| ProfileSettings、Connection | profileId、用途、adapterId@version、provider/model 引用、endpoint 标识、credentialRef、启用及能力检测结果；存凭据引用，浏览器不读密钥 |
| Idea、IdeaVersion、IdeaProjectLink | 原文、来源 URL/时间、附件、标签、置顶、派生标题和方向、引用记录。原文和派生分开，合并生成新版本并保留来源 |
| Project、BriefVersion、Decision | 名称、规格、目标时长、来源、当前简报、工作流版本、项目 revision、已批准决定及引用；被采用版本不可原地改 |
| Asset、AssetLink、UploadGrant | 类型、来源、哈希、可读状态、时长/尺寸/音轨、拥有范围、参考/可使用、受控存储引用。上传授权绑定指定素材版本和目标服务 |
| Shot、ShotInputVersion、Candidate、ShotSelection | 镜头稳定 ID、顺序、画面/动作/时长、起止图与提示、素材区间、依赖引用；候选绑定输入快照、任务、生成器、费用和检查；当前选用单独保存 |
| ArrangementVersion、SubtitleVersion | 有序镜头和素材区间、转写证据、字幕轨版本、确定的总时长；草稿输入来自一份已采用编排快照 |
| Conversation、Message、ViewState | idea/project 作用域、历史、焦点对象、上下文引用、可定位回执、当前会话、活动页和筛选。输入框草稿按作用域保存，敏感字段不进入 ViewState |
| WorkflowVersion、DependencyEdge、Preference | 阶段、产物输入输出边、替换影响图；项目或当前 profile 偏好、依据、来源决定、启停与撤销记录 |
| Task、TaskAttempt、DispatchRecord、Event | 作用域、阶段、输入指纹、执行器/模型/Skill 固定版本、外部 ID、取消标记、失败分类、事件序号与产物。派发记录在外部请求前持久化 |
| Approval、CommandReceipt | 授权人、目的、上传范围、估价和数量、写入目标、输入指纹、有效期、使用状态、稳定请求 ID。回执包含事务版本、改动对象、差异和可撤销条件 |
| Handoff、FinalVersion | 交接类型、已选素材/区间/字幕、剪映版本、目录和草稿 ID、程序检查与实机结果分别记录；成片文件、校验、关联交接、当前主版本 |
| SkillVersion、PluginVersion、RouteReceipt | 来源、许可、内容哈希、能力和角色、允许范围、版本、可用状态、本次路由理由及固定输入，支持停用和审计 |

### 2.2 写入、撤销与依赖更新

- 写命令带显式 `scope`、目标 ID、`expectedVersion` 和 `commandId`。唯一键至少包括 profile + scope + commandId。同 ID 同内容复用原回执；不同内容返回 `IDEMPOTENCY_CONFLICT`。版本冲突返回当前版本及安全刷新动作。页面保留用户输入，禁止自动拿新版本强写。
- 低风险变更生成可逆的领域命令，回执记录该对象的前后版本。撤销前确认相关字段未被后续修改，冲突时给「查看历史／另存为新版本」。外部付费、写入剪映和真实文件删除不走对话撤销。草稿撤回通过创建新版本或在剪映处理。
- 输入内容变更后沿依赖图标记下游「需要复查」，保留已有产物和费用。比如修改镜头 2 尾图可影响镜头 3 首图；只有依赖引用变化才传播。用户复用旧版本时记录选择与确认依据。标题改名等元数据仅触发对应的审核。重跑由用户逐镜或选择影响范围，重新审批。
- 重连媒体必须重新探测。哈希一致只更新位置。内容不同显式创建新素材版本，列出受影响镜头并失效旧审批。导入最终成片、旧项目或图像候选都禁止从模型回包指定任意磁盘路径。

## 3. Host 接口与页面同步

统一前缀 `/video-agent/v3`。下表路径是实施契约，可在保留语义和覆盖的前提下按仓库路由风格调整。JSON 统一为成功 `{ data, cursor? }` 或失败 `{ error: { code, message, nextAction?, diagnosticId, retryable } }`。文件上传、下载、SSE 使用各自媒体类型。错误文本按用户语言生成，绝对路径、堆栈和凭据只在受控诊断中按需脱敏输出。

| 接口 | 关键语义 |
| --- | --- |
| `GET /bootstrap` | 页面会话、profile 能力摘要、最近项目、上次工作区、任务待办与数据协议版本。无模型正常返回 |
| `GET /ideas`、`GET /ideas/:id`、`POST /ideas` | 按游标、关键词和类型分页。保存原文、链接、文件引用，返回相关卡。连接断开时保留待发草稿和请求 ID |
| `GET /projects`、`GET /projects/:id`、`POST /projects` | 创建空项目、从灵感、示例或旧工程导入。详情返回已采用版本、阶段和事件游标。明确的 ID 绑定项目，移除全局活跃项目写法 |
| `POST /commands`、`POST /receipts/:id/undo` | 白名单变更，包括灵感引用、版本采用、排序、选择区间、字幕、偏好、任务计划和草稿预检。回执可定位并写事件 |
| `POST /uploads`、`PUT /uploads/:id/content`、`POST /uploads/:id/finish` | 创建受控上传，流式写入、限大小与超时，结束时校验并返回素材或 Skill 预检引用。单文件失败独立处理。取消或过期清理暂存 |
| `GET /assets/:id/content`、`GET /assets/:id/thumbnail` | 只服务授权媒体和归档文件。视频支持拖动播放，HTML/脚本附件以下载处理 |
| `GET/POST /conversations`、`GET /conversations/:id/messages`、`POST /conversations/:id/messages` | 作用域化列表、新对话、分页历史和发送；消息附 focus、目标版本和客户端消息 ID。发送返回 runId 和游标。支持更新当前打开的会话与位置 |
| `GET /events` | SSE 按 scope 和游标补播，事件有递增 seq、类型、主体 ID 和最少更新数据。心跳及断线重连，游标过期让页面读取快照再订阅。Host 不套用现有短请求超时；实机阻断 SSE 时用同游标长轮询 |
| `GET /tasks`、`GET /tasks/:id`、`POST /tasks/:id/actions` | 查询与按项目/工具筛选。动作限状态机允许的取消、继续核对、重试回收、标记人工检查。重拍创建新任务计划，按新费用审批 |
| `POST /approvals/:id/decision` | 绑定输入、额度、权限与幂等键，一次性批准、拒绝或撤回未使用授权。仅页面明确操作可发起。过期或变更后重新预检 |
| `GET /connections`、`POST /connections/actions` | 列目录、检查、保存、设默认、更新密钥、停用、测试已有功能。回包仅连接摘要和诊断。付费试生成仍走审批和任务 |
| `GET /skills`、`POST /skills/import-preview`、`POST /skills/actions` | 查询、导入预览、添加、停用、设偏好、升级、回退、导出预检和下载。默认按当前 profile 查 |
| `GET /plugins`、`POST /plugins/actions` | 查看能力、来源、状态和权限。M3 增加验证后启用、停用、重测和替换。通过 DSH 支持的安装流程 |
| `POST /handoffs/prepare`、`GET /handoffs/:id`、`GET /handoffs/:id/package` | 预检、查看和下载。原生写入从审批派发，素材包从同一快照生成。成片回收经导入与归档命令关联交接 |
| `GET /legacy/projects`、`POST /legacy/:id/import` | DSH 兼容区列出旧工程、会话、交付，指定旧 revision 派生制作工程。旧写接口另设白名单兼容路径 |
| `GET/POST /templates`、`GET/POST /workflows` | M3 的模板预览、导入导出、画布拓扑和保存。实际运行仍走命令、任务、审批和事件 |

示例命令和事件：

```json
{
  "scope": { "type": "project", "id": "p1" },
  "commandId": "client-stable-id",
  "kind": "shot.selectCandidate",
  "targetId": "shot-02",
  "expectedVersion": "selection-v3",
  "input": { "candidateId": "candidate-09" }
}
```

事件类型至少覆盖 `message.created`、`reply.delta`、`reply.final`、`receipt.committed`、`entity.updated`、`approval.changed`、`task.transitioned` 和 `asset.validated`。已提交的消息和最终结果可重放。短暂文字流可以丢弃，重连后以已持久化的最终消息为准。页面根据 seq 去重，切换作用域后丢弃旧订阅对当前视图的更新。清除筛选、切换路由、窗口 resize 和动画都不能取消后台任务。错误动作按确定原因选择「重试这一步」「继续查询」「回到连接」或「补齐素材」，避免统一刷新。

### 4.2 页面布局及路由

页内主导航为「首页／灵感／项目／设置」，任务中心常驻顶部。用插件内部 hash 路由承载深链接，例如 `#/ideas/:id`、`#/projects/:id/shots?shot=…`。页面模式由显式状态控制，Host 嵌入页卸载后从工程记录恢复。

```text
DSH 侧栏  | CUTDIRECTOR 插件区域
          | 首页  灵感  项目  设置                  任务（待处理 2）
          | ← 项目       咖啡短片    现在：检查镜头   [先做一个镜头]
          | 对话              | 简报 / 分镜 / 素材 / 交付    | 镜头 02
          | 当前：镜头 02     | 固定成果区、镜头卡            | 开始图 / 结束图
          | 历史 / 新对话     | 草案、已选、待复查            | 候选 / 提示词
          | [和导演说想法]    |                              | [采用这一版]
```

以 **iframe 容器宽度** 断点为准。≥1200 px 三栏，左 280–340 px，右 300–340 px，中间可伸缩。900–1199 px 双栏，镜头详情按需侧抽屉。<900 px 单栏，顶部「项目／对话」切换，详情占主区并带明确返回。≥1600 px 限制阅读宽度，媒体按可用空间延展。720 px 以下继续保留可操作布局，支持 Windows 125%/150% 缩放。不要把主动作、回退或播放控件塞入仅悬浮可见区域。

**视觉实施基线。** 参考自媒体工作台的编辑式布局，首屏聚焦一句输入和可见成果，采用大标题、较轻的分隔线、媒体优先的卡片和紧凑的动作组。深浅色接宿主能稳定提供的主题，若主题接口缺失则用 `prefers-color-scheme`。采用统一的 4/8/12/16/24/32 px 间距，主要页面标题 24–28 px，常规文字 14–16 px，辅助信息至少 12 px，常用点击区约 40 px。强调色只给当前主操作、焦点和已选对象，成功、警告、失败用图标与文字。页面、卡片和弹层分三层背景。主操作放在页头或当前步骤底部，审批层的取消和确认位置固定。素材卡按原比例提供海报槽，文字草案使用等高骨架，用户可区分「还没开始」「正在做」「可以看」「需要处理」。

### 4.4 关键行为与新手文案

- 头部的主操作由已确认状态派生。优先级为当前对象缺必要输入 → 当前阶段需要确认或审核 → 可执行下一步。全局任务异常或历史审批走任务中心。界面只强调一个主操作，其他常用操作做次级按钮。操作被禁用时写出具体原因，并提供可补齐的入口。
- 点击「和导演改这一镜」附带镜头 ID、版本和可移除引用，聚焦输入框。聊天顶部常驻「整个项目」或「镜头 02」，发送前即可更换。新对话保留工程、已确认简报和所选对象，消息历史从空开始。列表支持选择旧会话、显示更新时间和标题，旧消息分页加载保留阅读位置。草稿和待发送引用按作用域保存。
- 流式文字增量不重建成果区。进入任务后对话显示一个任务卡，状态直接读任务记录。正在读旧消息时只提示「有新消息」，用户主动回底部才跟随。中文输入法合成时 Enter 继续选词，合成完成 Enter 发送、Shift+Enter 换行。发送失败保留内容与相同请求 ID。
- Agent 先答用户问的事，常见引导为 1–3 句和一个按钮。「什么是转写」→「把视频里说的话变成文字。有了文字，我能帮你找到重复和重点。」按钮「导入字幕」或已验证的「识别视频里的话」。缺少识别能力时另给「按时间选片段」。「开始剪吧」结合当前项目只给一个下一步，多对象才问一次。「你好」正常回复，可在无模型时由内置引导完成。
- 统一词表采用「制作步骤」「镜头开始的图」「镜头结束的图」「已选版本」「制作方法」「交给剪映」「需要你检查」。设置中可出现模型 ID 和 API Key。普通卡片不展示 revision、JSON、原始错误、供应商任务号。对话中出现这些技术字段时过滤诊断字段，保留正常用户内容。错误展示阶段、已完成的部分和下一步。例如「第 3 镜已提交，暂时查不到进度。继续查询」。
- 表单保存状态区分未保存、保存中、已保存和冲突。依靠明确按钮或已说明的低风险自动保存。切走时不丢输入。标题等写入成功后显示可撤销回执。改已确认编排、首尾图和已采用版本时先展示新草案并确认。
- 键盘覆盖主导航、选卡、排序、对话、审批与播放。弹层锁定焦点，关闭回触发控件或可见标题。状态用文本和图标，焦点边界可见，动态更新用礼貌播报。禁止仅靠颜色辨认候选和当前版本。审批按钮在弹层焦点序列清楚可达。

### 4.5 动效实现与验收

把动效 token 固定在页面基础样式中。下面时长是 V3 执行基线，可在实机试用后统一调整。用 CSS 或 WAAPI，优先 transform 和 opacity。保留滚动锚点和稳定骨架，动画结束不触发业务写入。

| 场景 | 动效和时机 | 退出、回退和减少动态 |
| --- | --- | --- |
| 卡片出现与保存 | 首次进入卡流 140–180 ms 轻抬和渐显，最多给首屏前 6 张 20 ms 错峰。新灵感写入成功后只突出新卡一次 | 刷新、分页和筛选无需重复播放旧卡。减少动态时直接插入并播报「已保存」 |
| 从卡到工作区 | 记录点击卡片边界，用共享位置展开 260–320 ms，参考上游柔和弹簧；无可见锚点时用 140 ms 淡入 | 返回时锚点仍在就逆向收回并恢复滚动。深链接、窗口缩放或锚点消失时切为淡入或直接显示 |
| 成果格放大 | 从格子原位展开至主区域，200–260 ms。保留对应标题、关闭按钮和逻辑顺序。仅一个格子展开 | 关闭收回同一格。预览嵌套时先退预览。快速重复点、切路由或缩放时取消旧动画，界面直接落在当前状态 |
| 对话、抽屉和窄屏切换 | 抽屉 180–220 ms 位移与淡入。点击镜头引用滚到对象并轻描边，定位后聚焦 | 对话输入与历史位置保存。减少动态用瞬时定位。自动滚动只发生在用户已接近底部或主动定位时 |
| 产物回填 | 缩略图区预留比例。由真实事件把占位变成校验通过的媒体，140–180 ms 交叉淡入。失败在本格显示原因 | 其余卡片不移动、选中和焦点不变。并行结果按事件各自更新，关闭页再打开直接用快照 |
| 预览和确认 | 预览 150–200 ms 小幅缩放与淡入，确认层 120–160 ms 淡入，关闭同源控件复焦 | 不依赖过渡结束来切状态。减少动态下跳过动效。视频开始播放须用户意图或浏览器可用性允许 |
| 进度与回执 | 状态文本和图标即时更新，按钮提交态和回执可用轻微淡入 | 远端无百分比用静态状态或不定进度；不造假进度。回执停留在历史中，短提示消失不丢恢复入口 |

CSS 使用 `prefers-reduced-motion`，JS 监听变化并取消正在运行的动画。深链接、重开窗口、失焦、连点和 resize 时不能遗留遮罩或焦点锁。实机录屏验收对照上游动作，检查 1440、1024、768 px 嵌套容器，200% 文本缩放、键盘、减少动态、慢网、并发回填和播放返回。截图覆盖空、等待、失败和已完成四类状态。

## 5. 两条工作流的实现细则

### 5.1 路径 A · 现有素材编排

1. 从 `/projects` 创建已有素材项目。批量导入各文件时独立探测和提交，验证文件签名、体积、时长、尺寸、旋转和音轨。视频缩略图和必要预览代理由本机工具生成。区分可验证的源文件与预览代理，交接使用已选源素材。重复文件可共享物理文件，保留每次导入和选用引用。磁盘配额不足时显示所需空间及下一步。
2. SRT 导入提供编码识别、错误行与偏移预览。区分「字幕文件用于已编排成片」和「字幕对应一段原素材」。后者明确绑定素材，剪切区间后做交集、偏移和单轨重排。顺序变化重新生成对应版本，不能覆盖源 SRT。无法可靠配对时让用户选素材或只保留原文件。
3. 编排卡支持同一素材多区间、必用项、拖放和键盘排序，检查重叠、边界、可解码性与合计时长。建立 `ArrangementVersion` 后显示每镜区间、预计时长和来源。超过已验证范围提示缩短、拆分或导出素材包。输入原片允许长于交付范围。不能直接沿用旧 writer 对同一 segment ID 只允许出现一次的假设。
4. 「保留重点剪成 30 秒」先读取转写或已验证的外部粗剪能力。每个建议记录素材、证据区间、保留原因，优先保留数字、否定、前提、承诺和用户指定内容。模型建议的区间由程序验证。内容证据不足时给导入字幕、连接识别或按时间选片段。已有可用内容时给有证据的编排建议，确认后才采用。卡点等扩展按 M3 单独开放。
5. 采用编排后，在「交付」构造冻结快照，包含版本、选用候选、绝对时长、字幕和素材哈希。播放源和候选时可切到不同镜头，成片效果以剪映实际预览为准。预检后走 §8.4。验证首次交接、另存第二稿、成片导回，验证 25 分钟附近实机样片后才显示该支持范围。

### 5.2 路径 B · 创意、试拍和补镜头

| 阶段 | 写入与确认 | 就绪条件及错误退路 |
| --- | --- | --- |
| 立项 | 用户一句话起步，确认影响最大的用途、画幅、时长或必须保留项；其余可用默认 | 可以先保存未完简报。参考标记与媒体使用、外传许可分开 |
| 故事与分镜 | 记录画面、动作、时长、衔接意图、用到的角色、道具和场景版本。支持手工编辑和部分采用 | 检查总时长、镜头数量、前后连贯与缺素材项。能从某镜继续，改镜头不覆盖其他确认 |
| 视觉设定和首尾图 | 先给可比较设定图，再按镜头创建开始/结束图候选和提示词版本 | 尺寸、比例、解码验证。视觉工具实际收到帧才能记录图像审核。缺视觉则「需要你检查」；可手动导入替换 |
| 试拍 | 从冲突最大、最能代表画风或衔接风险高的镜头选一个。审批绑定指定素材、提示词和生成费用信息 | 下载并验证后并排查看输入图与视频。确认选用、重拍或改输入后重拍 |
| 批量生成 | 选未完成镜头并冻结快照。每镜独立任务与费用记录，审批明确数量和总范围 | 单镜失败保留其余成功。下载或核对不触发新付费提交。待处理镜头可以换实拍或外部片段 |
| 审核与交付 | 程序验证与独立审核记录并存。用户比较、标注时间点并选用。按路径 A 同一交接 | 审核信息显示「已验证可播放」「需人工检查」「已选用」三个独立概念。切换输入后有影响提示及重新确认 |

两条流程共享 `Asset`、`Shot`、`Candidate` 和 `ArrangementVersion`。工作流状态基于所需输入、确认和产物计算。切换到已有素材不会丢掉 AI 候选。可跳过已用实拍补齐的生成步骤。批量操作仅针对明确选中的镜头 ID 和输入版本。

### 5.3 灵感、公开链接与参考来源

- 本地搜索可先用标题、正文、标签的归一化词匹配，中文加入连续字词片段。相关性排序固定，同分按时间与 ID，默认最多三条。用户明确操作才引用或合并。保存和搜索无需联网。
- 公开链接原地址、抓取内容和用户备注分开记录。只有「读取这个链接」或「查找参考」显式启动工具。HTTP(S) 公开抓取限制域名解析和所有跳转，拒绝环回、私网、链路本地、云元数据与凭据 URL，限制数量、体积和超时，禁止运行页面脚本。网页内容带来源、日期和摘录，保留用户原文。
- M1 支持快速记录、读取单条公开来源和手工引用。M3 的「找参考」工具可搜索、筛选并汇总带来源的条目；参考视频分析先走授权与媒体检查，输出可用的画面节奏、镜头结构、配乐/动作意图或证据时间点。内容无访问权限时提示用户上传合法文件或改用公开材料。参考图与视频默认「只做参考」，作为生成输入或成片素材需独立选择。
- 资料正文、字幕、外部生成器文本和导入 Skill 均不提供权限。向模型发摘要、参考帧或转写前列出拟发送的资料。外部模型接到的私有文本、图片、视频和附件按 §7 授权。查询词也禁止自动拼入密钥、项目私有路径和未同意的素材正文。

## 6. CUTDIRECTOR Agent、上下文和路由

### 6.1 模型与 Loop 职责

```text
发消息 → 确定作用域与对象 → 判断咨询／建议／明确改动／执行
      → 读取当前阶段和候选能力 → 组装最少上下文 → 调用已选模型
      → 文字 / 可编辑建议 / 受校验的本地命令 / 待审批计划
      → 执行和验证 → 保存回执与事件 → 回到消息和下一步
```

- `Run` 固定当前 profile、scope、conversationId、messageId、focus、目标版本、模型与执行策略版本。按阶段重读工程和证据，审批或提交前重核对。用户关闭对话或切项目不会把旧任务转移到新对象。编辑目标如「从 45 秒改 60 秒」只改时长字段，保留其余已确认要求。
- 组装顺序是用户明确限制和授权 → 当前对象与已确认简报 → 已选输入与依赖状态 → 最近相关决定/消息摘要 → 匹配 Skill 和片段证据。控制 token、工具数、最大步数、时间和外部成本。超出时保留高优先级信息并提供补充或人工选择。只读取与任务有关的转写、图片或参考，不把全项目历史、路径、密钥和他项资料发给模型。
- 已确认的项目决定、手工改动、撤销和失败可记录为案例。案例供回看与评测。只有用户点击「下次也用」并确认范围，才生成跨项目偏好；默认是本项目。偏好带证据与生效范围，可编辑、撤销和停用，当次指令优先。新对话可读取项目决定和有效偏好。改善效果用固定样片同模型做基础规则、专项 Skill 和批准偏好对照，记录保留率、时长误差、人工返工、越权次数和工具量。
- M1/M2 用主 Agent 和隔离审核任务。审核上下文包含有限产物、检查规则和证据。审核执行者没有工程写权限、支付批准权或长期偏好批准权。DSH 原生 Agent、Codex、后续 Claude Code 只在显式选择的角色上执行受控能力，必须验证隔离和结果。M3 可给工作流增加监督和代理角色，监督输出风险提醒，代理在用户设定范围内选低风险分支；审批权限仍归用户。

### 6.2 输出协议与降级

| 模型结果或意图 | 运行时处理 |
| --- | --- |
| `reply` 或正常纯文字 | 作为用户可读回答。普通提问、问候、术语解释不要求 JSON。模型说「已改」仍需真实回执 |
| `proposal` | 校验对象、内容和证据，保存草案或显示建议卡。采用前不切换已确认版本 |
| `command` | 校验动作白名单、对象、版本、字段范围和权限。仅明确请求的可逆本地改动自动执行，生成真实回执 |
| `taskPlan` | 校验能力和资源，创建计划与预检；需要上传、费用或外部写入时生成独立审批 |
| 输出带坏 JSON、超时或没有有效动作 | 对用户要求的具体动作可有限重试一次结构化请求。纯文字作为回答时不报格式错。不能执行时指出尚未执行及可以点的下一步。避免输出原始协议 |
| 断开模型或未配置 | 问候、记录灵感、浏览、排序、预览、剪映预检、手动导入与工具直接操作保留。依阶段提示「连接文字助手」或可用本地动作 |

所有请求从单个明确的对象开始。当前没有明确对象、动作有冲突或用户只说「开始」时，只问影响最大的一个问题，或给出对应按钮。切换模型或工具只作用于新任务；对已经提交的任务保持原服务引用。任何来自模型或子 Agent 的动作都走工程命令层，模型输出不能构造内部 URL、磁盘路径、终端命令或审批凭证。

### 6.3 Skill 选择与执行者

路由在后端执行，先识别阶段、输入类型和角色，再过滤禁用项、缺工具、缺权限、不支持的模型及版本。优先级 **用户本次显式选择 → 项目默认 → 内置默认**。多个等价项先给推荐并可选择。只加载命中的 Skill 正文和必要参考。替换执行器重新计算权限、费用、外传范围和审批，已有任务绑定旧版本。保存 `RouteReceipt` 并在任务详情用「为什么选这个工具」展示。

| 请求 | 执行者与传入信息 | 结果校验 |
| --- | --- | --- |
| 从灵感列三镜 | CUTDIRECTOR 规划角色，当前灵感/简报 + 分镜方法 | 生成可部分采用的分镜候选，保留原文 |
| 做第 2 镜的开始图和结束图 | 已验证 Codex 或图像 API，指定镜头和经批准参考 | 实际两张合规图片与镜头和输入版本绑定 |
| 查角色是否一致 | 实际收到图像的审核模型，选定输入和输出截图 | 带证据与疑点。无视觉能力时不派发，提示人工看 |
| 按指定图生成视频 | Seedance 等视频适配器只收到验证过的结构化参数和授权媒体 | 远端任务 ID、合法视频、实际时长和候选关联 |
| 找重复口播并交给剪映 | 粗剪执行者收转写与方法；剪映适配器只收已选用交接清单 | 证据与区间校验。没有转写走替代路线，原生草稿以实机验证 |

## 7. 后台任务、审批与恢复

### 7.1 状态机与调度

| 内部状态 | 用户状态和允许动作 |
| --- | --- |
| `needs_input` / `awaiting_approval` | 「缺少素材」补文件或换输入。「等待你确认」可批准、拒绝或修改 |
| `queued` / `dispatching` | 「排队中」「正在提交」。记录尝试和稳定调用号。取消排队立即撤销，正在提交时先判断外部是否已收到 |
| `submitted` / `running` | 「已提交，等待生成／正在生成」。持久外部 ID，查询和取消按实际支持 |
| `collecting` / `validating` | 「正在取回」「检查文件」。记录下载尝试和本地临时路径，允许重试回收 |
| `succeeded` | 「可预览／草稿已创建」，入库后才发布。审核或人工实机确认另存 |
| `failed` / `unknown` / `stopped` | 「这一步没完成」「状态待核对」「已停止后续步骤」。按错误给查询、补输入、重试回收、重新计划。远端停止需明确确认 |

- 一个计划可派发多镜头子任务，父任务汇总成功、失败和未提交数量。每镜独立持久化。按工具设置并发上限、队列容量、超时与退避；默认同一项目一个相同素材的外部草稿写入，同一任务只有一个有效租约。处理 429、网络重连和连接过期，避免多次轮询打满工具。
- 事务完成检查和占用授权、保存冻结快照、创建尝试、记录派发意图。外部调用后持久化外部 ID 和返回摘要。进入回收先写临时文件，检查文件和哈希，再登记候选与事件。服务重启先恢复未完成任务的当前环节。过期租约可以接回，但未知派发状态需要核对。
- 有外部幂等键时使用同一个稳定调用号，按厂商文档查原任务。没有幂等保证或响应丢失时进入 `unknown`，使用已验证的任务列表或账户界面核对。确认同一任务后保存 ID，证据不足保持未知。用户明确选择新提交时展示可能重复收费，建立新计划和批准。永不自动重发收费 POST。下载和校验重试不会创建生成任务。
- 退出 DSH 前记录当前阶段。外部 ID 已知的任务重新打开后继续查询原任务。账户暂时失效时显示更新原连接后续查。更换账号若不能查询旧任务，保持原外部记录。取消停止本地后续，并按支持情况请求远端取消。仅当远端确认取消时显示远端已停止。取消过程中收到结果可保留为未选候选，按适配器回收策略显示。
- 剪映写入有同样的派发记录与 Handoff ID。程序重启后通过自有 staging、目标标记和可验证记录核对，无法确认时提示检查目标文件夹。禁止覆盖或删除来源不明的草稿。

### 7.2 权限、费用和审计

- 预检生成规范化快照与输入指纹。审批覆盖项目和镜头、输入版本和文件、上传对象/用途/目标服务、数量/时长、费用及来源、草稿位置和写入方式。应用同一 scope 及会话身份。审批采用一次性记录，短期有效。修改输入、服务、模型、费用上限或目录使审批失效。重复点击或并发审批返回同一任务。
- DSH 文本默认模型的用途、发往厂商的数据类型和连接身份在首次连接时说明。默认仅用必要文本；当前项目的私有媒体、字幕或参考资料确需发送时，按本次范围授权。读取、写项目、外传、付费、写剪映和读取私有资料独立受控。任务可以同时需要多个批准项。审批页禁止将整个工程默认勾选。
- 账目记录估价、币种、来源、更新时间、批准数量、已用次数及能获取的实际费用。未知价格须显示「由该服务计费」及生成量，用户明确确认后才执行。试拍和重拍各自计量。配置可设置项目预算或数量上限，达到上限停在待处理。
- 适配器执行使用固定程序、参数数组、受限工作目录、允许的输入副本与最小环境变量。需验证执行者有效的工作区隔离与网络边界，不能只依赖提示词。外部文件按路径归属、类型、大小、解码和摘要验证。诊断按事件 ID 定位，日志脱敏，脱敏导出限用户选定范围。

## 8. 连接、工具适配和产物验证

### 8.1 图形化连接向导

1. 用户从当前动作或「设置 → 连接」进入。保存 `returnTo`、未发送输入、选择的镜头和版本。先展示用途和已可用方案。如果只有一个已就绪方案且用户已设默认，直接回当前步骤。
2. 「文字助手」优先列当前 DSH profile 的已有模型，只展示名称、提供方和可用能力。未设置时引导到 DSH 的模型设置，返回后刷新目录并测试。允许按项目设默认。模型切换不影响已有任务，候选下拉不列不支持当前用途的模型。DSH 凭据由 DSH 持有。
3. 「做图」列 Codex、已连接图像服务和「我已有图片」。「做视频」列方舟等已验证适配器与「导入我已有的视频」。「交给剪映」先检测安装版本和草稿目录，检测不了就选择位置，再做一次安全检查。按可用性显示原因和推荐下一步。
4. 插件直接连接的服务提供厂商卡、官方取钥链接、粘贴区和「检查连接」。内置服务预填地址及已知配置，自定义接口归「更多设置」，必要时允许手动填模型 ID。保留未提交的非敏感配置，密钥在页面关闭后清空。服务地址变更重新确认，禁止用用户密钥向原授权外的域名转发。
5. 连接状态至少有「未连接」「账号已连通」「当前模型可用」「已完成真实测试」「不支持这项能力」「需更新连接」。测试按实际能验证的层级逐步升级。免费验证优先，生成测试前展示生成量及可能费用。密钥无效、目录空、超时、模型移除、能力不足和配额不足分别提示。
6. 测试通过后即时刷新工具选择，提供「设为这个项目的默认」或直接回原步骤。返回时复核项目、对象和版本。已补齐的连接不会自动上传或收费。更新或移除凭据前提示受影响的任务，已提交任务保留可核对的原记录。
7. 插件密钥用 Windows 当前用户保护，例如经 M0 验证的 DPAPI CurrentUser，持久化引用放在当前 profile。禁止 Key 明文进入库、缓存、配置、进程参数、导出、对话、遥测或日志。前端仅在录入及发送期间持有，读接口只回是否已配置。日志记录脱敏主机和测试阶段。使用自定义接口时校验端点协议与地址，默认 HTTPS；本机免密服务可经显式配置到精确环回地址和端口。测试 DSH 隔离 profile 无法读到其他 profile 的 Key、任务或资产。

### 8.2 Codex 和图像服务

- M0 通过目标 DSH 版本已安装的 Codex 子 Agent 或受控运行器验证出图。测试能力包括启动隔离执行、最小读写权限、返回可读取的图片文件、关联镜头、取消与超时。不把文字「已经生成」算作结果。
- 每次任务创建独立工作区。只复制批准的参考图片和必要说明，给明确输出目录和文件类型。验证路径在工作区内且不经符号链接或重解析点逃逸。校验图像真实可解码、宽高和比例，再去重入库。多张输出逐一关联开始/结束图，缺一张只重试该图。记录生成器、提示词、方法版本和检查结果。
- 图像 API 适配器声明文本出图、参考图或编辑能力。至少实测一个已支持的备用 API；仅支持文字出图时不能作为参考图编辑能力。导入自己的图片无需账号，仍走同一校验和候选流程。选择备选时告知上传范围和计费情况，并按计划重新审批。
- 独立视觉审核把已批准的原图、候选帧和检查清单交给实测可看图的模型，记录实际输入媒体数、时间点及输出。文件的编码/分辨率由程序检查。角色、道具、画面衔接和片段质量保留人工判断入口。

### 8.3 Seedance 适配器

- 对照当前官方 API 锁定接入契约。连接记录持有访问端点和模型版本，输入能力单独标注参考图、首尾帧、时长、比例、分辨率及配额。参数校验在审批前进行，审批后重新校验，不假定所有 Seedance 模型支持同样输入。 [火山方舟创建任务](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh) · [查询任务](https://docs.volcengine.com/docs/ark/list-video-generation-tasks-api?lang=zh)
- `submit` 输入固定快照，输出外部任务 ID 或未知状态。`poll` 按官方状态映射，未提供百分比时只更新文字状态。`cancel` 在该类型实测支持时开放。`collect` 用原任务获取结果，限时下载到暂存后用 FFprobe 与解码验证。限制响应和下载的域名、重定向、MIME、大小和超时。URL 过期则查询原任务刷新，不自动再次生成。
- API 需要远程引用时使用已验证的上传方式和用户授权的临时可读引用。记录上传目的、文件、过期策略与任务关系。账号凭据、内部 URL 和本机路径不得外发。保留远端失败原因脱敏摘要。验证真实短片、部分失败、下载过期、关闭 DSH 后继续查询、取消受限和不重复付费。

### 8.4 Easy 剪映和备选适配器

1. 在支持矩阵中记录剪映精确版本、Windows 版本、适配器提交、运行依赖、素材组合、路径约束、通过或失败日期。先使用 Easy 剪映的 `jyr` 计划和经确认的 Windows 最小适配，再对比 capcut-cli。重点核对上游应用发现、草稿根、登记方式和字段单位，避免把 macOS 假设当成 Windows 支持。 [Easy 剪映](https://github.com/YeJe-cpu/easy-jianying) · [计划格式](https://github.com/YeJe-cpu/easy-jianying/blob/main/docs/plan-format.md) · [capcut-cli](https://github.com/renezander030/capcut-cli)
2. 统一 `HandoffSpec` 包含 Handoff ID、项目/编排快照、候选素材与区间、输出比例/时长、单轨字幕、各文件哈希、剪映版本、目标位置和可用权限。适配器做单位与类型转换，保留对照清单。模型仅生成建议，不写剪映数据。
3. 预检检查剪映安装版本、目标写权限、路径空间、名称冲突、所有文件可达、编排与字幕时序。用稳定交接名，拒绝目录穿越和已存在文件。显示新草稿名称与位置，用户确认后执行。
4. 在同卷自有暂存目录创建新草稿，先检查清单、结构、媒体路径、片段/字幕数量和时间戳。再以已通过实测的方式登记；安全落盘失败时保留可诊断暂存，支持只重试未完成阶段。交接时保证素材引用可持续读取，不能指向即将清理的临时文件。
5. 返回草稿 ID、打开剪映或打开位置的能力及说明。若无已验证直接打开方式，给「在剪映首页找到这个草稿」和复制名称。区分 `draft_created`、`editable_verified` 和 `final_archived`，程序校验不能自行提升为实机可编辑。实机验证打开、移动片段、改字幕、保存并导出。再次交接另建草稿，验证原稿的手工修改仍在。
6. 兼容性未知、权限缺失或两个适配器都失败时，提供素材交接包。包里按排序命名，包含合法媒体、字幕、顺序、入出点和来源清单。需要导出已裁区间时调用经验证的媒体处理工具生成交接副本并记录来源。明确显示素材包，保留原生草稿未通过的状态。
7. 「导回成片」使用同一导入流程校验 MP4，关联交接，保留多个版本并可指定主版本。V3 首发只回收成片和必要备注。剪映时间线回读、加密草稿和不同平台必须分别实测后再登记能力。

## 9. 制作方法的导入、导出和调用

- 接受标准 `SKILL.md` 目录或 ZIP。M2 通过文件选择/目录或压缩包完成导入，目录选择由实际 DSH iframe 能力验证。先只预览元数据与文件清单。服务端校验 UTF-8、frontmatter 的 `name` 和 `description`、许可和声明，YAML 禁用危险类型和不必要的别名扩展。只解析白名单文本参考和可审核的安全静态资源。上游 `allowed-tools` 声明仅作为信息。
- ZIP 实施基线为压缩体积 ≤10 MiB、解压 ≤50 MiB、最多 256 文件、单个参考文本 ≤1 MiB，限制压缩比、递归层级和耗时。逐条拒绝绝对路径、`..`、盘符/UNC、Windows ADS、设备名、大小写冲突、重解析点、符号链接和嵌套包。检查实际写入路径。脚本、二进制及未认可文件不安装、不运行，预览显示忽略的条目。需要程序功能时用户从可信 DSH 插件接入。
- 可选清单 `cutdirector.skill.json` 用版本化 JSON Schema 验证，字段至少有 `schemaVersion, skillId, version, stages, roles, capabilities, inputKinds, outputKinds, scopes, requestedPermissions, suggestedExecutor, references`。清单缺失时以「仅供建议」导入，允许界面关联已安装能力。清单和 Skill 正文只能描述做法，无权自动开启工具或增大发送范围。
- 导入预览显示用途、来源、许可、权限建议、依赖、文件列表、重复/升级提示和默认模式。确认后按内容哈希登记。名称相同、内容或来源不同的包可另存或升级；保留旧版本，运行任务不换版本。允许设为项目偏好、限制范围、停用、回退和查看近期调用。
- 导出先列文件，可取消。包含标准说明、允许分享的参考、可选清单和许可证；排除凭据、工程媒体、聊天记录、项目与任务标识、本机路径、日志、临时文件及运行脚本。文本导出检查明显密钥和私人路径，提示用户查看预览。隔离 profile 往返校验哈希与版本。停用或移除制作方法时保留已有产物和历史证据。
- DSH 自带 Skill 经已验证发现接口读入元数据，再映射到 CUTDIRECTOR 注册表。默认不把导入方法作为全局可执行 Skill 注入 DSH。正文按 §6.3 惰性加载。路由匹配、执行权限与真实工具就绪分别检查。

## 10. M3 扩展实现

### 10.1 插件清单与适配器 SDK

- 清单包含 `schemaVersion, pluginId, version, hostRange, platform, capabilities, entryType, inputSchema, outputSchema, permissions, cost, readiness, resume, cancel`，并提供来源、许可、最小示例和正常/失败样例。版本固定，输入输出严格验证，未知能力与未知扩展字段不会获得权限。
- 统一执行接口 `probe(context)`、`prepare(snapshot)`、`execute(approvedInput)`、`validate(artifacts)`。可选 `poll(externalId)`、`cancel(externalId)`、`collect(externalId)`。三种接入分别为本机受控 CLI、允许的服务 API、DSH 已安装工具/子 Agent。Agent 调用能力 ID，不选择任意命令或 URL。
- 安装通过 DSH 官方支持入口。注册、启用、替换、升级和移除在工具中心显示权限与成本，未通过 probe 的能力不会被默认选中。停用后新任务不得调用，排队任务提示替代，已提交任务按可恢复接口或人工核对处理，已归档产物保留。升级和回退重测默认工作流。
- M3 至少交付一个实测新增执行器（优先 Claude Code，证实后开放）、粗剪与卡点适配路径、参考视频分析和公开参考搜索。生成器、模型或剪辑工具可替换；用同一制作工程验证替换，禁止静默降级到范围或价格不同的工具。

### 10.2 制作模板与节点画布

- 模板保存版本化步骤、能力依赖、参数默认值、端口类型、许可证和示例。导入预览检查缺能力、缺输入、数据范围和付费步骤。复用模板创建新工程，使用者重新绑定本机素材和账户。模板包不携带凭据与私有项目数据。外部公开示例保留许可和下载确认。
- 画布从已有 `WorkflowVersion` 与依赖图投影。节点为简报、参考、素材、分镜、生成、审核、选用、交接。连线需通过输入输出类型、循环检测、引用权限和固定版本检查。允许折叠节点组和缩放适配，窄窗口提供等价步骤列表。点击节点跳到对象或任务，使用 §4 的定位、预览和焦点规则。
- 保存连线后展示受影响的镜头或步骤；旧产物仍可用和比较。支持只复查或重跑受影响节点。画布运行复用任务、审批和回执，每个付费或外部写入节点遵守同一门禁。验证模板导出重导、缺依赖、错误类型、环路、撤销、单节点失败和重新接续。

## 11. 打包、升级和回退

### 11.1 迁移顺序

1. 在隔离 profile 安装 V3 包。将现有工作区路径、DSH 版本、插件包、旧 writer 进程及端口、旧工程、会话、设置、媒体和已有草稿列入迁移清单。运行校验并记录 `release-manifest.json` 文件哈希。先从备份副本测试旧项目、导入和回退。
2. 正式升级前让在跑的旧渲染完成或获得明确停机安排。退出 DSH，识别旧 writer 的可执行文件、数据根和启动来源，关闭确认归属 CUTDIRECTOR 的进程。备份 DSH profile 的插件配置和链接、旧数据根（如 `.m1-data`）、旧会话、旧发布包及快捷方式。凭据按受保护形式备份。记录时间、散列、恢复步骤和可用空间。
3. 切换当前 profile 的 `@local/video-agent` 插件路径与实际链接。V3 数据进入新命名空间。旧工程继续使用原 schema，在兼容页读写。第一次派生 V3 制作工程生成 migration receipt，保存旧项目 ID、revision、媒体哈希、源会话/交付引用和跳过项。重复派生请求返回原结果，用户主动另建项目时用新请求。旧模型密钥不自动复制到插件或导出，用 DSH 模型选择或按新向导连接。
4. 先启动 DSH 实测侧栏、灵感保存、已有工程访问、模型目录、预览和恢复，再退役已确认的旧独立启动项、已知桌面快捷方式和旧浏览器启动页。只处理属于 CUTDIRECTOR 的明确目标，已备份的旧发布包保留。V3 插件不生成新的独立启动器、独立服务或桌面快捷方式。验证旧地址不能打开独立 UI，退出 DSH 后内部前端和私有服务都不可访问。
5. 回退时关闭 V3 Host 与其进程，留存完整 V3 数据和媒体，恢复旧插件路径和兼容服务在 DSH 里的访问。旧发布包如需 writer，限制给旧 DSH 插件使用并确认独立启动仍停用。若旧包本身无法隔离独立入口，使用经过测试的回退包或保留 V3 中的旧工程兼容页。核验旧数据、修订和交付，避免旧服务写入 V3 数据库。保留 V3 成果用于恢复升级。

### 11.2 构建产物与检查

- 基于现有 `tools/package-plugin.cjs`、`tools/package-release.cjs` 改出 DSH V3 构建。脚本可按仓库规范确定参数，文档记录可复现的构建、校验和安装命令。清单覆盖 Host、Client、构建后 Web 静态资源、schema 迁移、运行时、适配器、许可证、默认 Skill 和不含真实账号的示例。
- V3 校验检测资源路径、入口、许可证、版本握手、缺文件和篡改。拒绝把 `Launcher.cs` 编译的独立启动器、打开浏览器脚本、快捷方式生成器、开发临时文件、真实项目、凭据和固定旧端口配置装入 V3 用户包。Node、FFmpeg 等纯内部运行依赖按需要保留。
- 记录安装 Windows、DSH、剪映、各工具版本和范围。测试干净 Windows 用户仅装目标 DSH 和已声明的剪映/必要账号时，侧栏即可打开。普通操作不需要预装 Node、运行脚本或手工编辑配置文件。

### 12.2 测试分层与必测故障

- **单测与契约**。数据版本、同请求幂等、字幕/时间对齐、对象切换、依赖图、撤销冲突、审批散列、权限分离、Skill/插件 schema、适配器结果校验、模型正常文字和结构化异常。
- **集成与故障注入**。跨 profile 读写、恶意 origin、伪造内部请求、路径穿越、重解析点、压缩炸弹、SSRF、上传断线、磁盘不足、进程崩溃、并发审批、模型移除、Key 无效、工具目录空、未知剪映版本、草稿目录冲突。对远端超时、429、响应丢失、重启、下载过期、部分成功和取消受限检查恢复。
- **DSH 端到端**。在同一 profile 从灵感或已有素材进入、选对象、换会话、预览返回、改稿、连接、确认、交付。退出 DSH 后用相同侧栏续查；异常关闭再打开。验证原生 DSH 对话没有被悄悄创建、工作台没有独立入口。不同 profile 之间仅允许用户显式导出和导入公共方法。旧 M0–M4/V2 回归以保留的旧工程行为为边界，替换涉及独立入口的测试。
- **真实验收**。覆盖短口播、多区间、导入并改字幕、接近 25 分钟的素材编排、真实 Codex 产图、真实 Seedance 短片、实拍加生成混合、换某镜上一版、第二次草稿另存、剪映精修导出和 MP4 归档。逐项保存日志摘要、测试输入引用、截图/录屏和产物校验。真实证据去除密钥与用户私人素材。
- **可用性**。至少 5 位很少使用 AI 剪辑或生成视频的用户，在无终端和口头协助下，保存灵感、转项目、导入素材、找到下一步、播放返回、完成草稿交接，至少 4 位完成。另测连接向导、外传和付费确认。记录找不到步骤、术语误读和需要协助的次数。
- **效率对照**。同一素材与目标比较手工跨工具流程，记录复制粘贴次数、首次草稿耗时、单镜修改耗时和操作步数、失败恢复耗时、重复收费次数。用户仍可在每个阶段发现已生成产物和下一步。
