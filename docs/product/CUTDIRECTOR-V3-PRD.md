## 1. 产品目标和边界

### 1.1 用户要解决的问题

创作者可以用 Claude Code、Codex 和 Seedance 做出一条视频，也可以用 Easy 剪映生成可编辑的剪映草稿。实际制作时，一个工程仍然需要持续保存分镜、提示词、角色设定、参考图、候选镜头、审批和草稿。用户改动一个镜头之后，还需要知道哪个版本已选中、它影响了谁、哪里可以继续。创作者是否只和一个 Agent 聊天，与这条生产链路是否可靠是两件事。 [Eian 的完整工作流](https://xarticles.io/articles/claude-code-codex-seedance-ai) · [Easy 剪映](https://github.com/YeJe-cpu/easy-jianying)

CUTDIRECTOR 提供一个能持续工作的工程。用户在工作台确认制作方向、审核关键产物、批准付费和选用镜头。原生 Agent 负责理解、解释、规划和调用。各工具完成出图、视频生成和剪辑，任务和产物回到工程，最后在剪映里继续编辑和导出。用户更换某个工具后，已有素材和决定仍能继续使用。

**产品一句话**  
在一个工程里，把一个想法、一批已有素材，或两者的组合，推进到一份能在剪映里继续编辑的草稿。

### 1.2 三类首发场景

| 用户 | 典型诉求 | 首发交付 |
| --- | --- | --- |
| 有现成素材，平时不熟悉剪辑 | 「把手机里这几段按事件顺序排好，加上已有字幕，给我一个剪映草稿。」 | 素材检查、顺序和时长建议、可调整的编排及剪映草稿 |
| 有创意，愿意用 AI 做一条短片 | 「做一条 20 秒的手绘短片，先让我看看画风。」 | 创作简报、分镜、参考图、首尾帧、生成镜头、剪映草稿 |
| 实拍和生成混用 | 「保留我的实拍开场，缺的镜头用 AI 补，结尾用已有素材。」 | 同一张分镜板上的多来源素材、候选与选用记录、剪映草稿 |

生成验收使用 **15–30 秒、3–5 个镜头**，以验证完整链路与重拍成本。已有素材路径的交付计划继续按 **25 分钟以内**设计，输入素材可以更长。只在近上限样片通过实际交接后，公开该能力范围。首版涵盖顺序编排、素材区间、单条基础字幕及可编辑草稿交接。复杂多机位、专业调色、复杂特效、多人云协作、社媒排期和自动发布留给后续能力。

### 1.3 产品职责和复用边界

| CUTDIRECTOR 掌管 | 由接入工具执行 |
| --- | --- |
| 工程、素材归属、版本、工作流、会话、选用状态、审批、日志和恢复 | 文本和视觉模型执行创作推理与审核 |
| 连接工具、描述能力、校验输入、调度、回收和验证产物 | Codex 或其他图像工具生成、编辑首尾帧 |
| 把已有素材、生成镜头和字幕组织为统一交接清单 | Seedance 或其他视频服务生成镜头 |
| 检查交接条件、留存交接记录、回收最终成片 | Easy 剪映或备选适配器创建草稿，剪映负责精剪、调色、效果和最终导出 |

V3 唯一入口是 DSH Desktop 侧栏里的 CUTDIRECTOR。新发布包退役独立工作台、Windows 双击启动器、桌面快捷方式和可直接打开的独立网页。工程文件仍保存在本机，后台由插件启动和管理。原工程、会话、媒体和交付记录随升级保留，在 DSH 内的「旧项目」兼容页打开。用户可从旧工程创建制作项目，复用素材并保留来源。旧工程的时间线写入和回退走兼容页，V3 只使用制作工具。

## 2. 从输入到交付的闭环

### 2.0 灵感到项目

用户可以先记一句话、存一张图或贴一个链接，稍后才决定做什么。灵感卡保留原始内容、来源和附件，不要求预先填写项目名、画幅或模型。打开卡片后可选「继续想」「开始做视频」「加到已有项目」。开始制作时保留来源关系，并询问素材是「只做参考」还是「可以用在视频里」。多条灵感可以被同一个项目引用，同一条灵感也可以发展成多个方案。

从灵感到成片的路径为 **随手记 → 选一条开始做 → 整理想法和画面 → 补素材或生成镜头 → 选用结果 → 交给剪映 → 导回成片**。已有素材用户可以直接进入工作区，之后仍能把参考、想法或制作经验保存回灵感库。记录和浏览灵感在未连接模型时也能完成。

### 2.1 路径 A · 已有素材 → 剪映 → 成片归档

| 步骤 | 用户操作 | 系统行为和完成条件 |
| --- | --- | --- |
| 导入 | 选「我有素材」，拖入实拍、已生成的镜头和可选 SRT | 展示缩略图、时长、比例、音轨和可播放状态。列出损坏或找不到的文件，允许逐个重连 |
| 整理 | 拖动排序、指定必用素材或跟 Agent 说「产品特写放前面」 | 创建或更新镜头卡。建议卡展示顺序、选用区间、素材来源、字幕和预计总时长 |
| 确认 | 查看方案并调整，选「采用这个顺序」 | 保存编排版本。用户调整可撤回，原素材保持只读 |
| 检查交接 | 选择「生成剪映草稿」 | 检查素材、区间、字幕时序、时长、剪映版本和写入权限。展示目标位置及草稿名称 |
| 创建草稿 | 确认写入 | 先在暂存目录生成，再校验素材引用和草稿结构。按经验证的适配器方式登记新草稿，返回可定位的交接记录 |
| 精修与回收 | 在剪映打开草稿、修改和导出，回工作台选择最终 MP4 | 保留草稿交接编号、采用的素材与版本。用户可归档多个最终版本并指定主版本 |

编排完成后可以先播放素材和候选镜头。精确的最终效果以剪映实际播放和导出为准。首版的按内容粗剪仅在外部能力已验证且有可用转写时开放。缺少转写时，界面提供导入 SRT、手动指定区间，或调用已连接且实测可用的识别工具。按时间取片显示具体区间，避免用户把它当成按语义提取的结果。

### 2.2 路径 B · 创意 → 生成 → 剪映 → 成片归档

| 阶段 | 用户确认的产物 | 工作台要求 |
| --- | --- | --- |
| 立项 | 主题、受众、用途、画幅、时长和必须保留的内容 | 支持一句话开始。对影响后续的缺失项给出默认值或选项。可将参考片设为仅供分析 |
| 叙事与分镜 | 故事简报与镜头清单 | 每镜写清画面、动作、时长、转场意图和所需素材。检查总时长与前后连贯性，允许只改指定镜头 |
| 视觉设定 | 角色、道具、场景、色彩和光线 | 设定图可被多镜共享。视觉方向可比较和确认。确认后按版本引用 |
| 首尾帧 | 每镜的首帧、尾帧和提示词 | 优先验证 Codex 出图，提供已配置图像 API 与手动导入。程序检查尺寸、比例和文件完整性；具备视觉能力时辅助检查人物与道具的一致性 |
| 试拍 | 一个代表性或高风险镜头 | 用户确认所用首尾帧、提示词和本次费用信息后再提交。试拍效果不合适时，先修改对应输入，再决定是否重拍 |
| 批量生成 | 其余需要生成的镜头 | 只提交本次已批准镜头。生成结果下载并检查可播放性后进入候选列表。保留成功、失败和中断记录 |
| 审片与编排 | 用户选用的一组镜头 | 同屏比较候选，记录问题时间点。可用已有素材替换 AI 镜头，也可以为单镜重新生成 |
| 交接与归档 | 可编辑草稿及最终 MP4 | 复用路径 A 的交接。用户从剪映导出的成片可导回项目并关联本次交接 |

### 2.3 两条路径如何合并

已有素材和生成镜头最终都成为带来源的素材，可赋给任意镜头。一个镜头可以有多个版本，只有「已选用」的版本进入草稿。用户在等待第 3 镜生成时，可先把实拍开场赋给第 1 镜，也可以继续检查其他镜头。

「剪映草稿已创建」表示适配器已完成结构检查和外部写入。「已验证可编辑」由实际在剪映打开、修改或实机验收记录确认。「最终成片已归档」表示用户导入了实际的输出文件。无法建立原生草稿时，可以下载按顺序组织的**素材交接包**，内含视频、字幕、顺序和来源清单。界面清楚标注两种交付形式。

### 2.4 变更、回退和版本影响

| 操作 | 行为 |
| --- | --- |
| 改文案但画面要求不变 | 保存新简报版本，关联镜头进入「建议复查」。现有候选仍可播放和选择 |
| 替换第 2 镜尾帧 | 现有生成视频标记为基于旧输入。若第 3 镜引用这张图，显示衔接复查提醒 |
| 选择某镜的上一版 | 更新该镜的当前选择，保留其余镜头、历史生成记录和费用 |
| 重新交给剪映 | 创建新交接记录和新草稿，保留此前用户在剪映内做过的修改 |
| 在剪映里改完导出 | 通过手动导回 MP4 归档。首版记录最终成片与交接的关系，时间线回读须按编辑器和版本另行验证 |

## 3. 工作台页面和交互

### 3.1 首页、项目和连接引导

- **首页**显示「记个想法」「继续制作」「我有素材」「我有一个创意」。已经有项目时优先展示继续卡，首次进入时可打开明确标识的示例项目。最近项目卡显示封面、阶段、最后更新时间和一项待办，例如「3 个镜头已选 · 1 个待审核」。
- **打开项目**回到上次查看的阶段与镜头。未完成任务在项目顶部和任务中心都可找到。切换项目保留各自的会话与选中状态。
- **首次连接**按实际需要引导。本地素材导入可直接开始。用户第一次需要生成或交接时，弹出对应工具设置，只显示必要配置、用途、权限和测试结果。模型密钥在后端保存，界面只显示连接状态或掩码。
- **唯一入口**。在 DSH 侧栏打开工作台，优先复用当前 profile 可用的 DSH 文本模型。退出 DSH 后通过原侧栏入口重新打开并接续任务。模型未配置时，记录灵感、整理素材、浏览项目和手动编排仍可在插件中完成。

### 3.2 项目工作区布局

| 区域 | 主要信息和行为 |
| --- | --- |
| 顶部 | 工程名、阶段、运行任务数、待审批数和一个当前主操作。不同阶段使用「确认分镜」「审核首尾帧」「查看候选」「生成剪映草稿」 |
| 对话区 | 会话列表、消息、下一步按钮和输入框。输入框上方显示「整个项目」或「镜头 04」，可点击切换，防止指令作用到错误对象 |
| 主工作区 | 「简报」「分镜」「素材」「交付」四个页面。默认跟随当前阶段。分镜以缩略图卡片展示，支持拖动、键盘排序和批量选择 |
| 镜头检查面板 | 显示画面说明、目标时长、首尾帧、已选素材、其他候选、提示词、参考图与任务来源。常用操作靠近媒体，技术信息折叠 |
| 任务中心 | 显示待确认、排队、生成、下载、待处理和完成。支持按项目或工具筛选，点击任务跳到对应镜头 |
| 工具中心 | 显示接入能力、版本、权限、连接状态、测试和启停。替换工具时显示对哪些待处理任务有影响 |

桌面宽窗口采用对话、主工作区、镜头检查面板并排。窄窗口保留一个主工作区，通过「对话／项目」切换。视频预览在工作台内打开，保留「返回对话」或「返回分镜」，Esc 关闭后恢复焦点和原位置。状态既用文字也用图标表达，键盘可完成选中、确认、播放和关闭。

### 3.3 交互规则与状态文案

- **讨论和提交区分清楚。** 「帮我想三个开场」产生建议卡。「生成这三个镜头」产生待审批卡。界面给出具体动作，用户无需再猜一句「可以」会触发什么。
- **动作可追到对象。** 在镜头卡点「和 Agent 改这一镜」会附上镜头和版本引用。聊天里点引用可以回到该卡。请求里的「再短一点」若有多个可能对象，先让用户选一个。
- **播放、采用、重拍是独立按钮。** 播放不会改变已选版本。重拍展示将复用的输入与本次提交量。失败后可打开问题时间点和已有候选。
- **进度使用真实状态。** 远端无百分比时显示「已提交，等待生成」。下载结束后先显示「检查文件」，检查通过才变成「可预览」。
- **提示给出可操作的下一步。** 例如「第 3 镜已提交，暂时查不到进度。可以继续查询」和「当前剪映版本还没通过验证，可以先下载素材交接包」。
- **审批先看风险。** 显示供应商、上传范围、镜头数、时长、输入版本、预计费用及估算来源。有可验证的供应商额度时显示额度状态。未知报价时显示生成数量和时长，并要求用户明确确认。
- **避免把技术错误交给新手。** 日常页面使用「需要连接」「需要确认」「暂时查不到」「素材路径已变」等可理解状态。任务详情里保留技术原因和诊断编号。

### 3.4 灵感库与对话改稿怎样借鉴自媒体工作台

调研覆盖上游客户端与已安装版本的 Host 实现。自媒体工作台首页可以快速记灵感，记录后会找出相关旧卡。打开灵感后，左侧对话关联当前灵感，右侧保留固定的稿面结构，产物逐块出现。对话接口把回答、受校验的数据操作和实际改动回执分开。模型只回普通文字时保留回答，模型不可用时降级到有限的本地操作。部分成稿可以单独修改，实际改动有撤销入口。CUTDIRECTOR 复用这些交互原则，并按视频生产的外传、付费和草稿写入增加审批。 [灵感入口](https://github.com/woniuniuniu/dsh-media-desk/blob/main/client/canvas.jsx) · [成稿工作区](https://github.com/woniuniuniu/dsh-media-desk/blob/main/client/studio.jsx) · [对话执行](https://github.com/woniuniuniu/dsh-media-desk/blob/main/src/host.js) · [操作校验](https://github.com/woniuniuniu/dsh-media-desk/blob/main/src/ops.js)

| 产品能力 | V3 交互决定 |
| --- | --- |
| 快速收集 | 首页输入一句话后按「保存想法」。支持粘贴公开链接、拖入图或视频。失败时保留输入，链接无法读取时仍能保存链接和手写备注。收集时保留原始来源，抓取或 AI 总结由用户发起。公开链接抓取仅允许 HTTP(S)，拦截本机和内网地址及跳转 |
| 卡片与检索 | 灵感默认用有序卡片流，最近保存优先。提供置顶、关键词搜索与按类型筛选。卡片显示缩略图、原文摘要、来源、日期和「已用于哪个项目」 |
| 相关灵感 | 保存后可显示少量相关旧卡，先用本地标题、标签和正文匹配。用户可引用、忽略或主动合并。自动匹配不会删除、移动或合并卡片 |
| 灵感详情 | 左侧聊当前想法，右侧显示原文、来源和附件。Agent 可建议标题、方向或分镜构想，用户点「保存这版」后写入派生内容 |
| 进入制作 | 「开始做视频」打开简短确认页，只询问这次影响最大的规格。原灵感保留，项目卡可回到来源。可把多条灵感加到同一个项目 |
| 并排改稿 | 右侧先展示脚本、画面和结果的固定区域。Agent 回执说明改动了哪一项，例如「已把第 2 镜改为手部特写」。从回执可跳到结果、比较版本或撤销 |
| 合理取舍 | 首版采用易浏览的卡片流和分镜板。自由散落画布、内容日历、社媒账号抓取与数据复盘留在扩展范围 |

示例流程是用户保存「咖啡凉了才想起来喝」→ 在卡片中点「开始做视频」→ Agent 提出三个镜头 → 用户选中第二镜说「改成杯子特写」→ 右边只更新对应镜头的文字草案 → 用户点「画这镜的开始和结束」。已经选用的素材或成片保持原版本。需要上传、生成费用或写入剪映时，才进入相应的确认。

参考自媒体工作台的卡片展开、成果格子放大、媒体预览与逐块回填。工作区切换时保留空间方向，实际产物到达后只更新对应格子。动画可中断，支持系统减少动态效果设置。缩窄 DSH 窗口时保留明确的返回和切换路径。 [工作区与预览动效](https://github.com/woniuniuniu/dsh-media-desk/blob/main/client/studio.jsx) · [弹簧缓动](https://github.com/woniuniuniu/dsh-media-desk/blob/main/client/util.js)

### 3.5 新手模式和页面文案

- **首页按任务组织，工具按需出现。** 主要导航是「首页／灵感／项目／设置」。新手从「我有素材」「从想法开始」或「看看示例」进入，系统按阶段带路。专业配置统一收进「更多设置」和「工具与能力」。任务中心入口保持可见。
- **每个页面只突出一个下一步。** 空状态说清现在能做什么。导入素材后出现「排一下顺序」，审核后出现「先做一个镜头」，准备好后出现「交给剪映」。用户仍可返回前一步、跳过可选步骤或先保存。
- **优先展示能看得见的东西。** 分镜卡默认展示画面、要发生的动作、秒数和可播放状态。首尾帧区域主标签用「镜头开始／镜头结束」。需要学习术语时可展开简短解释。日志、参数、供应商任务号和能力名称放进详情。
- **Agent 先给结果和一项下一步。** 问「什么是分镜」时可以回答「就是先把视频分成几段，每段写清要拍什么」，并给「看看示例」或「帮我列几个镜头」。问「怎么继续」时结合当前工程给出可点动作。
- **预览能返回。** 从对话打开媒体时显示「返回对话」，从分镜打开时显示「返回分镜」，保留原卡片和滚动位置。关闭预览不会改变已选版本。所有关键操作可用键盘完成。
- **表达有统一词表。** 「工作流」在默认页面称为「制作步骤」；「首尾帧」显示为「镜头开始和结束的图」；「启用 Skill」显示为「添加制作方法」；「调用失败」说明哪一步受阻及如何继续。设置页在需要对照厂商时保留 API Key 等原名。

### 3.6 图形化连接向导

用户只在使用某项能力时配置所需连接。DSH 嵌套工作台优先发现当前 profile 可复用的模型或工具，生成、审片或交给剪映时按需提示。首次操作可先体验随包示例或整理已有素材。

| 步骤 | 用户看到的内容 | 系统处理 |
| --- | --- | --- |
| 1. 选用途 | 「帮我想内容」「生成图片」「生成视频」「交给剪映」 | 先按用途筛选支持的服务，只有多个可用方案时才要求选择 |
| 2. 选已有服务或连接 | 优先列出当前 profile 可复用的能力。未连接时引导到 DSH 配置文字助手，或在插件内按用途连接生成服务和剪映 | 内置厂商预填官方地址和支持项。需要密钥时显示去哪里获取、粘贴在哪里，支持图形界面直接保存 |
| 3. 检查可用性 | 「已连接」「能生成图片」「当前账号不能使用参考图」等 | 测试区分连通、身份验证、模型可用、实际产物。免费检查优先，涉及付费的试生成显示数量与费用信息，经确认后执行 |
| 4. 开始使用 | 「设为这个项目的默认工具」「回到当前步骤」 | 保存后回到原动作，保留所有输入。DSH 凭据由宿主保管，插件直接连接的服务密钥由插件后端按 profile 和当前 Windows 用户保护 |
| 5. 连接出错 | 「密钥已失效」「账户暂时不能生成视频」「剪映版本尚未验证」 | 提供更新密钥、切换已连接工具、导入现有产物或下载素材包。保留正在编辑的工程 |

默认按「每种用途一个可用默认工具」呈现。画幅、时长、是否使用参考图和预计花费是用户决策；接口地址、模型 ID、超时及日志归高级设置。订阅或平台账号的官方授权步骤可以通过明确链接完成，完成后返回工作台重新检查。普通用户路径不依赖终端、配置文件或整篇说明书。

## 4. 原生 Agent、工程与任务

### 4.1 原生 Agent 的工作方式

主循环按 **理解请求 → 确定对象 → 读取工程和可用工具 → 给建议或生成待执行动作 → 检查授权 → 执行 → 验证 → 写回工程 → 汇报下一步** 推进。普通问题可以直接回答。耗时任务交给后台，用户关掉对话后也能通过任务中心接续。运行时维护任务状态和权限，模型负责在允许范围内作出创作判断。

| 能力 | 行为与验收 |
| --- | --- |
| 对话与引导 | 识别咨询、立项、改单镜、查状态、生成、剪映交接。对「开始吧」读取当前阶段、对象和待办，显示可点的下一步 |
| 项目上下文 | 按当前目标、选中对象、已确认简报、相关素材和近期决定组织上下文。新对话可继续同一个工程，其他工程的素材和决定默认隔离 |
| 创作与分镜 | 提供可编辑简报、镜头描述、视觉设定和提示词。每份建议说明影响的镜头，用户可部分采用 |
| 工具选择 | 根据能力、权限、当前输入与配置选择执行器。每次任务固定执行器与模型配置版本。运行过程中配置变化时，已有任务继续查询原服务 |
| 审核 | 文件存在性、解码、尺寸、比例、时长和时间区间由程序验证。视觉或语义审核记录所看素材、问题位置和结果。工具能力不足时显示「需要人工检查」 |
| 故障解释 | 区分输入缺失、工具未连接、额度不足、远端状态未知、下载失败、版本不兼容。提供能实际执行的下一步，保留已成功产物 |
| 记忆与复用 | 工程记忆保存已确认的创作决定。只有用户点「下次也用」才保存跨项目风格或规则。支持查看依据、修改和撤销，当次要求优先 |

Agent 可以委派有限的导演、审核或制作任务。首版以**主 Agent 加独立审核任务**实现。Eian 的监督和代理角色可在后续作为可配置流程加入。监督负责检查当前执行是否偏离用户已确认要求。代理最多在用户预设权限内做低风险选择。上传私有素材、额外付费生成和外部草稿写入仍由用户批准。 [Eian 的多 Agent 工作方式](https://xarticles.io/articles/claude-code-codex-seedance-ai)

### 4.1.1 Agent 何时主动介入

| 请求类型 | 默认介入方式 |
| --- | --- |
| 「记下来」「把标题改成这个」 | 用户对象明确时立即完成本地、可撤销的改动，并给回执 |
| 「给三个开场」「这个地方怎么改」 | 提出建议卡。普通聊天或文字回答保持为消息，无需触发工具 |
| 「把已经确认的第 2 镜改掉」 | 生成新候选或修改草案，显示影响，用户确认后才切换当前采用版本 |
| 「继续吧」「开始」 | 查看当前阶段和最后一个待办。只有一个明确的低风险动作时给出可执行按钮。有多个目标时询问一个关键选择 |
| 「把全部镜头跑一遍」「交给剪映」 | 先展示具体范围、可能发生的费用或外部写入，等待用户确认 |

工具动作与回答分开校验。模型只返回自然语言时，正常展示回答，工作台仅在用户确实请求执行且缺少有效动作时说明下一步。不能把「我已经改了」当成执行回执。实际修改以工程服务或工具确认的结果为准。模型不可用时继续支持灵感收集、排序、浏览、预览与已接入工具的手动操作。

### 4.2 工程对象与版本关系

| 对象 | 需要保存的信息 |
| --- | --- |
| 制作项目 | 名称、目标、创作简报版本、规格、镜头顺序、工作流版本、来源工程引用 |
| 会话和消息 | 所属项目、角色、时间、当前作用对象、引用的素材与任务、已确认的关键决定 |
| 素材 | 稳定 ID、本机引用、类型、时长或尺寸、来源、内容校验值、是否仅供参考、上传授权 |
| 镜头 | 稳定 ID、描述、目标时长、顺序、输入素材、当前选中的版本 |
| 镜头候选 | 产物、执行器和模型、参考图及提示词版本、任务引用、检查结果、来源和费用记录 |
| 任务 | 稳定 ID、项目和镜头范围、操作类型、输入快照、执行器版本、外部任务 ID、状态、事件序号 |
| 审批 | 谁在何时批准了哪个输入版本、数据外传范围、目标服务、生成数量、费用信息或外部写入位置 |
| 交接 | 草稿或素材包类型、已选镜头和字幕版本、目标应用及版本、校验结果、草稿标识和位置 |
| 成片 | 用户导回的文件、关联交接、版本、归档时间及是否为当前成片 |
| 灵感 | 原始文字、来源链接、附件引用、记录时间、标签、派生版本与使用过的项目 |
| 制作方法与调用记录 | 方法来源、固定版本、适用阶段、所需能力、当前路由、权限要求和本次使用结果 |

素材、简报、镜头输入和候选都有版本引用。改动后创建新版本，已有产物继续对应原输入。任务开跑前固化其输入。DSH 插件内的页面读写同一个工程服务，通过事件更新任务状态。连续点击同一个审批或交接按钮时，服务端依据稳定请求 ID 返回同一次操作。旧工程接口经 DSH 兼容页访问，V3 新数据单独存放并随工程备份。

### 4.3 任务、审批和故障恢复

任务状态统一表达为 **待输入 → 待确认 → 排队 → 已提交 → 运行中 → 回收产物 → 验证 → 完成**。另有「失败」「已停止」「状态待核对」。只有工具已经明确接收任务才显示「已提交」，只有本地文件可读且验证通过才显示「可预览」。

- 审批绑定工程、对象、输入版本、目标工具、上传范围和可执行数量。用户更改首尾帧、提示词、服务或生成数量后，旧审批失效。付费重拍与首次付费分别确认。
- 对已返回外部 ID 的任务，重启后查询原 ID。提交响应丢失时先核对外部任务记录，无法确认则停在「状态待核对」，说明再次提交可能产生额外费用。
- 下载失败重试下载环节。产物链接过期时先尝试从原任务重新获取。最终无法取回时标明外部任务已完成与本机文件缺失的区别。
- 取消先停止本地后续动作。只有供应商明确确认取消才显示远端已取消。用户可以关闭对话并在任务中心查询已提交的任务。退出 DSH 时保存进度，重新打开后用原任务 ID 续查。
- 剪映交接先暂存后写入，核对目标版本、目录权限、素材引用和草稿名冲突。写入失败保留工程和暂存诊断，提供重试或导出素材包。默认新建草稿，每次交接独立留痕。
- 网页、字幕、外部产物和插件结果按资料处理。调用权限来自用户和系统策略。只有用户同意的素材和任务参数才能离开本机。密钥不进入对话、素材清单或日志。

## 5. 工具接入与插件体系

### 5.1 首批工具与接入路线

| 能力 | 首批方案 | 验证与退路 |
| --- | --- | --- |
| 文本理解、故事、分镜 | 当前 DSH profile 的模型目录和单次推理接口 | 验证普通聊天、创作建议与工具动作各自可读。连接失败仍可手工编辑简报和分镜 |
| 首尾帧生成 | Codex 优先，配已配置图像 API 和手动导入 | 验证隔离任务能回收实际图片，不能仅凭「已生成」文本判成功。图像服务声明参考图或编辑能力。用户从设置页明确选择备用路线 |
| 视频生成 | 火山方舟 Seedance 官方 API | 校验所选模型是否支持当前输入、分辨率和时长。完成后及时回收视频。配置不可用时可导入外部生成的镜头。 [创建任务](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh) · [查询与下载](https://docs.volcengine.com/docs/ark/list-video-generation-tasks-api?lang=zh) |
| 剪映草稿 | Easy 剪映优先，capcut-cli 为 Windows 备选 | 只把已实机验证的剪映版本标为可交接。兼容性未知时允许素材包。生成草稿、实际打开与能否读回分别标记 |
| 媒体读取与预览 | 复用本地 FFmpeg、FFprobe 和工作台预览 | 检查时长、尺寸、音轨和文件可解码性。支持缩略图和预览返回。用户从剪映完成最终精修与导出 |
| 粗剪、卡点、参考分析 | 后续按能力接入外部实现 | 优先复用 Easy 剪映已实测可用的粗剪或卡点能力。各自验证素材范围、输出可编辑性与失败后的接续 |

DSH 是唯一宿主，负责嵌入工作区以及提供模型、Skill 和受控子 Agent。CUTDIRECTOR 管理工程、权限、任务和对话。已配置的本机 CLI、服务 API 和 DSH 扩展都经能力注册表接入。Claude Code 等执行器后续按同一接口接入，现有工程和两条工作流无需重新建档。 [DSH 扩展手册](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/extension-cookbook.md)

### 5.2 插件契约

首版以内部适配器验证契约。社区插件在两条默认链路稳定后开放。插件应声明 **ID、版本、能力、输入输出、执行方式、权限、可用性检查、成本信息和恢复能力**。

- 能力按任务角色注册，例如「生成首尾帧」「生成视频」「生成剪映草稿」「审查镜头」。工作流依赖能力，项目设置决定用哪个已连接执行器。
- 支持本地 CLI 或 Skill、HTTP API、DSH 工具或子 Agent 三种接法。每种适配器都至少提供能力检查、执行、产物验证。是否支持进度、取消和恢复通过声明和实测确定。
- 插件可申请读取本任务输入、向本任务目录写产物、访问指定服务、上传指定素材、发起付费调用、写入经用户确认的剪映草稿目录。不同权限独立授权。未知的命令、可执行脚本和未经注册的远程地址不由 Agent 直接运行。
- 本地执行使用限定工作目录和参数。外部输出进入素材库前校验路径归属、文件类型、大小和内容摘要。日志记录工具和任务 ID，隐藏凭据。配置和测试结果按本机用户保存。
- 插件启用时显示来源、版本、权限和费用。升级后重新检测能力。移除后仍可回看已归档产物，待执行任务提示选择替代工具，已提交任务保留外部记录。
- 插件开发者验收至少提供最小示例、正常与失败样例、权限和产物清单、Windows 或其他宿主的支持范围。默认工作流先由维护者验证和固定依赖版本。

### 5.3 分镜画布和可复用工作流

首版使用阶段导航与分镜卡片。每个产物从第一天就带输入引用，记录某张设定图被哪些镜头使用、某个尾帧是否是下一镜的首帧、哪批镜头组成一次剪映交接。后续画布将这些依赖可视化。

画布节点包括创作简报、素材、参考图、分镜、生成、审核、选用和交接。连线检查输入输出类型和循环依赖。替换角色设定图前展示受影响的镜头，用户可选择单独复查或重跑。已有候选继续保留。涉及付费或外部写入的节点仍走同一审批。流程可保存为模板，模板保存配置、规则和依赖结构，复制到新项目后需重新选用素材、连接账户并批准执行。

### 5.4 制作方法、Skill、插件和模板

用户在工具中心看到「制作方法」。导入时允许显示 Skill 这个通用名称，工作区默认只展示方法的用途，例如「口播去重复」「短片分镜」「检查角色是否前后一致」。Skill 负责描述做事的方法，插件负责提供真实的可执行能力，模板负责把多步产物和依赖连起来。同一 Skill 可以由不同执行器完成，也可以只指导原生 Agent 整理建议。 [Agent Skills 规范](https://agentskills.io/specification) · [DSH Skills 子系统](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/skills.md)

**首版交付基础导入和导出。** 支持选择含标准 `SKILL.md` 的目录，或导入符合范围的 ZIP。读取标准 `name`、`description`，保留已允许的文本参考资料。CUTDIRECTOR 的可选 `cutdirector.skill.json` 补充适用阶段、输入输出、所需能力、角色、网络与收费声明、推荐执行器及版本。通用包缺少该清单时，以「可阅读的方法」导入。用户可以在图形界面将它设为仅供建议，或关联已安装的兼容能力。来源方声明只用于匹配，授权由工作台发放。

| 动作 | 用户操作与系统边界 |
| --- | --- |
| 导入预览 | 展示方法用途、来源、许可、会读取哪些资料、可能使用的工具和缺少的能力。先预览再添加 |
| 检查和确认 | 限制压缩包大小和文件数量。拒绝路径穿越、绝对路径、链接和嵌套压缩包。脚本与未知可执行文件不从 Skill 导入流程运行。若需脚本能力，通过独立插件安装和授权 |
| 添加或升级 | 同一内容提示已添加。相同名称但来源或内容不同，展示差异并允许作为新版本或另存。运行中的任务继续绑定原版本 |
| 导出 | 打包标准 Skill 说明、允许分享的文本参考、可选 CUTDIRECTOR 清单及许可信息。导出预览列出文件。默认排除账号密钥、工程媒体、聊天记录、私有素材路径和临时文件 |
| 管理 | 可停用、按项目限制、设为偏好、查看最近使用及回退版本。停用后不影响已经生成的产物 |

后续可以导入和导出多步骤制作模板。模板保留依赖、每一步用途、所需模型和可用示例。打开后先显示缺少的能力，并让用户自己连接或换用已配置工具。带外部素材的模板需显式说明来源和使用范围。借鉴 ComfyUI 模板的可浏览预览与依赖检查，首版保留 CUTDIRECTOR 自己的轻量 Skill 格式和固定制作流程。 [ComfyUI 模板库](https://github.com/Comfy-Org/workflow_templates) · [模板与依赖检查](https://github.com/Comfy-Org/docs/blob/main/interface/features/template.mdx)

### 5.5 原生 Agent 怎样把方法交给正确的执行者

Agent 首先识别用户要做的事、当前阶段和对象，再从 Skill 的简短用途与能力声明中筛选。运行时匹配输入类型、执行者角色、可用权限和所需插件。用户显式选择优先，之后使用项目偏好和内置默认。能力不匹配或缺少必要输入时，提示最关键的一个选择或等待配置。只有命中的 Skill 才加载正文和本步需要的参考文件。

| 用户任务 | 谁拿到方法 | 怎样判断成功 |
| --- | --- | --- |
| 「把这条灵感整理成三镜」 | CUTDIRECTOR 的规划 Agent 使用分镜方法，只读取当前灵感和简报 | 给出可编辑分镜卡，未确认前不改变已定方案 |
| 「画第 2 镜开头和结尾」 | 图像执行器，如已验证的 Codex 或图像 API，收到该镜头简报、被授权的参考图和必要规则 | 返回两张合法图片，关联到第 2 镜的正确版本 |
| 「帮我看看人物前后是否一致」 | 有图像理解能力的审核执行器，使用审核方法及被授权的图片 | 返回对比结论、具体证据和仍需人工复核的问题 |
| 「按这两张图做成视频」 | 视频适配器调用 Seedance 等服务。由规划 Agent 把方法转成结构化生成参数 | 用户确认上传和花费后提交。视频验证完成后进入目标镜头候选 |
| 「剪掉重复口播，交给剪映」 | 已验证的粗剪工具和剪映草稿适配器。前者使用转写与粗剪方法，后者接收选用的片段、顺序和字幕 | 没有转写时显示识别或导入字幕。草稿在剪映实际可打开，素材可继续编辑 |

路由记录至少保存当前对象、Skill 来源与版本、实际执行者、收到的输入范围和结果。普通页面可展开看「为什么选了这个工具」。不具备看图能力的模型不能接图像审核，图像生成器不会接收视频生成任务，剪映工具只接收交接所需的已选素材。Skill 命中不会触发自动外传、自动付费、自动安装或向其他项目传递资料。替换执行者时重新验证权限、输入和审批。

### 7.3 质量、可用性与回退

- **真实环境**。隔离项目和隔离 DSH profile 先行。分别记录 Windows 剪映实机、真实 Codex 出图、真实方舟生成、模拟故障和自动化回归的结果。模拟产物只用于回归。
- **异常场景**。覆盖未配置工具、角色参考缺失、两张图比例不同、预算不足、重复审批、远端超时、下载中断、换工程、关闭 DSH、重启、取消受限、剪映版本未知和路径冲突。每项要验证恢复入口与已有产物。
- **内容检查**。验收样片至少包含字幕改字、多区间或多素材、实拍与 AI 混用、回看旧候选、重拍单镜、剪映内另存和最终成片归档。对角色连续性和镜头衔接保留人工评审。
- **新手试用**。邀请至少 5 位很少使用 AI 剪辑或 AI 生视频的用户。让他们自行记录一条灵感、转成项目、找到「我有素材」的路径、播放并返回、完成可编辑草稿交接。目标至少 4 位无需终端和人工口头指路。再测连接向导，观察用户是否知道密钥从哪里来、是否理解会上传什么及何时付费。
- **Skill 验收**。测试标准文本 Skill、带清单的 Skill、重名或升级、损坏或带路径穿越的压缩包、未安装依赖、图像审核误选文本模型、视频生成超权限、停用和版本回退。确认导出包不含密钥、项目素材和本机私有路径。
- **效率对照**。用同一短片对比手动跨工具流程，记录复制粘贴次数、首次草稿用时、重复付费次数、改单镜重做步骤和失败恢复用时。试用记录新增术语误解、找不到下一步次数、连接需要协助次数和每一步的退出位置。
- **发布与回退**。验证后再切换正式 DSH 插件，停用已确认的旧独立启动项和工作台快捷方式。备份现有工程、会话、设置和插件配置，保留上一个发布包供 DSH 内回退。回退时保留 V3 制作项目和已生成的媒体，旧版可在 DSH 内继续访问原有剪辑工程。

**首发完成的判断**是用户从 DSH 侧栏打开制作工程，把已有素材和 AI 生成镜头组合成一条片，知道下一步、哪里要确认、什么时候可能花钱。交付物能在目标 Windows 剪映版本里独立编辑，成片也能回到原项目，整条链路可以从失败点接着完成。
