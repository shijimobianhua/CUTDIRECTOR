# CUTDIRECTOR 产品与使用指南

适用版本：0.3.0-preview.7。更新日期：2026-11-10。

CUTDIRECTOR 希望解决的是创作过程分散的问题：想法在笔记里，剧本在文档里，图片和视频在不同服务里，最后还要转去剪辑软件整理。工作台把这些入口、资料和任务记录放到一起，帮助用户找到下一步。

当前产品运行在 DSH 内。CUTDIRECTOR 管理自己的作品、会话、制作记录与确认流程，DSH 提供插件宿主、模型和工具接入；剪映负责后续精修。本仓库仍是个人预览源码，实际供应商和长片交付还需要进一步验证。

## 1. 先找到适合你的起点

| 你现在有什么 | 从哪里开始 | 第一步先做什么 |
| --- | --- | --- |
| 有一段要剪的视频 | 工作台 → 用已有视频制作 | 建立作品，导入素材，说明想保留什么 |
| 只有一个想法 | 灵感，或工作台 → 从想法开始制作 | 先把想讲的事写下来 |
| 有小说或短剧剧本 | 剧本 → 新建剧本 / 创作完整一集 | 导入原文，按集和场景整理 |
| 想先了解怎么用 | 右上角助手 | 直接问“我有一段视频，怎么开始？” |
| 已经制作过 | 工作台的继续制作，或作品列表 | 回到原作品，查看已保存内容与任务 |

第一次可以从剧本页的“先试 10 秒”开始。先验证一个角色、一段动作和一种制作服务，比一开始批量制作整集更容易发现问题。

## 2. 页面之间怎么配合

**工作台**是制作入口和进度概览。它展示最近作品、待办和最近灵感。

**灵感**是随手记录的地方。想法暂时不成熟也可以先保存，之后再发展成作品。灵感采用整齐卡片；它与作品内的关系画布分开。

**剧本**存放每个作品的故事、分集、场景、分镜和概念资料。它既可以自己编辑，也可以请导演讨论，再选择采用建议。

**作品**承接素材、制作与交付。一个作品是一份创作记录，不是每次聊天都建立一个新作品。

**任务**帮助你核对正在进行、失败和等待确认的工作。外部服务没有明确返回结果时，先查询原任务，避免重复提交。

**设置**管理制作服务、工具和方法。日常创作不用先理解工具协议；普通接入优先使用预设，高级参数留给需要 DIY 的用户。

## 3. 助手怎么聊

右上角助手可以自由聊天、问一般知识、讨论创意或问工作台怎么用。它使用在 DSH 选择的模型，保留历史，支持新对话、搜索和改名。

默认没有附上作品。需要讨论某个作品的具体内容时，在“模型与上下文”中选择作品并决定附上资料。只是在旁边打开了一个项目，不等于模型已经看过全部素材。

普通聊天不会自动创建灵感，也不会直接改工程。想保留某段内容时，可以主动保存为灵感或建立作品。

专业任务从对应工作区发起。例如在剧本里选择“完善剧本”或“拆成分镜”，导演才会按当前一集与选定资料提供结构化建议。逐项查看，采用后才保存。剧本有了新版本，旧建议需要重新核对。

连接失败会提示可以采取的操作。例如重新登录模型厂商、更新 Key、检查额度或稍后再试。“重新问这条”只把问题放回输入框，仍由用户再次发送，不自动产生新调用。

## 4. 从剧本到分镜

### 写或导入剧本

在作品中选好当前一集，再添加场景。每段内容可以区分为：

| 类型 | 怎么理解 |
| --- | --- |
| 动作 | 画面里能看见的事，例如“林夏收起伞，抬头看向站台” |
| 对白 | 人物实际说出口的话，标明说话人 |
| 旁白 | 画面外的讲述 |
| 内心独白 | 人物心里想的话，和直接说话分开 |
| 音效 | 明确需要出现的声音，例如站台广播或脚步 |

支持文本和 DOCX 正文导入。导入原文会保留；改编内容在剧本中编辑。让模型参考小说时，明确选择本次发送的原文区间，不把整本小说默认为模型已读。

内容有版本记录，可以导出或查看历史。发生并发保存冲突时，先保留当前输入，再比较新版，不直接覆盖。

### 拆分镜头

每一镜说明发生什么、预期多长、关联哪段剧本，以及开始或结束画面。可以自己写，也可以请导演提出建议。

分镜支持复制、拆分、合并和排序。查看“剧本来源”可以回到关联内容。把某一集发布到制作流程时，确认是你要制作的那一集，其他集不会因为浏览或编辑就自动替换它。

### 固定角色与场景

把角色外观、服装、声音、场景光线、道具特点等放在对应资料中；概念图用于沟通与参考。保存这些资料有助于后续任务保持方向一致，但不保证外部生成模型能做到完全一致。

## 5. 关系画布用来做什么

关系画布展示同一作品内的剧本、场景、分镜与其他内容。可以拖动位置、连接关系、自动排布、缩放和查看内容。

画布与文字工作区共享内容，布局单独保存。连上一条线只是在整理关系，不会开始出图、生成视频或审批费用。它目前也不是可以任意自动执行的节点工作流引擎。

## 6. 对话模型和制作服务怎么接

### 对话模型

先在 DSH 配置厂商和模型，再在助手的“模型与上下文”里选择。CUTDIRECTOR 通过 DSH 模型服务调用，不要求为聊天再复制一次相同 Key。一次调用开始后使用固定的模型，修改选择影响之后的请求。

### 图片和视频服务

到设置的图片与视频页面，选择添加服务：

1. 选择已有预设，例如兼容图片接口、方舟、RunningHub 或 ComfyUI。
2. 填写服务地址、模型或工作流 ID，必要时输入 API Key。
3. 核对工具来源与能力说明，点击检查并保存。
4. 在作品的制作素材页面选择该服务。

检查连接不会生成图片或视频。一些自定义接口只能确认配置格式，真正的可用性仍需首次调用验证。看到“已配置”与看到“已连接”含义不同。

Windows 本地保存的制作服务 Key 使用当前用户 DPAPI 保护。导出工具配置不包含 Key，其他电脑需重新配置；它不是跨电脑共享的凭据备份。

### RunningHub 与 ComfyUI

RunningHub 使用用户自己账号下的工作流，填写工作流 ID 并检查参数。ComfyUI 需要用户已有运行中的服务、API 格式工作流与所需节点。H3 等方案通过适配器和工作流接入，不会自动安装模型权重或赠送调用额度。

## 7. 一次制作怎么确认

制作素材页可以选择服务、目标内容、制作方法和有序参考素材。图片 1、图片 2、音频等顺序可能影响工作流输入，提交前需要核对。

“准备这次制作”之后会显示本次要求、资料与服务。需要发送参考素材或可能收费时，由用户分别确认，然后提交。

任务会固定本次连接、内容和相关版本。返回结果先作为候选保存，用户检查后再选用到目标内容；不把第一份生成结果直接当作最终成品。

外部任务状态不确定时先核对原任务与账单。查询或收集已有结果不会重新生成。主动重试与重新生成是新的动作，可能产生新费用。

## 8. 用一个 10 秒故事走一遍

演示主题是“雨后站台，两位老朋友重逢”。

1. 新建一个作品，选择先做 10 秒。
2. 写一个场景：雨停后，林夏收起伞，看向站台另一端。
3. 添加一句对白：“你还是来了。”
4. 拆成两镜：5 秒开场动作，5 秒对视与回应。
5. 保存人物与环境说明，准备需要的概念图或参考素材。
6. 选择自己已配置的服务，先做一个短小样，确认素材上传与额度。
7. 检查人物、动作、声音和台词，满意后再选用；有问题先调整局部。
8. 安排画面、对白和配乐，创建剪映草稿继续精修。

上面的内容是演示脚本，截图展示的是保存和规划过程，没有真实生成该影片，也没有成片效果承诺。

## 9. 画面、声音和剪映交付

主画面之外，可以安排叠加画面、对白、音效和配乐，并设置音量、淡入淡出及关键点。例如保留说话人的对白，同时切到另一人的反应画面。

剪映交付依赖本机环境与草稿编译器。交付前检查素材可用性、顺序、声音和目标位置；进入剪映后继续预览与精修。

多轨 handoff 数据契约已做本地检查，真实多轨完整导出、接近25分钟的项目仍需验收。不要把接口支持或截图当作所有剪映版本的兼容性保证。

## 10. 自己接工具和制作方法

| 内容 | 作用 |
| --- | --- |
| 工具 | 实际完成调用的服务、程序或 DSH 插件 |
| 能力 | 工具能做什么，例如画图、生成视频、分析参考 |
| 制作方法 / Skill | 告诉对应阶段怎么做，不能代替服务或授权 |
| 工作流 | 组织多个制作步骤或运行用户提供的工作流 |

工具标准 v2 声明身份、版本、输入输出、能力、权限、任务生命周期与费用属性，支持配置导入导出。通过 HTTP、MCP、DSH 等方式接入时，仍遵守相同的准备与确认流程。执行不可信本地程序有风险，本地 MCP 的信任声明不等于操作系统沙箱。

制作方法可导入导出，并按任务阶段和执行器条件使用。方法不匹配时不会因此获得其他工具的权限。MCP OAuth 尚未实现；当前路径以已配置 Key 或可信本地服务为主。

开发说明见 [工具接入标准](../v3/创作扩展与工具接入-v2.md) 与 [工具开发](../v3/扩展工具开发.md)。

## 11. 当前哪些还需要验证

- Codex 原生出图在开发机仍被隔离检查阻止，WSL2 路径也尚未完成本机验收。
- 真实文字模型的创作质量、图片/视频供应商的效果与费用，需用对应账号实测。
- 每种外部工作流、MCP/DSH 工具和节点依赖需按实际配置核对。
- 接近25分钟的视频、多轨剪映完整导出和新手群体试用尚待完成。
- 公开仓库提供源码和文档，不包含能在任意电脑直接运行的安装成品。
