## 2 产品定位与目标用户

### 2.1 一句话定位

帮助中文个人创作者把自己的素材与创作要求，变成可预览、可接手修改、可继续交给 Agent 的视频工程，并完成经过检查的交付。

用户主要表达“想保留什么、哪里需要修改、希望达到什么效果”。Agent 负责理解内容和组织执行；工作台让用户看见、接管和修正结果。DSH 承载运行和插件组合，产品围绕视频任务形成连续体验。

### 2.2 首批用户与任务

| 用户 | 典型素材与任务 | 首版重点 |
| --- | --- | --- |
| 知识或观点创作者 | 一人讲话、多次重录、长停顿、重复表述 | 内容粗剪、保留观点和限定条件、字幕纠正、多轮缩短 |
| 教程创作者 | 讲解、录屏或操作演示 | 依照用户标注或可核对的画面保留步骤，避免只剩讲解没有操作 |
| 产品介绍创作者 | 口播与产品展示，含名称、参数、使用限制 | 整理介绍顺序、保护关键事实、协调讲解与展示画面 |

第一版使用环境为 Windows 本地、单用户 DSH 工作区。复杂品牌团队审片、多机位长纪录片和专业调色交付另行评估。

### 2.3 用户痛点与预期价值

| 现有痛点 | 产品提供的价值 | 验证方式 |
| --- | --- | --- |
| 素材需要反复通看、整理 | 转写与按需画面帮助定位可用内容 | 选段能回到原素材，用户能说明遗漏或误判 |
| 自动粗剪容易删掉重要信息 | 明确保留项、来源依据与冲突处理 | 产品名、数字、否定和限制说明逐项核对 |
| 生成结果后不方便继续改 | 交付可编辑工程，并支持直接操作 | 用户改字幕后 Agent 继续剪，修改仍保留 |
| 一句修改要求导致整体重做 | 选中对象与范围驱动的局部调整 | 检查目标变化和非目标区域保持情况 |
| 不知道任务卡在哪里、成片是哪版 | 可见任务、版本和真实产物检查 | 失败可定位；旧版本导出有明确标记 |
| 每次需要重复说明习惯 | 先记录确认的反馈，后续发展偏好复用 | 当前任务调整与跨项目复用分别评估 |

差异化假设是中文内容处理、人工与 Agent 的连续协作、可解释的取舍以及可扩展方法。能否优于其他产品需要真实任务和用户验证，不能用“有聊天框”替代结论。

## 3 产品目标、边界与版本范围

### 3.1 首版目标

首版让用户完成：导入素材 → 表达要求 → Agent 理解和选段 → 共同编辑 → 预览与反馈 → 导出视频、字幕和可重开工程。

交付同时满足三类结果：视频任务完成、用户可接手修改、出现错误时可解释并继续处理。任何一类缺失，都不能只凭生成一个 MP4 宣称完成产品。

### 3.2 范围与优先级

P0 为首版退出要求；P1 为后续优先扩展；P2 为进一步评估。P1/P2 当前只做接口和数据位置规划，不提前实现空页面或全部后端。

| 能力 | 优先级 | 首版边界 |
| --- | --- | --- |
| 项目建立、素材入库与媒体检查 | P0 | 本地文件与实际可解码格式，原素材保留 |
| 中文转写与时间依据 | P0 | 一条真实可用实现；缺失时间或精度不足明确呈现 |
| 按需读取画面、短预览与来源片段 | P0 | 支持核对关键内容，不承诺完整长视频视觉理解 |
| 创作简报、内容选段与方案说明 | P0 | 时长、保留项、顺序、素材缺口可检查 |
| 基础可视编辑与 Agent 共同修改 | P0 | 片段选择、删除、裁剪、排序、字幕纠正、基本音量与淡化 |
| 版本、差异、撤销和重开 | P0 | 同工程、稳定对象、冲突可见，人工修改受保护 |
| 异步任务与产物检查 | P0 | 查询、失败、取消、重试、中断核对、版本归属 |
| 主 Skill、三个通用流程、口播专项 | P0 | 共五个，按任务加载，验证扩展机制 |
| 简单教程与产品素材 | P0 | 用户标注或可回看核对的操作；沿用首版基础编辑子集 |
| 反馈记录 | P0 | 项目内修正、接受或否决和对应版本；不承诺自动长期学习 |
| 高级教程、访谈、用户给定参考分析 | P1 | 增加视觉、说话人等能力和专项验收 |
| 卡点、Vlog、素材搜索与偏好复用 | P1 | 分项上线，不随 Skill 名称出现就算支持 |
| 动效、配音、生成、多语言、多画幅 | P2 | 增加能力与时间映射后独立验证 |
| OTIO、剪映等外部工程互通 | P1/P2 | 依据实际用户需求选一个格式和固定版本起步 |
| 多机位、长叙事、独立应用、对外服务 | P2 | 单独确定范围、资源、兼容与排期 |

复杂拖拽与高级效果不必成为早期原型前提，但“人工改后 Agent 接着改”的证明必须在 M1 完成。

### 3.3 输入输出与资源范围

| 项目 | 需求 |
| --- | --- |
| 输入 | 本地视频和音频；媒体支持按容器、编码、时间戳、声道等实际探测决定 |
| 项目规格 | 显式分辨率、画幅、帧率、音频与字幕设置；默认值可见并保存 |
| 视频输出 | MP4；编码、字幕烧录路线和精确配置在 M0 验证 |
| 附属输出 | UTF-8 SRT、可重开的工程或工程引用、版本差异、检查报告 |
| 素材规模 | M0 记录验证过的文件数、总时长、分辨率、硬件与耗时 |
| 范围外输入 | 说明未验证或不支持的原因；提供转换、缩小范围或人工继续的路径 |

初始验证可以使用 1 至 3 段、累计约 10 分钟、1080p 的素材，作为测试规模建议。此值不是产品硬限制，也不是已达到的性能承诺。

## 4 产品组成与责任分工

| 组成 | 应承担的事情 | 关键边界 |
| --- | --- | --- |
| 产品 Agent | 理解目标、评估素材、内容取舍、选择方法、组织执行、检查反馈 | 依据实际工具结果推进，不能自述替代成功证据 |
| 主 Skill | 提供通用编排、选择与组合规则 | 不写入全部视频类型的详细方法 |
| 通用与专项 Skill | 组织共同流程和具体剪辑方法 | 同一 Agent 按需读取，不自动变成其他 Agent |
| 工作台 | 项目入口、素材、预览、基础编辑、选择、任务、版本和交付 | 工程内容以共同服务为准 |
| 项目与编辑服务 | 权威工程、命令校验、原子版本、历史、变更通知 | UI 与 Agent 共同写入；不能各存一份独立时间线 |
| 能力适配器 | 探测、转写、画面、渲染及未来外部能力 | 将后端差异转换为可检查结果，声明支持范围 |
| DSH | 模型和会话、插件组合、工具、Skill、运行任务、界面扩展等 | 视频语义、项目版本与业务任务由产品补齐 |
| 用户 | 创作意图、核心约束取舍、审片与接受 | 明确需要决定的冲突；普通可撤销修改可自主推进 |

对外可以安装一个视频产品插件包，内部组合页面、Agent 配置、Skill、工具与服务；外部能力可由其他 DSH 插件提供。插件之间通过服务契约接入，不要求把开源项目整体搬入产品。

## 5 用户主流程与交互要求

### 5.1 首次进入与继续项目

进入后展示新建项目和最近项目。必要依赖检查给出可执行原因，如转写尚未配置、渲染不可用；设置放在设置入口，创作主流程使用业务语言。

继续项目恢复工程、当前版本、任务与产物归属。媒体丢失时标出受影响素材，支持重新定位；找到同名但内容不同的文件不能静默替换。

### 5.2 新建到首次方案

1. 用户导入素材并设置或接受可见输出默认值。
2. Agent 整理创作简报：用途、目标时长及允许偏差、保留项、风格、作用范围、输出要求和缺口。
3. 读取素材信息、真实转写和必要画面，形成可回查的素材摘要。
4. 给出内容结构、候选片段、来源位置、预估长度与简短理由。
5. 在明确目标且可撤销的授权范围内应用方案；涉及核心表达冲突则给出可比较选择。
6. 工作台更新同一工程，用户能播放、定位和修改。

不要求所有任务逐条确认每个剪切。用户要求“先给方案”时停在提案；要求完成剪辑时应持续推进到可审看结果。

### 5.3 人工与 Agent 接续修改

用户选中片段、字幕或时间范围后提出“这里缩短”“保留这句话”。上下文携带项目、版本、对象与范围，不能只传一句没有指向的文本。

Agent 读取最新工程，解释改动范围并提交局部提案。工作台展示差异、更新预览，非目标人工编辑保持。基准版本过旧时重新核对，不能静默覆盖，也不能直接把旧操作改成新版本号重试。

### 5.4 导出与交付

导出明确当前版本和规格，显示任务状态与实际检查结果。导出过程中继续编辑时，原任务保持原版本；完成提示“来自 rN，当前工程 rM”。

视频、字幕、工程和检查结果有稳定入口，重新打开可以继续编辑。用户最终审片接受与程序检查分别记录。

### 5.5 贯穿验收示例

设计样例：用户提供六分钟产品讲解，要求约一分钟、保留产品名和使用限制。Agent 选取“问题—操作—结果—限制”并指出可能的时长冲突。用户手动修正产品名字幕，再让 Agent 缩短开头五秒。Agent 保留纠正和限制说明，工作台显示差异并允许撤销；导出与检查绑定相同版本。该样例是测试目标，不是真实运行报告。

## 6 工作台详细需求

### 6.1 页面与信息组织

| 区域 | 首版内容 | 关键交互与状态 |
| --- | --- | --- |
| 项目与作品入口 | 最近项目、可重开工程、已发布产物 | 区分项目与某次导出；显示版本和检查状态 |
| 素材区 | 文件、规格、转写状态、异常、来源 | 加入素材、定位缺失媒体、跳转原素材位置 |
| 预览区 | 工程预览、播放位置、来源回看 | 区分工程预览和已导出成片，显示所属版本 |
| 片段列表或基础时间线 | 顺序、区间、来源、选中状态 | 选择、删除、排序和裁剪；可先用列表实现完整行为 |
| 字幕与转写 | 原始识别、纠正文本、成片字幕 | 跳转播放、纠错、显示不确定时间；不将纠正写回原始识别 |
| Agent 区 | 当前要求、修改目标、提案、结果和缺口 | 发送选中对象，定位受影响区域，继续修改 |
| 任务区 | 排队、执行、检查、失败与取消 | 查看阶段、日志摘要、重试；未知进度不伪造百分比 |
| 版本与交付区 | 差异、历史、恢复、输出规格、产物 | 恢复旧内容产生新版本；旧成片仍保留归属 |

可以复用 DSH 现有对话和任务区域，避免强行再建重复界面。具体布局在 M0 联合小样中验证；这里规定行为与信息，不冻结像素布局。

### 6.2 关键状态

空项目给出导入入口；处理中说明阶段和是否可继续编辑；分析不足可回查或人工标注；能力缺失给出设置与替代方案；编辑冲突保留原提案并提示刷新；取消中与已取消分别显示；恢复核对中不伪称完成。

### 6.3 可用性要求

核心操作有清楚名称、可见焦点与键盘可达入口。状态不能只靠颜色区分。耗时任务不阻塞全部页面；播放器、文本和选中状态相互对应。设置使用简明解释，模型、依赖和凭据细节按需展开。

## 7 Agent 行为需求

### 7.1 能力与证据

| 编号 | 行为 | 产出与验收重点 |
| --- | --- | --- |
| AG-01 | 理解要求 | 简报区分明确要求、默认值、推断与待定冲突 |
| AG-02 | 评估素材 | 摘要、候选、来源时间、质量问题和缺失信息可回查 |
| AG-03 | 判断和组织内容 | 内容顺序与保留删除有简短理由，不只按静音机械切分 |
| AG-04 | 选择 Skill 与能力 | 路由依据任务与就绪状态；缺能力时不假装执行 |
| AG-05 | 执行与等待 | 使用共同编辑入口和异步任务，区分提交、运行与验收完成 |
| AG-06 | 接续人工编辑 | 读取最新版本，限定范围，保留纠正和其他已接受修改 |
| AG-07 | 检查并修正 | 对照真实产物定位问题；修改有范围，有次数与成本记录 |
| AG-08 | 整理交付 | 说明版本、产物、检查结论、待审片项及已知限制 |
| AG-09 | 记录反馈 | 区分本次修正、明确长期偏好和不确定倾向 |

### 7.2 决策原则

必须保留项、事实与语义完整性优先于未经明确授权的时长压缩。产品名称、参数、条件与否定表达不得随意改写。素材不够时说明需要补充的内容，可以给可行替代方案。

Agent 可以组合多个 Skill，不要求每次从导入到渲染全跑一遍。已经有效的分析可复用；修改文字时只重做受影响部分，必要时再执行对应预览或导出。

### 7.3 失败处理与停止条件

工具失败先区分输入、配置、依赖、时间映射、内容判断、版本冲突和执行失败。能够在已授权范围内修复的继续推进；依赖不满足或核心要求冲突则给出明确下一步。

修正循环有可配置次数、时间或成本上限，达到上限提供当前可用版本、失败证据与待决定项。上限是运行保护，不能把未完成任务标成通过。

素材中的字幕、网页文字和参考视频内容只作为待分析数据，不能自行变成控制 Agent、执行命令或改写用户要求的指令。

## 8 Skill 产品架构

### 8.1 三类 Skill

~~~text
同一视频 Agent
├─ 主 Skill：video-editing
├─ 通用流程：footage-intake / revise-edit / render-qa
└─ 专项方法：talking-head-roughcut / 后续卡点、教程、访谈、Vlog等

共用项目、选择上下文、编辑提案、能力工具、任务、版本与产物。
~~~

这些是职责层级，不代表运行时必须采用三层目录或另开子 Agent。具体 DSH 发现方式见技术手册。

### 8.2 首版五个 Skill

| 名称 | 触发与输入 | 功能与产出 | 产品边界 |
| --- | --- | --- | --- |
| video-editing | 新建或继续视频任务；当前项目、目标、技能与能力摘要 | 整理简报、选择组合、协调范围与冲突、推进验收交付 | 保持通用，不内置全部口播或卡点细节 |
| footage-intake | 新素材加入、分析失效或信息不足 | 检查素材、组织转写与按需画面、形成摘要和缺口 | 不对所有素材无差别运行全部模型 |
| revise-edit | 局部反馈、选中对象、最新项目与已接受修改 | 确定目标、保护其他修改、形成局部提案 | 不默认重做整片，不绕过版本校验 |
| render-qa | 预览或导出产物和对应清单 | 组织文件、内容和人工审片检查，形成问题与修正建议 | 技术探测由工具执行，待人工判断项保留 |
| talking-head-roughcut | 讲话内容占主导，已有转写和目标 | 选择、去重、处理停顿、组织顺序、保护完整语义 | 是首个专项，不能成为所有视频的强制入口 |

### 8.3 调用、组合与新增

主 Skill 提供选择规则，Agent 按需读取通用与专项正文。分析得到简报；涉及编辑则形成统一提案，包含项目、基准版本、稳定目标、候选操作、来源证据、保护范围与未决问题，由共同编辑服务校验应用。

组合时每个方法有明确范围。例如口播方法组织讲解，卡点方法只处理指定产品展示镜头；卡点不得截断受保护的语句。方法切换后读取当前工程，不恢复先前旧快照覆盖人工操作。

新增 Skill 应有可发现的名称与说明、适用和不适用条件、所需能力、作用范围、输入输出和独立验证任务。新增 Skill 提供方法；缺少节拍分析、视觉或渲染能力时，还需接入相应工具。

### 8.4 后续 Skill 规划

| 类别 | 名称 | 简要功能 | 前置能力 |
| --- | --- | --- | --- |
| 通用 | reference-analysis | 对标结构、节奏和风格分析，说明适用条件 | 可访问参考、转写、镜头和必要画面/音频分析 |
| 通用 | media-discovery | 找对标或补充素材候选，保留来源与用途 | 搜索提供方、获取、元信息和素材入库 |

## 10 对标搜索、分析与学习

### 10.1 对标功能分层

| 环节 | 输出 | 产品要求 |
| --- | --- | --- |
| 搜索候选 | 链接、来源、匹配理由、可访问状态 | 平台能力分开验证，用户能选择候选 |
| 获取媒体 | 文件/字幕/元信息及来源引用 | 链接能打开不等于能够获得可分析媒体 |
| 分析参考 | 开头、结构、镜头、字幕、音乐等特征与时间证据 | 观察、推断和不确定结论分开 |
| 应用参考 | 对自己素材可采用的结构、差距和剪辑提案 | 不凭空假定已有所需镜头，不照搬所有风格 |

先验证用户提供参考文件的分析与应用，再发展主动搜索。yt-dlp 等获取工具不能代替候选搜索；参考资料和将进入成片的补充素材要区分用途并保留来源。

### 10.2 学习能力的三个层次

| 层次 | 需求与阶段 | 验收 |
| --- | --- | --- |
| 当前任务适应 | P0，依据反馈调整当前工程 | 后续修改体现反馈且不破坏保护范围 |
| 跨项目偏好 | 后续，用户确认的字幕、术语、节奏和输出习惯 | 可查看、编辑、删除；项目要求优先；减少重复说明 |
| 方法优化 | 后续，离线提出并比较 Skill 或规则改进 | 固定任务、保留任务和回退记录，不能自动覆盖生产方法 |

保存聊天和历史不等于可靠长期学习。一次撤销不自动形成永久偏好；参考结构相似也不等于已经学会作者风格。

### 11.1 首版固定验收场景

| 编号 | 场景与通过条件 |
| --- | --- |
| AC-01 | 页面与真实 Agent 读取同一工程，projectId、revision、素材与对象引用一致 |

### 11.2 质量、体验与业务指标

建立约 12 至 20 个明确要求的任务，覆盖首版三类素材及失败路径；开发样例与未参与调优的保留任务分开。先记录基线，再确定可接受阈值；不填入未经测试的成功率或响应承诺。

| 指标 | 统计要求 |
| --- | --- |
| 可交付任务比例 | 分母为约定支持范围内全部验收任务，失败和需人工补救分别记，不只统计成功样例 |
| 关键内容保留 | 对标注保留项逐项检查来源和成片，单独报告否定、数字、实体错误 |
| 转写与对齐 | 记录一般错误、关键错误、时间精度和缺失覆盖，写明分母与标注方法 |
| 局部修改质量 | 目标是否达成，受保护与非目标内容是否意外变化 |
| 人工返工 | 完成同类任务需要的修正次数和修正类型 |
| 耗时与成本 | 分析、模型、预览、渲染和人工等待分阶段记录，包含环境和计费依据 |
| 稳定性 | 重试、取消、重开、旧版本与任务恢复的真实结果 |
| 人工观感 | 语义自然、剪切节奏、字幕、音画对应，统一量表并保留意见 |

文件能解码、内容满足要求、用户认为可用分开评估。字幕出现产品名不能独立证明原声被保留。

## 12 非功能要求与数据原则

| 类别 | 需求 |
| --- | --- |
| 一致性 | 唯一工程事实来源，UI 与 Agent 共享命令、版本和变化通知 |
| 可恢复性 | 工程、任务和必要证据落盘；会话消失不能使项目事实丢失 |
| 性能与成本 | 长任务异步，摘要与按需读取，记录真实时延与资源；未知进度明确表示 |
| 媒体正确性 | 时间基准、字幕实例、音画映射与输出规格可验证 |
| 可维护性 | 方法、业务服务、DSH 接线、能力实现分工；精确依赖和兼容范围有记录 |
| 数据处理 | 本地工程与模型运行位置分别说明；配置能力时展示媒体/文本是否发送外部服务 |
| 凭据与路径 | 凭据由配置或 DSH 管理，不写入 Skill、工程或日志；文件访问限定项目与明确配置范围 |
| 数据保留 | 原素材只读，缓存、任务中间文件、成片与历史分别管理；清理显示影响，不破坏仍被引用内容 |
| 可迁移性 | 明确媒体为引用或副本；工程重定位和 schema 升级留兼容记录 |

本地工作台不代表所有模型都本地运行。首版不预先承诺完全离线、跨机器无依赖重开或所有外部工程无损互换。

## 13 后续路线与开发阶段

### 13.1 首版 M0—M3

| 阶段 | 产品交付 | Agent / 工作台 / Skill 如何共同推进 |
| --- | --- | --- |
| M0 选型与联合小样 | 编辑路线比较、真实 DSH 调用、最小页面、异步样例与 ADR | 明确任务与 Skill 契约；以真实 Agent 和页面共同验证，不先做完整口播方法 |
| M1 最小共同编辑 | 同工程、局部修改、版本、撤销与重开 | 主 Skill 和局部修改最小可用；其他 Skill 有输入输出草案，随服务联调 |
| M2 真实剪辑闭环 | 中文分析、内容提案、字幕、真实导出与检查 | 逐个完成素材接收、口播、验收方法；同步完善 UI 与工具 |
| M3 首版联合验收 | 五个 Skill 发布、固定任务回归、反馈、作品入口 | 验证选择、组合、切换与缺能力；AC-01 至 AC-10 全部有真实记录 |

阶段以行为验收推进，日历排期在 M0 获得运行和集成证据后估算。M3 是稳定与发布阶段，不能到 M3 才开始编写和调用 Skill。

### 13.2 后续按任务扩展

先强化教程产品与访谈，再结合需求增加卡点、Vlog、搜索与风格化制作；外部工程和长期偏好按实际用户价值独立推进。每次扩展包含专项方法、所需能力、工作台可检查结果及失败路径。

不同时建设所有后端、所有编辑类型和自己的通用插件市场。首版底座预留共同接口，具体扩展逐项交付。

## 15 风险、待决事项与变更管理

| 问题 | 验证与决定方式 |
| --- | --- |
| 底座是否真正支持共同编辑 | 同素材跑通人工纠正、Agent 接续、冲突、导出与重开，再决定 |
| 中文识别和时间精度不足 | 按关键实体、数字、否定和切点评估；纠正、热词或对齐路径按证据选择 |
| 预览与导出效果不同 | 固定依赖与规格，检查相同版本的真实画面、字幕和声音 |
| 方法增加导致 Agent 乱选 | 简洁目录、清楚触发与范围、能力门控、专项路由样例 |
| 任务显示成功但产物错误 | 执行完成与验收成功分开，产物绑定不可变输入 |
| 过早实现未来能力 | 后续保留契约和验证计划，按完整任务上线 |
| 复用与分发条件不适合 | 决定采用前核对具体源码、依赖、模型和分发条件，记录 ADR |

主要待决记录：ADR-001 主编辑底座；ADR-002 媒体、预览与导出；ADR-003 中文转写与对齐；ADR-004 DSH 和运行依赖；ADR-005 存储与原子提交。开发组织和 Skill 发布细节由技术执行手册承接。
