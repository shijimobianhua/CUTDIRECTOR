# M4 · CUTDIRECTOR 自有剪辑 Agent

M4 的主交付是 CUTDIRECTOR 的剪辑运行时。DSH 提供工作台宿主、插件和可选的原生只读分析。独立本地入口和 DSH 内嵌入口调用同一个本地 writer 和剪辑 Agent。模型端点可在后端配置，在工作台选择。

## 运行职责

- 本地 Agent 固定工程、选区、模型和 revision，根据阶段构造简报并驱动有限步的模型循环。模型只能请求已注册的只读工具或提交结构化提案。用户逐项确认后，运行时通过既有 writer 提交编辑或发起渲染。
- writer 继续负责 CAS、命令幂等、历史、回退和渲染发布。现有工程数据和旧 API 兼容。会话、授权待执行记录和偏好存放在数据根目录的 `_agent` 中。
- 当前支持已有片段修剪、字幕纠正、证据驱动的已有片段粗剪，以及检查、预览、导出。中段删除与多区间抽取需要新增片段能力。真实 ASR 由既有本地 provider 提供，也可用 SRT。
- DSH 原生分析需要单独启用和验收。通过本地受认证的桥创建专用 Session，安装拒绝工具执行的作用域守卫，只提交显式批准的证据页。分析失败时主循环仍可继续。

## 契约

| 接口 | 行为 |
| --- | --- |
| `GET /agent/models` | 已配置模型及视觉、委派能力 |
| `POST /agent/run` | 使用客户端生成的 UUID 发起幂等运行，包含请求、工程、选区、模型、模式和可选前序运行 |
| `GET /agent/run?id=…` | 读取指定运行的进度、待确认提案、错误或版本绑定结果 |
| `GET /agent/events?id=…` | SSE 快照，运行停止推进后结束流 |
| `POST /agent/approve` | 使用运行 ID 与提案 ID 确认精确动作 |
| `POST /agent/cancel`、`POST /agent/resume` | 取消尚未提交的操作，或通过持久化检查点显式恢复 |
| `GET/POST /agent/memory` | 查看案例和偏好，批准、撤销或扩大一条已确认规则的作用域 |

仅提案产生可审阅结果且不可从该运行提交。运行中工程切换或版本变化会使旧动作失效。模型请求预算为 8 步，渲染运行可消耗两次尝试。网络重放复用原命令标识，用户显式重试失败渲染消耗新预算。文件、内容、人工 QA 分别记录。

专项策略和协议随本地版本发布。字幕、转写及 DSH 建议都是有来源的数据。用户显式填写的保留项参与剪辑前校验。用户只更新一个意图字段时，前序运行中其他确认过的字段继续有效。接受并标注为偏好的人工反馈，还需在工作台单独启用；回退和人工覆盖只形成案例。启用的规则可撤销，跨项目使用需要显式操作。

## 发布验收

1. 运行 `node --test --test-timeout=60000 test/agent.test.cjs test/single-page.test.cjs` 和 `node tools/m3-acceptance/run.cjs`。测试需覆盖仅提案、重复确认、切换端点、版本冲突、恢复、取消、偏好撤销和只读分析。
2. 按运行指南配置两个端点，分别在独立本地工作台和隔离 DSH profile 跑真实口播。记录目标、提案、执行前后的 revision、预览和导出 ID，以及人工审片反馈。
3. 用固定样片运行同模型的基础策略、专项策略、启用偏好三组对照。记录保留项命中、时长误差、越权写入、工具调用量和人工返工。样片资料与用户反馈仅进入授权的模型端点。
4. 用真实 DSH 版本验证委派守卫能拦截剪辑写入、通用文件工具和 Shell 调用。验证断开 DSH 后仍能剪辑。单独验证视觉模型实际收到关键帧并检查输出质量。

配置、回退和评测说明见 [M4-running.md](../M4-running.md)。
