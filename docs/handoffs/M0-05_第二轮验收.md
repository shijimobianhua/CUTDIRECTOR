## 4. G0-1 适配器 spike

代码（非产品代码，仅证据）：

- [writer-adapter.js](../../test/spikes/g0-1/writer-adapter.js)
- [preflight.js](../../test/spikes/g0-1/preflight.js)
- [README](../../test/spikes/g0-1/README.md)

适配器契约：

```text
PUT /project
{ projectId, baseRevision, commandId, project }
-> 200 { ok, projectId, revision, commandId }
-> 409 { code: REVISION_CONFLICT | COMMAND_ID_CONFLICT }
-> 400 { code: VALIDATION_ERROR | COMMAND_ID_REQUIRED | BASE_REVISION_REQUIRED | FORCE_FORBIDDEN }
```

实现要点：

- 所有写请求进入单进程队列；
- `baseRevision` 必填且必须等于当前 revision；
- 客户端自报 `project.revision` 不被信任，由适配器分配 `current+1`；
- `commandId` + 规范化摘要做持久账本；同 ID 同内容返回原结果，同 ID 异内容 409；
- `force` 一律 400；
- 校验 `name`/`clips`/`media`；
- 启动用 lock 文件拒绝第二个适配器；
- 提交后发 SSE `{eventId, projectId, newRevision, commandId, affectedIds}`。

日志：[2026-11-04_G0-1_adapter_preflight.log](M0-T2_复跑日志/2026-11-04_G0-1_adapter_preflight.log)、[replay](M0-T2_复跑日志/2026-11-04_G0-1_adapter_replay.log)

| 用例 | 结果 | 判定 |
| --- | --- | --- |
| T01 并发同基准 | 一个 200/r1，一个 409 | **通过** |
| T02 旧基准 | 409 | **通过** |
| T02 伪造高版本 | base=1 时适配器分配 2，客户端 100 被忽略 | **通过** |
| T02 缺字段 | 400 VALIDATION_ERROR | **通过** |
| T04 同 ID 同内容重放 | 200，`replayed:true`，revision 不变 | **通过** |
| T05 同 ID 异内容 | 409 COMMAND_ID_CONFLICT | **通过** |
| T06 force | 400 | **通过** |
| T07 事件 | 收到 eventId/projectId/newRevision/commandId/affectedIds | **通过（最小）** |
| T12 第二适配器 | 拒绝启动：“another adapter is running” | **通过** |

### 4.1 这证明了什么

- **适配器层**可以作为唯一 writer：baseRevision、commandId 幂等、拒绝 force、单实例、事件都成立。
- 可以支撑 M0-T3 的“页面与 Agent 经同一提交入口读写同一 projectId/revision”。

### 4.2 这没证明什么

- FableCut 原生 HTTP、MCP、UI、项目切换/历史/启动恢复仍然可以绕过适配器直写；本 spike 没有修改 FableCut。
- 适配器账本只是本地 JSON，没有 fsync/原子写；进程崩溃后的账本一致性未测。
- 只支持单项目 `P`；项目切换/新建/删除/历史恢复未接。
- 没有 DSH 插件、Client 面板、Skill 加载；这些是 M0-T3。
- 没有真实页面/Agent 联调；没有 r1/r2 导出；没有字幕映射。

**结论：G0-1 的“窄口径”通过（适配器唯一 writer），完整 FableCut 收敛未通过。** M0-T3 只能按窄口径做：适配器为唯一 writer，FableCut HTTP 仅作引擎，不启动 MCP、不使用 FableCut 原生 UI 写工程，单项目。
