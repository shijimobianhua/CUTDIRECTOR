## 3. T-A 口播 / 产品讲解

```text
taskId: T-A
来源与 hash: A-01 / 77849adb27faf0f26cc166219d4072ff9f67216c0a82d9caac67c67fa843df77
用户要求: 从原始口播中做出约 1 分钟版本
允许偏差: ±__ 秒（待用户确认）
保留项及来源: 产品名、参数/数字、否定表达、条件与限制说明（待用户逐项给出）
预期保护区域: 含保留项的句子及其直接上下文；不得为时长删除或改写语义
失败注入（后续补）: 旧 baseRevision 提交、字幕纠正后重排、保留句被裁切
验证方式: 成片与字幕逐项核对保留项；选段可回查来源区间；时长偏差在允许范围内
人工量表（后续补）: 语义完整性、否定是否削弱、限制说明是否保留、节奏是否自然
```

验收要点：

1. 四条保留项逐项有“来源区间 → 成片区间”的对应；
2. 否定句不得被改成肯定或模糊表达；
3. 数字/型号不得四舍五入或改写；
4. 限制说明不得因压缩时长被整体删除；
5. 输出 MP4 可解码、SRT 为 UTF-8、工程可重开。

## 4. T-B 教程 / 产品操作

```text
taskId: T-B
来源与 hash: A-02 / 待探测
用户要求: 保留关键步骤与结果，形成可看懂的教程片段
允许偏差: 步骤数不减少；总时长待用户确认
保留项及来源: 用户标注的关键步骤、操作结果、必要讲解
预期保护区域: 关键操作画面及其对应讲解；不能只剩讲解没有操作
失败注入（后续补）: 步骤顺序颠倒、结果画面丢失、讲解与画面对不上
验证方式: 步骤清单逐项对照成片；缺失/跳过步骤明确报告；画面与讲解时间对应可回查
人工量表（后续补）: 可跟随性、结果是否可见、是否产生误导
```

验收要点：

1. 每个关键步骤在成片中可见，顺序正确；
2. 每步的结果画面存在，不能只留操作不留结果；
3. 讲解与操作的时间对应可回查；
4. 缺失步骤必须报告，不能用字幕或旁白“补写”未拍到的步骤。
