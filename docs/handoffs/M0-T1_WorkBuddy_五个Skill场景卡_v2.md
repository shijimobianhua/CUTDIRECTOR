## 一、职责边界总表

- video-editing（主）：选组方法、协调冲突、组织交付；不内置专项细节。
- footage-intake（通用）：查素材、组织转写与画面、成摘要；不无差别跑模型。
- revise-edit（通用）：读最新版本、限定目标、护非目标、成局部提案；不重做整片。
- render-qa（通用）：按 manifest 查文件、内容与待审项；不只看退出码。
- talking-head-roughcut（专项）：按讲话选段、去重停顿、组顺序、保语义；不成强制入口。

## 二、五张场景卡

成功样例均为设计样例，尚未运行；实测须登记夹具、版本、请求、保护项与断言。

### video-editing

- 一句话功能：主协调者：整理简报、选组方法、协调范围冲突、推进可检查交付。
- 触发：应——新建/继续视频任务作入口、选组方法、协调冲突；不应——执行专项细节，已加载未变不重载。
- 前置输入：目标、素材/工程引用与保留项；首次无 projectId，经项目创建 [产品服务能力，M1 契约待定] 补齐。
- 工作步骤：①首次经项目创建取身份；继续读项目头；②简报分明确要求、默认值、推断与冲突；③新素材/分析失效→footage-intake、口播→专项、局部反馈→revise-edit、产物→render-qa，已有分析可复用；④核心冲突或放弃保留项等用户决定，「先给方案」到提案即止；⑤编辑成统一提案由主流程唯一一次提交；render submit/job control 查询/取消，产物交 render-qa。
- 保护与冲突：保留项与语义完整性优先于未授权时长压缩；缺能力或失败不假装完成并说明缺口。
- 所需能力：能力目录、提案校验/应用、渲染提交、任务控制；项目创建为产品服务能力。
- 输出类型：简报、统一提案或提交回执（newRevision、diff、affectedIds）。
- 成功样例：SC-VE-01（AC-06/07/10），设计样例，尚未运行：六分钟讲解剪约一分钟、留产品名与限制；断言：保留项有来源、冲突未决不放弃。
- 反例：全走口播；无 projectId 即拒；未加载即声称；要方案却提交；重复应用。
- 人工检查点：执行前——核心取舍或放弃保留项需用户决定；交付后——审片节奏与自然度。
- 与其他 Skill 的边界：管选择、授权、唯一提交与任务闭环；不代做素材/产物检查、局部提案、选段。
- 来源：PRD §8/§5/§7.1；手册 §5.1/§8.2/8.7；总览 §2。
- 假设与待确认：[推断] M1 主 Skill 只需最小协调规则；[推断] 入口加载保证需真实轨迹验证。

### footage-intake

- 一句话功能：素材接收与初查：查可用性、组织转写与按需画面、成可回查摘要与缺口。
- 触发：应——未入库素材、新素材或分析失效；不应——已入库且分析有效、无需补证据。
- 前置输入：素材路径/URI 或 assetId 与保留项；未入库时取 assetId 与 hash；分析失效才重做。
- 工作步骤：①未入库素材经 media intake 探测（容器、编码等），不凭扩展名判断；②查 VFR、旋转、缺音轨与中文路径，需规范化时生成工作媒体并留映射；③按目标提交转写或分析（analysis submit/read），读到完成结果才作证据；④标明时间精度与不确定项，明确引原素材或工作媒体，句级不声称精确切词；⑤按需读画面（media inspect）只取核对所需帧；⑥成可回查摘要并报缺口与阻断范围。
- 保护与冲突：原素材只读；转写与字幕纠正分开保存，纠正不写回原始识别；静音/缺音轨不强行当口播。
- 所需能力：媒体导入/探测与规范化、分析提交/读取；按实际返回区分 available、notConfigured 等状态。
- 输出类型：观察/简报（素材身份、媒体与分析引用、时间精度、摘要与缺口）；不改时间线。
- 成功样例：SC-FI-01（AC-06/09），设计样例，尚未运行：未入库竖屏 VFR 录像带旋转；断言：原文件 hash 不变、工作媒体有独立身份与映射。
- 反例：以未入库为由拒绝；把完整日志塞给模型；句级当字级切点；丢原素材映射；只提交分析就报已有结果。
- 人工检查点：执行前——影响素材含义或支持范围的取舍需确认；结果复核——抽查关键实体与否定词。
- 与其他 Skill 的边界：管导入、探测与证据编排；不做最终选段、不改时间线。
- 来源：PRD §8.2/§3.3；手册 §8.2/§4.2；总览 §4.2。
- 假设与待确认：[推断] 首版转写只接一条中文路径；[推断] 画面读取粒度需 M2 校准。

### revise-edit

- 一句话功能：局部修改：读最新版本、解析指向或选中对象、限定范围、护非目标修改、成局部提案。
- 触发：应——选中对象、明确范围或可结合工程理解的局部指向；不应——整片重组、歧义无法消除时先澄清。
- 前置输入：projectId 与修改目标；有选择时含 observedRevision、稳定对象 ID 与范围坐标系；无选择先解析指向。
- 工作步骤：①project read 读最新工程，不从旧聊天推测；②校验选择或解析指向；基准过旧或对象变更先读稳定对象映射；③明确目标、坐标系与作用范围，只要方案时不提交；④非目标纠正与已接受修改标为保护；用户明确要改的可改；⑤成局部统一提案交主流程唯一一次校验/提交；重排/裁剪须验证来源与纠正映射，不可靠则拒绝；⑥传输重试同 commandId 同 payload，版本冲突重读成新命令。
- 保护与冲突：非目标纠正与已接受修改必须保留；为缩短开头不删后面的限制说明。
- 所需能力：项目与历史读取、选择解析、提案校验/应用；缺必要校验只成带缺口提案。
- 输出类型：统一提案（待提交），含目标、保护范围与未决项；提交后关联服务回执。
- 成功样例：SC-RE-01（AC-01–05），设计样例，尚未运行：产品名纠正已存 r13，Agent 有 r12 旧提案，用户要求「缩短开头五秒」；断言：开头缩短、纠正与限制说明保持。
- 反例：旧基准覆盖；只改版本号重放；清楚指向也强制补选；为缩短删限制说明；映射失败仍提交。
- 人工检查点：执行前——范围歧义或与保留项冲突时澄清；结果复核——目标生效、非目标与纠正保持。
- 与其他 Skill 的边界：不做整片选段、素材检查与产物验收（交专项/footage-intake/render-qa）。
- 来源：PRD §8.2/§5.3；手册 §8.2/§4.4/§9.2；总览 §4.3/4.4。
- 假设与待确认：[待验证] 字幕映射最小契约 M1 定；[待验证] 选择上下文映射 M1 联调。

### render-qa

- 一句话功能：产物验收：按 renderManifest 查文件、内容与人工审片三层，成问题与修正建议。
- 触发：应——预览/导出产物就绪后核对版本与清单；不应——替代渲染或改时间线；不用最新工程验旧成片。
- 前置输入：验收需 renderManifest（projectId、revision、快照与依赖 hash）与产物引用；缺则只给阻断报告。
- 工作步骤：①读清单、产物与任务状态，未生成/失败/取消/状态不明时输出阻断，中间文件不当成品；②文件层（artifact verify/read）实际解码、帧数、画幅、音轨与字幕产物；③内容层按保留项与来源核对语义、句子、画面；④r1 渲染期间编辑到 r2 时只用 r1 冻结清单，报告标「来自 r1，当前 r2」；⑤缓存复用验证存在、完整、hash 与适用条件并建立验收引用；⑥列待人工项；报告逐项记通过/失败/未验证/待审片，带证据与建议。
- 保护与冲突：未完成文件不进作品库；探测由工具执行，Skill 不改产物、清单或时间线。
- 所需能力：产物探测与读取、清单读取、任务状态读取；缺探测能力不能断言合格。
- 输出类型：检查/阻断报告（含版本、产物引用与逐项结论）；修正交主 Skill/revise-edit。
- 成功样例：SC-RQ-01（AC-07/08/09），设计样例，尚未运行：r1 冻结 manifest，期间编辑到 r2；断言：报告仅属 r1、清单不因 r2 改变。
- 反例：用 r2 验 r1；产物未生成不报阻断；字幕出现产品名就断言原声保留；未审片却标已接受。
- 人工检查点：技术检查先由工具给证据；人工审片重点为语义、节奏、音画与字幕可读性。
- 与其他 Skill 的边界：检查产物与证据、成验收/阻断报告；不执行渲染/取消、不改工程。
- 来源：PRD §8.2/§5.4；手册 §6.1/§5.1；总览 §5.1/§8.1。
- 假设与待确认：[推断] 文件层容差待 ADR-002 细化；[推断] 人工审片量表 M3 固定。

### talking-head-roughcut

- 一句话功能：口播粗剪专项：按讲话内容选段、处理重复与停顿、组顺序、保护否定/数字/条件/限制说明。
- 触发：应——以讲话内容为主；教程/产品讲话部分可复用并保护操作画面；不应——非讲话主导视频强行进入、无转写直接生成选段。
- 前置输入：projectId 与版本、讲话范围、可回查转写或标注、目标时长及偏差。
- 工作步骤：①读工程、讲话范围、转写/标注与目标，确认版本与来源坐标，证据不足先补；②识别可用段、重复与长停顿，区分赘述与强调，不只按静音机械删；③逐项保护否定、数字、条件与限制说明；④按表达目标组顺序成连贯结构与候选片段，重排后核对指代；⑤算预估时长并列来源区间与依据，时长与保留冲突给取舍、不暗中删保留项；⑥成统一提案交主流程唯一提交，提交后核对差异，按需预览交 render-qa。
- 保护与冲突：保留项优先于时长压缩；不截断句意、不照搬示例时间码；组合时只处理讲话范围。
- 所需能力：工程与转写/标注读取、按需回看、提案校验；选段取舍由 Agent 判断。
- 输出类型：统一提案（待提交），附选段顺序、来源与保留依据；证据不足返回候选与缺口。
- 成功样例：SC-TH-01（AC-06/09），设计样例，尚未运行：六分钟讲话，含数字、否定与使用限制；断言：保留项逐项可回查、不误删否定/数字/限制。
- 反例：为时长删使用限制说明；截断否定句意或改变数字含义；照搬示例时间码；只留讲解删受保护画面。
- 人工检查点：执行前——核心表达、保留项或时长不可兼容时需用户决定；结果审片——保留内容与节奏自然度。
- 与其他 Skill 的边界：只管讲话范围内的选段；补证交 footage-intake、调整交 revise-edit、检查交 render-qa。
- 来源：PRD §8.2/8.3/§5.5；手册 §8.2/8.7/8.8；总览 §2。
- 假设与待确认：[范围说明] 适用于讲话主导片段，首版仍覆盖 PRD 约定范围；[待验证] 重复与切点判断需 M2 校准。

## 三、跨 Skill 的组合与冲突规则

1. 选择顺序：任务开始或恢复先加载 video-editing，同一 Agent 按缺失前置选方法；首次项目创建为产品服务能力 [产品服务能力，M1 契约待定]，未入库素材经 media intake 补齐；不假设正文自动注入。
2. 分析与编辑分离：footage-intake 出观察、render-qa 出检查/阻断报告，不改时间线；revise-edit/专项成统一提案（含项目、基准、范围、操作、证据、保护与未决），主流程唯一一次提交；版本、幂等、映射由服务保证。
3. 组合：先定分工与保护范围；第一份提交后读新 revision 与对象映射再核对第二份，冲突返回协调；口播整理讲解后第二专项只处理指定 B-roll。
4. 切换：沿用当前工程与已接受编辑，读最新版本、复用有效分析，不恢复旧快照；Skill 读取是获取指令，不等于函数调用。
5. 冲突：争同一对象不并行盲用；保留项与语义完整性优先于未授权时长压缩；核心取舍等用户；重试同 ID 同内容，版本冲突重读成新命令。
6. 能力门控：按能力目录实际状态执行，缺失不一律写 notConfigured，缺必要能力只停受影响步骤；仅一个口播专项时用夹具验证选择/组合/切换/缺能力四类（AC-10），夹具通过只证明接口。
7. 交付闭环：主流程经 render submit 绑定冻结清单，查询/取消/核对，不把提交当完成；render-qa 就绪给结论、缺失给阻断报告；主 Skill 引用报告交付。

来源：PRD §5/§8.3/§11.1；手册 §4.3–4.5/§5/§6/§8.8/§9.2；总览 §2/§5。
