# M0-T2 评审口径（Codex 比较与证据规则）

- 版本：1.0
- 日期：2026-11-03
- 状态：**冻结**——Codex 开始后不再改；确需修改时记版本、原因与影响
- 适用：M0-T2 候选编辑底座只读预研
- 使用者：Codex（产出证据）、DSH（复核与最终选型）
- 配套：`Video-agent执行包/02_给Codex_M0-T2_候选底座只读预研.md`、技术手册 §3.1、总览 §3.1、PRD §12

## 0. 一句话

本表不评“项目好不好”，只评：

> 它能不能成为 Video-agent 的权威编辑底座，或至少成为 M0-T3 用真实页面与 Agent 验证共同编辑的对象？

## 1. 适用与非目标

**适用**

- 对候选做只读代码审计与最小可复现运行；
- 判断工程写入口、事务/版本、字幕/时间、预览/导出、Windows 依赖与复用条件；
- 最多推荐两条进入 M0-T3。

**非目标**

- 不做产品实现、不写插件/Client/Skill、不改产品仓库；
- 不 fork 候选、不深度改候选核心代码；
- 不替 DSH 做最终选型，不判定 AC 通过；
- 不给法律结论，只记录许可证事实与待确认项。

## 3. 状态定义（唯一合法取值）

| 状态 | 含义 | 能否作为通过依据 |
| --- | --- | --- |
| **满足** | 有源码或实际运行证据，覆盖该维度全部必需项 | 是 |
| **部分** | 有证据但缺项、需适配或仅支持子集；缺项已写清 | 有条件（缺项须进入 M0-T3 验证清单） |
| **不满足** | 有证据表明缺失，或与要求冲突 | 否 |
| **未验证** | 未取得可复现证据；**不等于不满足** | 否，不得写成“满足” |
| **阻断** | 已证实的硬性阻止：装不上/起不来/无写入口/无接入面/许可证与用途冲突 | 淘汰 |

禁止：

- 用 1—5 分、百分比、加权总分代替状态；
- 用“应该可以”“看起来支持”“README 说支持”得出“满足”；
- 把“未验证”汇总成“通过”。

### 4.2 逐维度判定下限

#### D1 共同读写（G1）

- **满足**：页面写入口与外部写入口最终调用同一权威状态；源码定位到文件与函数；有 change event 或可订阅的变化通知。
- **部分**：只有单一入口，外部入口需新增但工程结构允许；或通知需补。
- **不满足**：页面直接改本地 UI 状态；无外部入口；需要另建第二份工程。
- **阻断**：工程格式不可读写/加密/云锁定，无法接入。
- **必须特别检查**：是否存在两个可独立修改的权威工程；页面是否绕过统一服务直接写状态。

#### D2 事务与版本（G1）

- **满足**：有 revision/baseRevision 检查；旧基准被拒绝；有幂等键；提交为原子（或每项目单写队列）。
- **部分**：有版本号但无冲突拒绝；或有事务无幂等；缺项须列入 M0-T3 验证。
- **不满足**：后写覆盖、无版本概念。
- **必须特别检查**：同一旧 baseRevision 的两次提交是否都会成功；恢复是否生成新版本。

#### D3 工程能力（G4：重开 + 稳定 ID）

- **满足**：片段、字幕、工程重开、稳定 segment/caption ID 都有数据模型与持久化证据；轨道、基础音频、历史至少可补。
- **部分**：核心四项缺 1 项，或轨道/音频/历史缺 2 项以上。
- **不满足**：无持久化工程；ID 每次重开都变。
- **阻断**：工程不可重开或被云服务锁定。
- **必须特别检查**：同一素材多次出现是否产生不同片段实例；字幕纠正是否与原始转写分离。

#### D4 预览与导出

- **满足**：实际导出成功、成片可解码；预览与导出基于同一工程/revision；有可复现命令。
- **部分**：只能预览；或导出可用但需云端/商业授权/额外服务。
- **不满足**：无导出能力。
- **阻断**：导出依赖不可用的云服务或商业授权。
- **必须特别检查**：导出是否能用同一 manifest 复现；旧版本成片是否会被新工程覆盖。

#### D5 字幕

- **满足**：字幕有独立数据模型；实例关联 segment 与来源词/区间；纠正与原始转写分离；重排/裁剪后可重映射；支持 SRT 导入导出。
- **部分**：扁平字幕轨按成片时间锚定，重排会错位但可补映射层。
- **不满足**：字幕只是烧录文本，无数据模型。
- **必须特别检查**：字幕纠正是否只以成片秒数为键；重排后能否追到相应片段。

#### D6 时间与媒体

- **满足**：能精确表示有理数 fps（含 30000/1001）；区间语义明确（[in, out) 或等价）；VFR、旋转/像素比、音画偏移有处理或明确拒绝与记录；支持非零原点。
- **部分**：用浮点 fps 但可无损换算；无 VFR 处理但有明确转换层与记录。
- **不满足**：以秒级浮点直接切、无时间原点概念。
- **必须特别检查**：29.97 是否用小数近似；帧网格往返是否保持帧号；原素材/工作媒体映射是否可查。

#### D7 DSH 接入

- **满足**：有 Web UI 或可嵌入界面 + HTTP/CLI/进程/服务中的稳定接入面，能在 DSH Host 外被调用。
- **部分**：只有桌面 GUI，但可通过 CLI/文件/本地服务桥接，成本可控。
- **阻断**：纯闭源桌面应用无外部接口；必须云端账号；无法在 Windows 本地调用。
- **注意**：具体插件/Client/Skill 接线在 M0-T3 验证；本维度只判“有无可行接入面”。
- **必须特别检查**：桥接插件是否只适配旧版 DSH；是否只是启动对话，没有可写工程面。

#### D8 Windows 运行条件（G2）

- **满足**：在本机 Windows 11 实际完成安装、构建、启动；Node/Python/FFmpeg/字体/原生依赖可获取；记录耗时与资源。
- **部分**：能启动但缺关键依赖（如 FFmpeg/字体/模型），且有明确补齐路径。
- **阻断**：30 分钟内无法安装/构建/启动；需要管理员权限、云服务或商业授权。
- **必须记录**：操作系统、Node/npm/pnpm、Python、FFmpeg、GPU/内存、安装方式、耗时。

#### D9 复用条件（G3）

- **满足**：已读 LICENSE 实际内容；许可证事实与用户确认的使用/分发意图不冲突；依赖可获取；维护状态有 commit 日期证据。
- **部分**：有约束（如 AGPL/GPL/商业条款）但当前用途可接受，后果已记录。
- **阻断**：许可证与用途冲突且无替代。
- **注意**：不给法律结论；只记录事实 + 待用户/法务确认项。
- **必须特别检查**：模型权重、可执行发行件、混合来源代码是否另有条款。

#### D10 测试

- **满足**：有可运行测试且通过；覆盖写入口、版本或时间中至少一项。
- **部分**：有测试但覆盖不足，或部分失败且原因已记录。
- **不满足**：无测试。
- **未验证**：有测试但没跑。

#### D11 可改造性（G1）

- **满足**：写入口集中；可在不 fork 核心的前提下加统一命令层/适配器。
- **部分**：需浅 fork 或少量核心修改，改动面已写清。
- **不满足**：写入口分散在 UI，需深 fork 才能统一。
- **阻断**：代码不可获取或构建不可复现。

## 5. 硬门与淘汰

| 硬门 | 组成 | 规则 |
| --- | --- | --- |
| G1 权威工程与可控写入口 | D1 + D2 + D11 | 任一“阻断/不满足”→ 淘汰 |
| G2 Windows 可运行 | D8 | “阻断”→ 淘汰；“未验证”→ 进入 M0-T3 前补证 |
| G3 许可证与用途不冲突 | D9 | “阻断”→ 淘汰；“未验证”→ 进入 M0-T3 前补证 |
| G4 工程可重开与稳定对象 | D3 的重开 + 稳定 ID 子项 | “不满足”→ 不能作为权威底座 |

补充：

- 硬门“未验证”不得当成“通过”；必须在推荐文件里写明补证方式与责任人；
- 非硬门维度用于比较与风险记录，不做加权总分；
- 同一维度不同子项可分别标状态，但总状态取最差的关键子项。

## 6. 证据规则

### 6.1 优先级（从高到低）

1. 实际运行过的命令 + 退出码 + 输出日志；
2. 源码中的写入口、事务、版本、通知、字幕/时间实现（文件:行号）；
3. 测试/示例；
4. 官方文档；
5. README；
6. 二手文章 / star 数（只能作线索）。

### 6.2 每条结论必须附

- 候选名 + 固定 commit；
- 证据类型：命令日志 / 源码位置 / 测试 / 文档；
- 具体路径：日志文件相对路径，或 `path/to/file.ts:123`；
- 若为“未验证”：原因 + 下一次验证假设 + 需要的条件。

### 6.3 日志与命名

```text
M0-T2_Codex_证据/
├─ env.txt
├─ commands.md
├─ <候选A>_install.log
├─ <候选A>_build.log
├─ <候选A>_test.log
├─ <候选A>_run.log
├─ <候选B>_...
└─ ...
```

- 日志保留原始输出，不剪裁关键错误；
- `commands.md` 按时间顺序记录命令、目录、退出码、耗时；
- 临时目录路径写入 `env.txt`，便于 DSH 复跑；
- 不提交大媒体；截图只放必要的界面证据。

### 6.4 环境记录（`env.txt`）

```text
OS:
CPU / 内存 / GPU:
Node:
npm / pnpm:
Python:
FFmpeg / ffprobe:
Git:
候选临时目录:
审计开始/结束时间:
```

### 6.5 禁止

- 用 README/star/演示视频作为“满足”的核心证据；
- 把“能启动”写成“支持共同编辑”；
- 只给结论不给日志；
- 为跑起来而改候选核心代码（只允许临时目录最小构建适配，并记录 diff）；
- 使用私有凭据、全局安装、管理员权限。

## 7. 每候选必填记录模板

```text
candidate:
repo:
commit:
commit date:
license files:
package manager:
runtime requirements:
OS tested:
install command:
build command:
test command:
run command:
result:

```

另附：

- 写入口：`文件:行号` + 一句话说明；
- 事务/版本：`文件:行号` + 关键类型/函数名；
- 字幕/时间：数据模型位置 + 是否支持有理数 fps；
- 预览/导出：命令 + 产物路径 + 是否可解码；
- DSH 接入面：Web/HTTP/CLI/进程，各自证据；
- 未验证/阻断：逐条原因。

## 8. 输出文件

只输出三个：

```text
M0-T2_Codex_候选比较.md
M0-T2_Codex_推荐.md
M0-T2_Codex_证据/
```

结构与 `02` §7 一致：

- `候选比较.md`：总表 → 候选 A → 候选 B → 横向结论；
- `推荐.md`：最多两条，每条含理由（≤5，带证据）、最大风险（≤3）、M0-T3 必须验证（3—5 项）、不能假设什么、失败备选；另列不推荐候选与需 DSH 决定的问题（≤5）；
- `证据/`：`env.txt`、`commands.md`、各候选 install/build/test/run 日志。

## 9. 退回标准

出现以下任一情况，M0-T2 产物退回，不进入 M0-T3：

- 推荐超过两条；
- 没有 commit 或没有读许可证文件；
- 只有 README/star/演示视频结论，没有实际命令或源码证据；
- 把“能启动”写成“支持共同编辑”；
- 未验证/阻断项被隐去或写成“通过”；
- 改了产品仓库或写了生产代码；
- 没有证据目录或日志为空；
- 直接给“选某候选”的最终结论，替 DSH 做决定。

退回话术：

```text
这份产物不能进入下一阶段。请只补以下缺口：
1. ...
2. ...
不要扩大范围，不要改产品仓库，不要重写全部。
```

## 10. 时间盒

| 阶段 | 上限 |
| --- | --- |
| 首轮广度（所有主候选） | 90—120 分钟 |
| 单个候选深入 | 45 分钟 |
| 总计 | 不超过半天 |

到时间仍无结论：输出“已排除原因 + 下一次验证假设”，不无限重试。

## 11. 交给 DSH 的问题（最多 5 条）

推荐文件末尾只列真正需要 DSH 决定的问题，例如：

- 许可证与分发意图是否冲突；
- 某候选的写入口是否必须 fork 才能统一；
- 是否接受云端渲染/转写依赖；
- 两条候选是否都值得进入 M0-T3，还是只留一条；
- 某候选的 Windows 依赖是否值得投入安装。

不要列“请确认哪个更好”这类把判断推回给 Codex 的问题。

## 12. DSH 复核清单

收到 Codex 产物后，DSH 逐项核对：

- [ ] commit 是否存在，与证据日志一致；
- [ ] 许可证文件是否真的读了；
- [ ] 安装/构建/测试命令是否实际运行，退出码与日志是否对得上；
- [ ] 工程写入口是否在源码中找到（文件:行号可打开）；
- [ ] 事务/版本/通知是否有代码证据；
- [ ] 字幕/时间/重开是否有数据模型或运行证据；
