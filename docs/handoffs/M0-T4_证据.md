## 1. 映射

| 层 | 实现 |
| --- | --- |
| 业务 job | `bj-<timestamp>-<rand>`，状态 queued/running/verifying/succeeded/failed/cancelRequested/canceled/needsReconcile |
| executionAttempt | 每个业务 job 一个 attempt；未结算 attempt 最多一个 |
| DSH runtime job | `ctx.jobs.start({ kind:'bash', label:'video demo <bj>', owner })`，返回 `bash-...` |
| 进度 | `JobHandle.updateProgress` + `append`；业务 store 同步记录 |
| 取消 | `video_job_cancel` → 业务 cancelRequested；runtime cancel → done killed；300ms 后业务 canceled |
| 回读 | `video_job_read` 读业务输出；`job_output` 读 DSH runtime 记录 |
| 重启 | `video_job_simulate_restart` 把非终态业务 job 标 needsReconcile；`video_job_reconcile` 记录核对结果 |

## 3. 状态与规则

- 每个业务 job 只有 1 个 attempt；本证据未出现同一 job 多 attempt。
- `cancelRequested` 不等于已停止：先观察到 cancelRequested，随后 DSH killed 才变 canceled。
- 失败路径 DSH failed → 业务 failed；未把退出码 0 当成功。
- 重启路径先 needsReconcile，再按核对结果 reconcile 为 failed；没有自动重跑同一 attempt。
- 没有产物发布；本小样只验证状态机与执行映射。
