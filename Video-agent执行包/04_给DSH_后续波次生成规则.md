# 04 给 DSH：后续波次生成规则

- 用途：M0 阶段门之后，由 DSH 生成 M1/M2/M3 的任务包
- 不要现在执行：本文件是“生成规则”，不是让你提前写 M1/M2/M3
- 核心原则：一次只生成下一波 3—5 张卡；每张卡必须有冻结契约、允许路径、验收命令、证据格式

## 1. 什么时候用

| 时点 | 生成什么 | 不要生成什么 |
| --- | --- | --- |
| M0-T5 通过 | 第一批 M1 卡：M1-T1、M1-T2、M1-T3 | 不要生成 M1-T4 之后 |
| M1-T3 完成 | M1-T4；M1-T5 可做准备 | 不要生成 M1-T6/T7 |
| M1-T2/T3/T4 完成 | M1-T5、M1-T6 | 不要生成 M2 |
| M1-T7 通过（AC-01—05） | 第一批 M2 卡：M2-T1 | 不要生成 M2-T2 之后 |
| M2-T1 完成 | M2-T2 | 不要提前做 M2-T3 |
| M2-T8 通过（AC-06—09） | M3-T1 | 不要一次生成 M3-T2—T5 |

## 2. 每张卡的固定格式

```markdown
### M?-T? 名称
- 主责：DSH / Codex / WorkBuddy
- 目标：一个可独立验收的行为
- 依赖：前置卡号、实际完成状态、ADR
- 需求：FR 与 AC 编号
- 输入：素材/工程/版本/场景/契约
- 冻结契约：接口、类型、错误码、时间单位、边界规则
- 允许修改：精确路径白名单
- 只读：精确路径
- 禁止：越界行为
- 实现步骤：3—7 步
- 验收命令：仓库中实际存在的命令
- 证据格式：命令、退出码、日志、截图、文件 hash
- 人工检查：内容/观感/可接手性
- 完成情况：通过/失败/未验证
- 交接：未解问题、下一步、受影响任务
```

没有“冻结契约”和“允许修改”的卡，不准发给 Codex/WorkBuddy。

## 3. M1：最小共同编辑

### 3.1 第一批只发三张

#### M1-T1 工程所有权、逻辑字段与原生映射

- 主责：DSH
- 输入：M0-T5 的 ADR-001、选定底座、夹具工程
- 必须冻结：ProjectHead、Asset、WorkingMedia、Segment、Track、Transcript、Caption、Revision、Artifact、Feedback 的字段与 ID 规则
- 产出：schema 正反例、原生映射说明、写入口清单
- 验收：权威状态唯一；标识、字幕、历史可映射；正反例可跑
- 不要让 Codex 定义 schema 语义

#### M1-T2 时间、工作媒体与字幕来源映射

- 主责：Codex
- 允许修改：`src/core/time/**`、`src/core/captions/**`、`src/adapters/media/**`、`test/time/**`（以实际布局为准）
- 只读：`contracts/**`、`src/dsh/**`、`src/client/**`、`skills/**`
- 必须冻结：有理数 fps、半开区间、最近帧/半帧规则、覆盖区间向外量化、VFR→CFR 映射、字幕锚点
- 验收：30000/1001、非网格时间、非零起点、旋转、缺音轨、中文路径、字幕重排
- 证据：单测 + 边界夹具 + 实际命令输出

#### M1-T3 命令服务、原子提交、baseRevision、幂等

- 主责：DSH
- 输入：M1-T1
- 必须冻结：commandId、projectId、baseRevision、op/target/params、错误码、幂等摘要规则
- 产出：单写服务、原子提交、历史、错误语义
- Codex 只能写黑盒并发/幂等测试，不改实现
- 验收：两个旧基准不能都成功；同 ID 同内容返回原结果；同 ID 不同内容拒绝

**这三张之后才生成 M1-T4。**

### 3.2 第二批

#### M1-T4 revision、恢复、历史、重开

- 主责：DSH
- 依赖：M1-T3
- 必须冻结：revision 单调不复用、恢复生成新版本、业务/原生历史映射
- Codex 可写崩溃/重开/恢复测试夹具
- 验收：r3 恢复 r1 内容生成 r4；重开恢复当前 revision

#### M1-T5 页面与 Agent 共用入口（含 K3 UI 子包）

- 主责：DSH
- 依赖：M1-T2/T3/T4
- DSH：Client/Host 通信、选择上下文、Agent 工具、主/revise Skill 最小正文、命令入口
- WorkBuddy/Kimi-K3：只做受控组件（片段列表、字幕编辑、选中/空/加载/冲突态、键盘可达）
- K3 包必须冻结：Props、Events、状态枚举、选择上下文；禁止直接请求服务、保存 project/revision
- 验收：人工改字幕→Agent 缩短开头；纠正保留、目标生效、差异可见

#### M1-T6 manifest、业务 job、预览/导出

- 主责：Codex（渲染适配），DSH 保留 manifest/job 状态机/DSH 桥接/发布门
- 依赖：M0-T4、M1-T4
- 必须冻结：renderManifest 字段、缓存键、businessJob/attempt 状态、产物发布规则
- Codex 允许：`src/adapters/render/**`、`test/render/**`
- 验收：r1 渲染中编辑到 r2，产物仍属 r1；半成品不发布

### 3.3 最后

#### M1-T7 AC-01 至 AC-05 集成

- 主责：DSH
- 依赖：M1-T2—T6
- Codex 可写黑盒 AC 脚本；WorkBuddy 不判 AC
- 验收：同一工程读取、人工后接续、旧基准冲突、幂等/回滚、重开
- 产物：证据包、日志、工程、diff、截图

额外规则：

## 10. 生成任务包前的检查

- [ ] 前置卡真的完成了吗？
- [ ] ADR 是否足够支撑这张卡？
- [ ] 契约是否冻结到可实现？
- [ ] 允许路径是否精确？
- [ ] 验收命令是否真实存在？
- [ ] 失败时是否知道找谁？
- [ ] 是否只生成了下一波，而不是全部？

任何一项为否，不要发。

## 11. 失败/退回规则

- Codex 失败：保留最小复现，退回“契约/测试/边界”具体缺口；
- WorkBuddy 文档不合格：退回格式/来源/反例，不重写全部；
- K3 组件越界：退回“移除服务调用/权威状态”，DSH 重接线；
- DSH 集成失败：先定位是契约、适配器、DSH API 还是 UI，不要用“换个 AI 重做”掩盖；
- 反复失败：记录观察、已排除原因、下一次验证假设，不无变化重试。
